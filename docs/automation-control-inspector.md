# 自动化中心：UiAutomator2 控件拾取（一期）

分支：\`feat/automation-center\`。本期复用现有 ADB Executor、会话视频、UiAutomator2 PreparedHelper 和脚本库，不提供独立手机执行器。

## 已实现

- 每台手机卡片新增「控件拾取」按钮：需先建立实时画面；已有群控同步或脚本录制时不能打开。
- 在弹窗中复用现有 MediaStream 展示实时画面，独立读取 **一次** 当前 UI 层级；点击画面只选择控件，不向手机发送 touch 指令。
- 支持控件列表搜索、按实际 bounds 高亮、Resource ID / 文字 / description 唯一定位策略；若没有唯一定位条件，可在画面比例一致时生成坐标点击。
- 一键生成 \`tap\`、\`wait_for\`、\`assert\`、\`input_text\` 步骤，放入现有 \`recordingDraft\`，前往脚本库后点击「新建录制草稿」导入并试跑/保存。输入使用运行参数，不把录入值直接写入草稿。
- \`GET /api/v1/automation/devices/{id}/hierarchy?owner_user_id=...\` 经登录、账号授权、当前设备绑定校验转发到执行器；浏览器不接触执行器 Token。
- 执行器 \`POST /internal/v1/automation/hierarchy\` 只接受受认证的内部请求，要求设备已显式初始化控件组件，使用受管隔离子进程和底层只读 UiAutomator2 RPC 获取层级，超时后由受管进程清理；不会自动配对、点击或重新准备控件。
- 控件树限制 XML 512 KiB、节点 1500、有效 bounds，密码字段清空，超长 Unicode 精确选择条件舍弃，拒绝含 DTD/ENTITY 的 XML；HTTP 结果不缓存。

## 第二阶段：父子控件与采集时间（2026-10-26）

- 控件树根据第一阶段输出的 parent_id 关系呈现真实父子结构，支持折叠和展开；搜索匹配节点时连同祖先路径一起展示，避免看不见上下文。
- 右侧属性区增加可点击的祖先路径。当前元素不可点击时，推荐当前层级里最近的、已启用的可点击父节点；不会擅自代替用户选择。
- 执行器返回 UTC \`captured_at\`，页面显示采集时间；视频流与控件快照各自采集，不承诺逐帧同步。滚动、旋转或切换页面后需要刷新控件树。
- 调整解锁单元测试以符合已使用的 \`adb shell input swipe\` 定时手势，不放松仅在两次确认锁屏时才输入密码的安全约束；独立执行器的 Actions 构建与测试已恢复成功。
- 此阶段未改动既有脚本 wire schema 或执行动作类型，保存的旧脚本继续使用原执行逻辑。

## 第三阶段：XPath / 组合条件（2026-10-26）

- **组合条件定位**：原有精确字段保留，新增 class_name 与 package；多个非空字段需同时命中一个控件。拾取界面通过当前快照搜索可唯一命中的字段组合，并自动生成步骤。
- **XPath 1.0**：用于点击（tap）、等待存在（wait_for）和断言存在（assert）。现有脚本协议在 selector 中新增独占字段 xpath；XPath 不可与其他原生字段共存。文字输入继续强制使用 UiAutomator2 原生唯一选择器，避免在焦点不确定时输入敏感文字。
- **执行规则**：XPath 在隔离进程中读取当前控件树；XML 上限 512 KiB，节点上限 1500，单个 XPath 不超过 512 字节；禁用 DTD / ENTITY，解析阶段不访问外部网络；仅当结果为一个带有效屏幕坐标的控件时才发送一次点击。0 个结果按等待时间处理，多于 1 个直接报歧义错误；不自动重试点击。
- **格式说明**：标准 XPath 示例 selector = {"xpath":"//*[@text='设置']"}，类名 XPath 支持 //android.widget.Button；可输入原生组合 {"resource_id":"app:id/ok","class_name":"android.widget.Button"}。
- **兼容要求**：Rust 服务与 Python 执行器需同步升级；旧的 tap / wait_for / assert 脚本继续按原有路径执行。此阶段未实现 XPath 文本输入、滚动查找、复杂条件编排或自动弹窗处理。
- **验收**：运行 executor 单元测试（包括 XPath 无匹配/歧义/组合/恶意 XML）和 Web 类型检查；真实 Android 对 XPath class 标签、等待和画面坐标需部署验证。

## 第四阶段：状态检查与滚动查找（2026-10-26）

新增三类可保存、试跑及批量执行的脚本步骤，复用现有每台设备的隔离执行进程和调度队列：

- \`wait_gone\`：等待匹配控件消失（100–30000 ms），0 个匹配视为消失，1 个或多个匹配视为仍在；底层连接失败、无效响应或 XPath 错误不能当成消失。支持 XPath 或原生组合选择器。
- \`assert_property\`：唯一原生控件定位后，从 UiAutomator2 \`objInfo\` 读取布尔字段 \`enabled\` / \`checked\` / \`selected\` / \`clickable\` / \`scrollable\`；必须是原生布尔值，与 \`expected\` 严格比较，缺失或非布尔数据不能默认为 \`false\`。当前不提供 XPath 属性断言和任意文本比对。
- \`scroll_find\`：先检查目标，未找到时查找用户指定的唯一、可滚动原生容器，获取可见边界后执行短距离上/下滑，再次查找目标；最多 5 次、单次 200–1000 ms、总体超时 30 秒。目标可用 XPath 或原生选择器；滚动容器只能用原生选择器。手势结果未知立即停止，无自动重发。查找成功**只表示控件出现**，不自动点击。
- 脚本编辑器加入上述动作、滚动容器、方向、次数、持续时间和布尔属性的编辑项；控件拾取窗口可自动生成等待消失和属性断言。仅当快照中具有唯一 Resource ID 的滚动父节点时，才自动生成滚动查找。
- Rust / Python 两端校验同步，旧脚本类型不变。前端脚本保存前进行步骤配置检查。
- 执行器单元测试覆盖条件校验、重复匹配、非布尔属性、容器无效、未知动作结果和单次手势次数。
- **待验收**：Android 17 真机、横竖屏变化、不同列表控件、设备断线、实际滚动方向、主镜像完成构建发布。不要把 CI 冒烟测试当作真实设备验收。

## 使用流程

1. 在设备「控件」菜单先完成 UiAutomator2 初始化，再打开实时画面。
2. 点击手机卡片的拾取按钮，等待控件树加载（不自动刷新）。
3. 点击画面或通过列表选择控件，确认自动选择的唯一定位方式。
4. 点击「添加点击 / 等待出现 / 断言存在 / 输入文字」；可连续添加。
5. 点击「去编辑脚本」，在脚本库点「新建录制草稿」，确认步骤后单机试跑、保存或批量运行。

## 边界与验收

- 控件快照与连续视频不是同一时刻获取；切换页面、动画、滚动或旋转后必须手动刷新。画面/控件树比例不一致时禁止基于画面点选。
- 已支持唯一精确原生选择器与 XPath 1.0 的点选、等待、断言；控件可见不代表业务动作成功。
- 只验证代码与模拟测试时不得声称 Android 真机已通过。需要实际手机检验控件树 RPC、Android 17 兼容、横竖屏、中文、多页面、遮挡窗口、设备断线与重新初始化、敏感字段。
- 前后端与执行器版本必须配套升级。只更新网页端会导致 hierarchy 接口 404。
