# 原始需求与四角色结论汇总

本轮交付目标是：在原 EasyTier Web 上，围绕已注册网络节点管理网关组、下挂设备和设备服务，保留原有网络实例操作。原始需求和最终答复汇总在本文件，开发安排见[计划总览](../plan/README.md)与[任务看板](../task/README.md)。本轮编写计划和任务，不代表相应功能已实现或验证。

基线是 `/workspace/EasyTier-main-node-attributes` 的 `feat/node-attributes-main` 工作树，HEAD 与 `origin/main` 均为 `e307dadb`，另有之前节点属性、卡片及菜单的本地修改。实际源码优先于旧分支截图和历史建议；不能把用户管理分支或生态拓扑分支的能力当作此基线已有能力。现有节点注册、config-server、OIDC、本地登录及原页面操作继续保留。

后端 Q01–Q60 已分 19 组答复；前端 F02–F15、F19–F21 已答，F01 表述不清撤回，F16–F18 未答撤回。按用户要求，问答已经结束，不再追加问题。以下分别标明“用户已确认”和“本轮工程默认”，不把未答推荐转成用户决定。

## 1. 产品经理结论：管理对象、使用流程与阶段边界

### 用户已确认

- **对象层级：**网络节点可以直接挂设备，也可以挂网关组，组内再挂设备；服务只属于设备。网关组代表实际拓扑关系，绑定至少一个手填内网网段，不是手机/电脑的聚合分类。不做自动或自定义聚合。来源：原始需求、D-04–D-07。
- **节点身份：**原 EasyTier 注册设备列表就是本需求的“网络节点”。一个 OpenWrt 可以是注册节点；需要登记它本机的服务时，另外手工创建一条设备，再挂服务，不自动同步两份资料。网关组内可标记最多一条“网关自身设备”，不强制存在。来源：D-05、Q04、Q10。
- **归属：**一条设备属于一个节点，最多属于该节点下一个网关组；新增可选，保存后固定，不支持进组、退组、换组、跨节点移动或整组迁移。来源：原始答复、Q02、Q03、Q35。
- **页面：**保留左侧菜单、右侧功能。在“网络节点”下新增二级“节点详情”，展示当前节点的设备列表，设备行展开服务列表。原实例数保持含义，新增独立“设备 N”入口；离线、零实例、零设备均可进入资料管理。来源：原始需求、Q46、F01 撤回后的澄清。
- **首期价值：**完成节点资料、网关组、设备、类型和服务的 Web 管理。设备是否连接 EasyTier、具体接入方案和真实公网发布后置，不把联网作为登记资料的条件。来源：首阶段交付答复、Q27–Q29、Q39–Q41。
- **服务附加信息：**链接选填，仅 HTTP/HTTPS，在新标签页打开；图标仅内置，未选用默认。服务登记不自动生成访问地址，也不证明可达。来源：Q30、F20、F21。

## 2. 项目经理结论：交付范围、风险与完成口径

### 用户已确认

- **范围：**首期做资料管理；普通账号部署下 Web 单条 CRUD，管理员可以跨账号管理，普通账号之间不分享。external webhook 新资料管理、程序接入和导入导出后置。来源：Q37–Q41。
- **删除边界：**有网关组或设备的节点禁止删除；网关组里有设备禁止删除。因为首期不支持移动，非空组需要先删除其设备。设备经二次确认后，永久删除该设备及执行删除时的全部服务，包含确认弹窗后新增的服务；不提供回收站或页面恢复。来源：D-09/D-11、Q01、Q31、Q32。
- **容量：**预计 1–5 个账号，每账号 2–3 个节点，每节点 0–10 台设备，每设备 1–2 项服务，1–2 人同时使用。它们是设计依据，不是系统配额或性能承诺。来源：Q43。
- **部署：**一个 Web 后端实例即可；升级前手动备份，允许短暂停机，不设未经确认的停机/恢复时限。来源：Q49/Q50。
- **开发协作：**先汇总需求/计划和问题，再写小计划及任务；按独立职责和文件分工，让多个 agent 并行，最后联调。调试模式下不自动测试、构建、lint、CI；本轮纯文档不执行这些检查。

## 3. 后端经理结论：实体、约束与一致性

### 关系模型与命名

```text
资料所有者账号
├─ 已注册网络节点（现有 devices，身份为 user_id + machine_id）
│  ├─ 节点静态资料/公网角色
│  ├─ 直属设备（新增 asset_devices）
│  │  └─ 服务（新增 asset_services）
│  └─ 网关组（新增 asset_gateway_groups）
│     ├─ 手填网段（至少一条）
│     └─ 组内设备（可有一条手动标记的网关自身设备）
│        └─ 服务
└─ 设备类型目录（按账号维护是本轮工程默认）
```

同一设备不会既直属节点又归入某个网关组，但所有设备均有唯一节点归属。设备类型是分类引用，不是树中的父级；公网节点角色也不是设备类型。实体以稳定 ID 定位，允许重名的对象不能凭名称或 IP 合并。

命名约束：保留现有 `devices` 表表示注册节点；新下挂设备使用 `asset_devices` 等清晰区分的名称。现有权限 `groups` 不能用作网关组表，旧网络实例与新服务目录不共用语义；节点的 `machine_id` 不能被当作下挂设备 ID。表、字段、DTO 及路由的最终拼写由 T01 统一给各任务使用。

### 字段与保存条件

|实体|首期字段/关系|关键规则与来源|
|---|---|---|
|网络节点|现有机器身份、名称/版本/OS、连接来源 IP/地区、地点、型号；追加静态公网角色|复用现有属性，手工角色不得被心跳覆盖；节点仍通过既有注册机制出现，不新增手工注册节点流程|
|网关组|稳定 ID、所属账号/节点、名称、备注、网段集合|名称必填、允许重名，备注选填；网段至少一条；有设备禁止删除。Q01/Q05/Q06/Q09、D-06|
|设备类型|稳定 ID、名称、所属目录|预置常用项，可新增/改名，使用中禁止删除；修改类型不改变设备归属或服务。Q07/Q08；目录范围及必填性见工程默认|
|设备|稳定 ID、账号/节点、可空网关组、名称、型号、类型、组网 IP、内网 IP、网关自身标识、备注|名称必填可重，型号/备注选填；组网 IP 必填一条，内网 IP 选填最多一条；每组最多一条自身设备，直属设备不能冒充某组自身设备。Q04/Q05/Q09/Q11–Q16/Q22|
|服务|稳定 ID、所属设备、名称、协议、一个端口、备注、访问链接、内置图标标识|名称必填可重；TCP、UDP 或两者；备注/链接/图标选填；无链接仍可登记。Q23–Q30、F20/F21|

地址规则必须由后端执行，不能仅靠表单检查：

- 设备两个 IP 字段均接受纯 IPv4/IPv6，不混域名、端口、URL 或 CIDR。组网 IP 可以重复，不按 IP 合并设备；非空内网 IP 在同一账号的同一节点内唯一，覆盖直属、全部组内及自身设备，不同节点可重复，多个空值允许。等价 IPv6 写法不能绕过唯一性。来源：Q11–Q16、Q22。
- 网关网段为手填 IPv4/IPv6 CIDR。含主机位时提示标准写法，用户改正后保存，不静默归一化为另一网段。组内完全重复的 CIDR 拒绝，不同网段包含或重叠允许，跨组相同或重叠也允许。来源：Q17–Q19。
- 组内设备已填内网 IP 不匹配任何同族网段时，提示具体设备但允许保存；编辑设备和修改组网段都适用。空内网 IP 和直属设备免匹配。该警告不代表离线、不自动改地址，也不放宽其他唯一/格式约束。来源：Q20/Q21、F09。
- 同一设备的每个“协议 + 端口”只能属于一条服务。双协议占两个组合，必须原子校验和保存；TCP 53 与 UDP 53 可分属两条服务，TCP+UDP 53 则与其中任一冲突。来源：Q23–Q25。

### 权限、事务与请求行为

- 操作者与资料所有者分开。普通账号仅管理自己的资料；管理员经服务端授权可跨账号 CRUD，新增资料仍归目标账号。关联节点、组、设备、类型都必须在允许的归属范围内，管理员同样受固定归属、删除及唯一性限制。来源：Q37/Q38、F19。
- 普通资料最后一次成功保存生效，允许后提交的旧表单覆盖此前修改；不把旧网络配置的 revision 规则移到资产表单，也不删除既有配置并发控制。更新不能复活已删对象。来源：Q33/Q35。
- 同一次新增重试返回原结果，主动再次新增算新操作。幂等不能按同名、同 IP 或相同内容猜测，需要客户端操作标识、服务端范围限定与持久结果，且和创建事务一致；删除后重放不能重新创建。来源：Q34。
- 节点/组删除条件、设备级联服务、创建时父对象有效性及所有唯一约束需在并发下成立。设备删除以实际提交数据为准，不能只删确认弹窗里列出的服务 ID。来源：Q01/Q31/Q32。
- 搜索设备名、型号、组网 IP、内网 IP，和组/类型条件取交集；最近新增优先，同时间保持稳定次序，每次查询最新资料。初始列表不捆绑全部服务，展开时读取服务。来源：Q44/Q45/Q47。
- 只统计设备记录，含自身设备；不把节点、网关组、服务加到设备数里，不按真实物理硬件去重。来源：Q46 最终补答。

## 6. 工程默认与后续边界

### 为本轮任务拆分采用的工程默认

这些是依据现有范围作出的实现设计，不是用户在 F16–F18 中作过的选择。T01 将其连同具体 DTO、错误码和组件契约写明，供开发协作；不再次发问或引入审批阻塞。

|未冻结事项|本轮计划采用的默认|理由及边界|
|---|---|---|
|类型目录归属|按资料所有者账号独立维护，管理员切换目标账号后管理对应目录|避免普通账号间隐式共享；不建立全局可编辑字典|
|预置类型|OpenWrt、手机、电脑、NAS、智能家居、其他|来自已讨论示例及最小常用项，仍可按已定能力新增/改名；不把预置清单写成用户逐项批准|
|类型必填性|类型允许为空，不增加用户未确认的必填门槛|仍能分类筛选，之后可编辑补充；不自动按 IP/型号推断类型|
|类型重名|不增加名称唯一限制，稳定 ID 区分|组/设备/服务重名已明确，类型未单独确认；本轮选宽松默认，不擅自阻止登记|
|类型入口|类型筛选旁管理弹窗；设备填写窗口不增加快捷新建类型|完成已有类型管理能力，减少新交互分支；与网关组管理方式一致，但不是 F16/F17 已答|
|手机呈现|沿用项目响应式、主题和键盘可操作性，保证本期页面基本可用|不额外立项独立手机版、手势功能或新视图系统；具体断点和布局由前端负责|
|链接打开动作与错误呈现|沿用现有组件风格，明确打开操作和局部错误/重试|不复用组网输入语义，不新增草稿恢复、重试队列或链接探测|

### 明确不进入本轮开发任务

- 实际设备接入、EasyADB/智能家居/Navloom 适配、拓扑画布、自动发现及 deploy 自动安装方案。
- 服务公开开关、目标地址选择、转发执行、入口切换、防火墙/安全组/DNS/证书管理。后续公网已有决定继续保存在 [require-06](require-06-backend-publication.md)，不得为本轮实现提前增加运行状态机。
- 聚合、设备移动、整组迁移、物理设备识别/去重、普通账号分享、手动启停标记、操作历史、回收站、导入导出及账号永久删除。
- external webhook 模式的新资料管理、外部程序专门授权、图片上传/外链/抓取、SSH/RDP 客户端唤起、新定时任务或后台探测。

后续公网阶段已确认的“单服务手选单入口、手填端口、只配置 EasyTier TCP/UDP、只管理自身规则、配置写入/删除成功即操作成功、离线拒绝开启”均保留；整个地址方案、接入与转发目标仍后置。它们不改变首期删除级联和资料管理规则，也不构成当前公网功能已实现的证据。
