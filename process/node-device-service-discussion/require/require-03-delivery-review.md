## 4. 后续必须解决的具体场景

### R-01：手填地址与网段的非阻断提示

已确认网关组网段完全由用户设置，不从机器读取后校正用户填写值；手工网段登记不表示已经发布路由。组采用 IPv4/IPv6 CIDR，仍需至少一个网段且允许多个。设备每类 IP 最多一条，组网 IP 必填且恰好一条；设备填写纯 IP，不混域名、URL、端口或 CIDR。

Q20/Q21 已确认：例如组手填 `192.168.1.0/24`，组内设备 LAN IP 为 `192.168.2.10`，提示该设备不匹配但允许保存。新增/编辑设备和修改/删除组网段条目均适用；只比较手填数据，匹配任一同地址族网段即可，空 LAN 与直属设备免匹配，组内自身设备适用。不匹配是提示，不是保存失败，不增加强制确认、不自动修改 IP、网段或固定归属；提示不表示设备离线或不可达，不增加探测或定时任务。

组网 IP 必填已经确认，不能继续保留“无任何 IP 也能登记”的推荐；所有设备内网 IP 选填，可留空保存。Q15/Q16 的同节点非空 LAN IP 禁重、Q17/Q18 的标准 CIDR 与同组网段禁重，以及每组至少一条网段仍是保存条件；不匹配允许保存不豁免这些要求。不同网段包含/重叠与跨组同段允许。接入逻辑仍后置，登记 IPv6 不代表已实现 IPv6 转发。

### R-02：固定归属与设备/服务身份

Q02/Q03 已确认首阶段不提供任何设备移动，不考虑整组迁移；设备新增时可选择直属节点或该节点下一个组，登记后节点和组归属固定。同节点进组、换组、退组、跨节点移动均不支持，编辑不能改归属。Q35 的移动冲突策略问题据此关闭，不再要求选择；这些能力不自行转入后续开发范围。

第 3 组已确认 Q04：增加“网关自身设备”标识，每组最多一条，手动新增且不强制存在；Q10：与注册节点即使同物理机也分别维护，首阶段不额外关联或同步。Q46 初答曾表达物理去重意图，最新补答已澄清为只记录设备数量，不记录网络节点、网关组及服务数量；当前采用下挂设备记录数，包含手动新增的自身设备。

19/19 组均已回复，但不代表全部实施细节冻结。节点卡片统计该节点下全部设备，筛选列表统计命中设备；本需求不新增节点、网关组或服务数量指标，原实例数和既有仪表盘保持不变。物理身份识别与多记录去重讨论关闭，不新增物理实体、唯一物理设备约束或硬件识别；管理员跨账号操作不改变资料所有权，不提供普通账号共享，也不改变不聚合、不移动的决定。整个公网地址方案仍按 Q52 后置，访问链接独立维护、不自动改写。稳定 ID 定位对象，名称重复不合并或覆盖记录。

### R-03：公网开启、关闭和删除需要同一套验收

公网发布已确定归后续阶段。第 17 组确认每服务仅一个由用户手动指定的入口节点，不默认选择或支持多入口；公网端口手填，冲突时提示用户修改后重试，不自动分配替换。整个地址方案留公网实施前确定，地址种类、数量、来源与监听配置未冻结；不把问题中的建议作为批准。第 18 组确认只配置 EasyTier 转发，防火墙、云安全组和 DNS 由用户处理；只管理本功能创建的规则，手工规则或本功能规则被手动改后的冲突提示处理，不自动覆盖、不认领旧规则。公网第一版只做 TCP/UDP，不做 HTTP 域名/路径分流或证书管理，TCP 可以透传已有 HTTPS。第 19 组已回复，采用以下配置操作口径：

- 开启：入口节点离线时拒绝，恢复后用户手动重试；不排队自动开启。用户仍手动指定入口及端口，地址和监听方案不提前冻结。
- 关闭/删除：用户明确“公开不做强绑定 删除了服务时 直接把该条转发规则删除”。直接删除对应本功能配置，设备级联删除同理，不要求先确认运行时撤销再完成业务删除；保留定位自身配置所需最小关联，不删任意规则。
- 入口调整：用户明确“你不用强校验 写入/删除转发配置 成功就是成功”。必要配置写入/删除成功即操作成功，不等待旧监听停止、新监听建立或公网探测，不新增强制待撤销、长期端口保留或补偿任务，不再追问旧先新先。
- 结果展示：保存/删除结果与已有应用反馈分开展示，应用未知明确为未确认，不阻止配置操作成功；公网可用性由用户自行验证，不以配置成功冒充已验证公网可达。
- 配置操作失败仍报错。权限、唯一性、固定归属及手工规则冲突保护继续生效；端口冲突提示用户修改重试，手工规则或本功能规则被手动改后的冲突不自动覆盖、不认领旧规则。
- 外部安全组、防火墙及 DNS 由用户处理，本功能只配置 EasyTier 转发，不扩展为云厂商管理平台。

### R-04：删除、重新登记与资产恢复

### R-05：账户范围与部署模式

当前注册节点按登录账号隔离，这是现有代码事实。Q37/Q38 已确认新增管理能力：普通账号限自己的资料，管理员可跨账号查看、新增、修改和删除；服务端必须验证管理员身份及其对目标账号的权限，不能对所有请求一概绑定操作者 `user_id`，也不能仅信任请求传入的目标账号。关联父对象必须属于同一目标账号和节点，资料所有权不随操作者变化；固定归属、禁移动/迁移及删除限制保持，普通账号间不共享/协作。

F19 已确认管理员页面先选择目标账号，再选择该账号的节点，并明确显示目标账号；这不替代服务端授权，也不改变资料归目标账号的规则。

可靠管理员身份判定、授权来源及现有接口如何扩展仍为实现设计事项，本轮未证明现有权限体系已满足完整管理能力。不把设备组变成权限组，不新增手工节点注册，不修改 config-server/OIDC，不因管理员能力追加操作审计。自定义类型不默认跨账号共享编辑。Q42 的账号永久删除政策后置独立账号删除需求，首阶段不增加删除账号入口。

外部 webhook 认证和当前本地登记模式在源码中有明确差异（E-08）。Q39 已确认首阶段先支持普通账号/本地用户登记部署，external webhook 模式的新增资料管理后续处理；OIDC 保持现有本地用户映射，不改 config-server、认证流程或外部模式的既有功能。此交付范围不等于停用外部认证。

Q40 已确认 Web 先行，页面所需正常 API 保留在首阶段；外部程序专门授权接入后续，不自行新增程序令牌或全局 API。Q41 已确认先做单条 CRUD，不加导入导出；数据库备份恢复按第 16 组决定单独设计，不能从不做应用层导入导出推导为不需要备份。

### R-06：容量与响应指标

Q43 已确认未来一年设计基线：1–5 个账号、每账号 2–3 个节点、每节点 0–10 台设备、每设备 1–2 项服务、1–2 人同时操作 Web。这些是预计使用量，不是配额、最低数量、容量上限或压测通过结论；仍可存在尚未登记服务的设备。Q49 已确认一个 Web 后端实例，无多实例、多主机高可用要求。设备搜索范围及服务按展开加载继续按第 15 组执行。

现有节点页使用内存分页（E-09），不能据此认为下挂设备和全部服务可以一次性加载。设备最近新增优先，每次查询最新数据，不固定快照、不定时刷新，同值稳定次序由后端保证；服务按展开请求，操作完成或手动刷新更新，不初始附带当前页全部服务或增加服务计数。设备分页的实现按已确认规模设计，响应时间尚未承诺；不编造性能数字，不把使用 JSON 本身当成性能问题。

Q50 已确认升级前手动备份，允许短暂停机，停机和恢复暂不设硬时限；后端须据此设计备份、数据库升级及恢复方案，保持原有用户、节点、客户端连接与页面。允许短暂停机不是允许任意丢失数据，也不等于承诺零损失；不新增定时备份要求，本轮不执行备份、升级或恢复操作。

1. 从独立设备数量入口进入详情，自动选中对应节点；实例数为 0 或节点离线仍能管理已登记资产。

8. 网关组、设备和服务均能创建同名但 ID 不同的记录；编辑、删除按指定 ID 操作，不合并或覆盖其他同名记录。三类名称均必填，名称空白处理与长度由后端统一规范；设备型号可空，三类备注可空或填写。此验收不放宽既有账号、权限组或网络配置的约束；服务访问链接及可选图标按第 11 组已确认范围独立处理。

10. 组网 IP 相同的设备可分别保存且不合并；同一账号、同一网络节点内的非空内网 IP 在直属、全部组内和自身设备之间统一禁重，不同节点可重复。多个空内网 IP 可共存；IPv6 等价写法不能绕过重复校验；新增与编辑均适用，编辑保留原地址时不与自身误冲突。约束仅作用于新登记资产，维持账号隔离，不改变原运行地址分配，不因跨组网段相同或重叠而豁免。
