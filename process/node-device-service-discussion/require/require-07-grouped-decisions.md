## 已确认的前提

- 节点有下属数据时禁止删除；设备二次确认后连同服务一起删除。
- 非空网关组禁止删除；结合第 2 组不支持移动，当前须先删除组内设备。首阶段组、设备、服务永久删除，页面不提供恢复，删除前提示影响范围。
- 设备删除以提交时的全部服务为准，包含确认期间新增的服务，不因服务数量变化强制再次确认。
- 每条设备记录只属于一个节点，最多属于该节点下的一个网关组。
- 新增时可选择直属节点或同节点网关组，登记后归属固定；首阶段不支持进组、换组、移出组或跨节点移动，不考虑整组迁移。
- 不做聚合；网关组至少一个手填网段，支持多个，不自动探测或改写。
- 组网 IP 必填，内网 IP 选填；组内已填内网 IP 不匹配手填网段时提示但允许保存，不自动修改任何地址或网段。
- 网关组不直接挂服务；需要网关本机服务时由用户手动新增自身设备。
- 增加“网关自身设备”标识，每组最多一条，不自动创建；与注册节点的资料分别维护，首阶段不额外关联或同步。
- 设备数量只统计下挂设备记录，含自身设备；不把节点、组和服务计入，也不新增它们的数量指标。物理身份去重讨论已由最新澄清关闭；原实例数保持不变。
- 新增网关组、设备、服务名称均必填且允许重名；设备型号选填；三类均提供选填备注。名称不承担唯一身份，不修改既有账号、权限组或网络配置约束。
- 设备类型预置常用选项，支持自行新增和改名；被设备使用的类型禁止删除。类型仅用于分类筛选，修改类型不自动把设备转成网关组。
- 首阶段设备和服务不增加手动启停标记，不改变既有节点/实例运行状态或设备计数。
- 每台设备组网 IP 必填且一条，内网 IP 选填且最多一条。设备 IP 与网关组网段均支持 IPv4、IPv6，设备填纯 IP、网段填 CIDR。
- 组网 IP 允许重复，不按 IP 合并设备；已填内网 IP 同节点全部设备之间禁止重复，跨节点允许。内网空值不构成重复。
- 网段填写标准网络地址；非标准输入提示后由用户手动修正。同组拒绝完全重复网段、允许包含/重叠；跨组允许相同/重叠，不豁免设备内网 IP 同节点唯一。
- 服务只登记一个端口，协议可为 TCP、UDP 或同时两者；同设备协议与端口组合唯一，双协议同时参与两种协议的校验，名称仍可重复。
- 首阶段服务目标地址选择及跟随规则后置，不展示公开开关；增加可点击访问链接与可选图标，访问链接不作为转发目标或公网生效依据。
- 普通资料编辑以最后一次成功保存为准，旧表单允许覆盖，但不绕过权限、唯一性或固定归属；同次新增重试返回原结果、不重复创建；首阶段不增加操作记录。
- 管理员可跨账号查看及增删改资料，仍遵守既定约束；普通账号间不增加分享协作。账号永久删除及资料处置留到后续需求。
- 首阶段先支持普通账号部署的 Web 单条管理，external webhook 模式新资料管理、外部程序专用接入及导入导出后置；保留既有认证与页面接口。
- 关键词搜索设备名称、型号和两类 IP；当前节点内组/类型/关键词取交集。最近新增优先，每次查询最新；展开设备时查询服务，操作后或手动刷新更新，不增加定时查询。
- 未来一年容量预期为 1–5 个账号、每账号 2–3 节点、每节点 0–10 设备、每设备 1–2 服务、1–2 人同时操作；单个 Web 后端实例。升级前手动备份，允许短暂停机，停机及恢复时长暂不设硬指标。
- 后续公网阶段每服务手动指定一个入口，公网端口手填，冲突后用户修改重试；入口地址方案留到公网实施前确定，不冻结地址种类和数量。
- 公网第一版只配置 EasyTier TCP/UDP 转发，防火墙/云安全组/DNS 用户处理；只管理自身创建的规则，手工规则或手动修改冲突时提示、不自动覆盖。不增加旧规则认领、HTTP 分流或证书管理。
- 后续公网配置写入/删除成功即操作成功，不强等入口运行确认；删除服务直接删对应转发配置，设备级联同理。保存及已有应用反馈分别展示，公网用户自行验证；离线仍拒绝开启、恢复后用户重试。权限和配置冲突保护保留。
- 首阶段管理节点、网关组、设备和服务；接入逻辑与真实公网发布后置。
- 不新增定时探测，不改变 config-server/OIDC 行为。

只讨论不同设备记录之间的地址重复，不要求连接方案、不自动改实际网络。包括网关自身设备；内网 IP 可空的决定保持，不以空值之间相同为地址冲突。
