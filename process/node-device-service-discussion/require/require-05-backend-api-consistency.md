# 后端需求审查：接口、权限与一致性

本文件承接[需求/计划汇总](../README.md)，集中记录 Q31—Q50。当前为需求讨论，不是接口定稿或实施计划。Q31—Q42 已记录本轮答复：Q35 因不支持移动关闭，Q42 账号删除政策留到后续需求；Q46 只统计设备记录、不做物理去重，Q48 不增加手动启停标记。普通资料最后一次成功保存生效，同次新增重试不重复创建，不增加操作记录。管理员跨账号 CRUD 纳入，普通账号间不分享协作。首阶段限定普通账号部署下的 Web 单条管理，external webhook 新能力、外部程序接入及导入导出后置；回收站、设备移动和整组迁移仍不提供。

已确认的边界：首阶段管理节点、网关组、设备和服务，公网发布另一个阶段；不聚合；一条设备记录只属于一个节点，最多属于该节点的一个组；设备删除经二次确认后同时删除其服务；节点有下属资产时禁止删除；组网 IP 必填且一条，内网 IP 选填且最多一条；两类 IP 和网关组 CIDR 支持 IPv4/IPv6，网关组至少一个手填 CIDR。已填内网 IP 不匹配所属组任一网段时提示相关设备但允许保存，保存设备和修改网段采用同一规则，空内网 IP 或直属设备不做此项匹配。设备如何连接 EasyTier 由用户后续补充，不在此继续追问。

优先级只代表讨论顺序：★ P0 为数据模型或权限边界冻结前需优先决定的问题；P1 可结合默认建议随后细化。没有用户答复时，不将默认建议记为已确认。本文仅 Q31、Q33、Q37、Q39 标记为 P0。

## 问题与已确认决定

### Q31 已确认：首阶段组、设备和服务永久删除

- 场景：用户已确认同时删除设备与其服务，随后发现删错设备。
- 用户决定：首阶段删除网关组、设备或服务后永久删除，页面不提供恢复；删除前明确提示影响范围。不改变已确定的删除条件和级联关系。
- 影响：永久删除与回收站会改变列表、唯一性、父节点删除条件、存储量及恢复冲突处理。现有节点删除是实际删除，不提供新资产回收站，见 S05。
- 落实要求：首阶段不新增回收站及恢复接口；备份恢复约束仍由 Q50 讨论，永久删除不等于取消运维备份。

### Q32 已确认：按提交时的全部服务执行设备级联删除

- 场景：页面甲确认删除设备及 2 个服务；页面乙同时新增服务；页面甲随后提交删除。
- 用户决定：按提交时的数据删除，连同新增的服务一起删除；不因确认期间新增服务强制再次确认。
- 影响：决定删除确认覆盖的是用户看到的关联集合，还是提交时的集合；不影响“设备删除同时删除服务”的已确认规则。
- 落实要求：确认文案说明将删除设备及删除执行时的全部服务，包含确认期间新增的服务；页面展示的数量只作当前参考，不作为服务删除白名单。后端原子执行设备及服务删除，并协调并发新增：删除前成功保存的服务纳入级联，设备删除后不得新增孤立服务。具体事务顺序由后端承担。此前“集合变化必须重新确认”的建议未被采纳，不作为验收要求。参考 S05、S06。

### Q33 已确认：普通资料编辑以最后一次成功保存为准

- 场景：甲把设备型号改成新值；乙仍持有旧表单，只修改备注，却把旧型号一起提交。
- 用户决定：以最后一次保存为准，允许 B 页面覆盖 A 已保存的修改；撤回拒绝陈旧表单覆盖的未采纳建议。
- 落实要求：组、设备、服务普通资料更新不因表单陈旧而拒绝保存，不要求用户处理资产版本冲突或字段合并。最后一次保存指服务端最后一次成功写入，不按客户端时间决定先后。
- 保持约束：写入仍校验权限、必填、唯一性及固定归属；已删除记录返回不存在，不能通过更新重新创建。服务协议/端口与同节点内网 IP 的唯一性不因覆盖策略放宽。
- 代码边界：既有 `managed_config_revision` 属于网络配置，不用于新资产编辑，也不因本决定取消既有配置的版本校验，见 S06。

### Q34 已确认：同一次新增重试返回原结果，不重复创建

- 场景：服务实际上已创建成功，但响应丢失；用户点击重试，或浏览器重复发送请求。
- 用户决定：同一次新增的重试返回原结果，不重复创建；主动再次新增算新操作，仍遵守已有唯一规则。
- 落实要求：区分一次新增的重发与用户发起的新操作；名称、IP 和请求内容相同不能被单独用来推断为同一次操作。按钮防重复提交不足以保障服务器端幂等，并发重复请求也只能创建一次。
- 后端责任：设计请求标识、账号与操作范围、记录期限、相同标识但内容不同的处理，以及结果与创建事务的一致性。重放仍需认证授权，不能跨账号读回结果；记录已被删除后，重试不能重新创建。具体契约在实施设计中明确，不因当前 UUID 创建就宣称已有幂等保证，见 S07。
- 范围：幂等保障不等于操作历史或删除恢复，不新增后台自动重试、定时清理；主动新建仍需校验同节点内网 IP 与同设备协议/端口唯一性。

### Q35 已关闭：不支持移动，移动与旧表单冲突不适用

- 场景：甲把设备从组 A 移到同节点的组 B；乙依据组 A 的资料修改设备名称、地址或服务信息。
- 用户决定：不支持移动。结合 Q02/Q03，设备登记后节点及组归属固定，不考虑整组迁移，以上场景不适用于当前范围。
- 落实要求：新增时确定归属；普通编辑不得改变节点或组，后端校验不能只靠前端隐藏字段。无需为本场景实现移动版本冲突或字段合并策略，不自动增加后续迁移任务。
- 关联决定：Q33 普通资料编辑采用最后一次成功保存，Q34 同次新增重试不重复创建；这两项不允许绕过固定归属。参考 S01、S06。

### Q36 已确认：首阶段不增加操作记录

- 场景：设备型号或服务访问链接发生变化，需要知道谁、在什么时候、做了什么修改；实际服务目标地址选择已后置。
- 用户决定：首阶段不增加操作记录。
- 落实要求：不新增资料操作历史页面、业务审计模块、变更快照或相应保留/清理任务；既有技术日志保持。Q34 所需幂等数据不因此取消，但不将其包装成用户可查询的操作历史。
- 边界：永久删除、无恢复的规则保持；后续权限讨论不自动重新纳入审计功能。若以后确有追溯需求，再独立确认范围。

### Q37 已确认：管理员跨账号查看、新增、修改、删除资料

- 场景：账号 A 与账号 B 均登记了网络节点，管理员是否可以查看并修改两者的下挂设备和服务？
- 用户决定：增加管理员跨账号查看、新增、修改、删除，仍遵守已定归属和删除限制；撤回首版完全不开放跨账号管理的建议。
- 落实要求：普通账号仍只能操作自己的资料；管理员的跨账号操作须由服务端核实权限并明确目标账号及资源。创建下属资料归目标节点的所有者，不因为操作者是管理员就改为管理员所有；不能单凭请求中的管理员标记或 `user_id` 授权。
- 保持约束：管理员也不能移动设备、迁移网关组、转移所有权，不能直接删除有下属资料的节点或非空网关组；设备仍经确认后原子级联删除服务。所有字段及唯一性约束继续适用，相同机器标识不自动代表共享资产，见 S01。
- 设计事项：结合现有身份与权限代码确定管理员识别、入口及目标账号选择，不将 S02 的权限查询直接当成完整授权；S02 是复用前的审查风险，不代表所有现有接口已越权。设备类型仍需明确所属账号及管理范围，不能默认全员共用可编辑字典。新增资料不改变原节点注册方式，不增加手工注册节点流程。
- 范围：Q36 不增加操作记录，Q38 不增加普通账号分享；管理员能力不自动把这两项重新纳入，不改 config-server/OIDC 行为。

### Q38 已确认：首阶段不增加普通账号之间的分享与协作

- 场景：所有者希望家人只查看设备，运维人员可改服务，但只有所有者能删除设备。
- 用户决定：首阶段不增加跨账号分享或协作；Q37 的管理员权限单独保留。
- 落实要求：不新增邀请、共享成员、资源级只读/编辑/删除授权或父子权限继承功能。网关组成员关系仅表示设备拓扑，不能成为用户授权依据。
- 代码边界：现有数据库 `groups` 是用户权限组，不可直接充当网关设备组，见 [groups.rs:15](/workspace/EasyTier-main-node-attributes/easytier-web/src/db/entity/groups.rs:15) 和 S02。普通账号的查看、搜索、数量和关联选择均保持所属账号范围。

### Q39 已确认：先支持普通账号部署，external webhook 新能力后置

- 场景：同一 Web 在内置认证模式能保存离线节点资料，在 external webhook 模式下节点只出现在在线会话列表中。
- 用户决定：先支持普通账号部署，external webhook 模式的新增资料管理后续再做。
- 落实要求：首阶段以现有本地账号与持久化节点为管理基础；OIDC 登录继续沿用既有本地用户映射。external webhook 模式不开放未实现的新资料 CRUD，具体不可用提示在页面设计中明确，保留其既有功能。
- 代码边界：外部模式的节点来源、稳定所有权及中央网络入口均不同，不能只加页面开关就承诺兼容，见 S03。不改 config-server 客户端认证、OIDC 登录或既有配置分发，也不把选择普通账号部署解释为停用外部认证。

### Q40 已确认：先完成 Web，外部程序接入后置

- 场景：后续 EasyADB 或其他程序希望批量创建、更新设备和服务，而不是由用户在 Web 手工操作。
- 用户决定：先完成 Web 操作，外部程序接入后续再做。
- 落实要求：页面正常使用的资料 API 照常设计，首阶段不提供外部程序专用令牌、授权管理、批量同步或 EasyADB 自动写入能力；管理员跨账号权限不自动变成程序全局授权。
- 代码边界：网页登录会话、config-server 客户端凭据、内部管理令牌用途不同，现有内部入口不是已获批准的外部程序接口，见 S04；不复用客户端连接 token 或向外部程序发放内部全局管理能力。

### Q41 已确认：首阶段单条管理，不增加导入导出

- 场景：用户有一批设备及服务，导入时部分设备的节点、组或字段无效；或者需要导出资产清单交接。
- 用户决定：先完成单条新增、编辑、删除，不增加导入导出。
- 落实要求：不新增清单导入、批量校验与结果处理、文件导出或按名称自动合并功能；格式、批次规模和部分失败策略不阻塞本阶段单条管理。
- 边界：设备删除连同服务的既定原子级联不是新增批量导入能力。同次新增的重试仍按 Q34 处理；完整数据库备份、恢复与升级兼容要求仍由 Q50 单独讨论，不因不做清单导出而取消。

### Q42 已后置：资产处置留到未来账号删除需求讨论

- 场景：将来用户真正删除账号，而不是退出登录，其节点下还有组、设备和服务。
- 用户决定：暂不决定，留到账号删除需求再讨论。
- 落实要求：本阶段不增加账号永久删除入口，不选择账号有资料时禁删或级联的产品政策；管理员能管理资料也不等于可以删除账号。不自动开放资产转移或保留期机制。
- 代码边界：未来账号删除必须与资产关联约束一致，不能仅依赖旧表级联规则推导行为。当前已查看的认证与数据库代码没有可复用的账号删除业务入口；现有 logout 只结束会话，不能称为账号注销，见 S08。

### Q43 已确认：首阶段容量设计基线

- 场景：少量家庭设备与多个节点下的大批手机，在列表响应、批量操作和数据库写入压力上差别很大。
- 用户给出的未来一年预期：账号总数 1–5 个；每账号 2–3 个网络节点；每节点 0–10 台设备；每设备 1–2 个服务；同时操作 Web 的人数 1–2 人。
- 使用方式：以上是容量设计输入，不是业务配额、最低数量或已经测试通过的容量。设备可先没有服务，不因预期为 1–2 个服务就强制新增；节点也不强制建满设备。
- 后端责任：据此安排分页、请求上限、并发一致性与后续容量验证，仍避免无界关联查询。当前节点全量查询不能自动等同于新资产接口的合适实现，见 S09；本轮未执行压测、不编造响应时延。

### Q44 已确认：搜索设备名、型号、组网 IP、内网 IP

- 场景：用户在指定节点中输入一个型号、IP 或服务名称，同时选择设备类型与网关组。
- 用户决定：关键词覆盖设备名称、型号、组网 IP、内网 IP；首阶段不覆盖服务名。
- 落实要求：始终在必选节点内查询；已选网关组、设备类型和关键词取交集，结果与总数均按设备记录计算，不因关联查询重复。管理员查询须先通过 Q37 的目标账号授权，普通账号不能扩大到其他所有者。
- 后端设计：明确文本与 IP 的匹配规则、参数长度、分页及索引；IPv6 等价表示需纳入地址匹配设计，不凭原始字符串推导不同地址。不扩展任意网段检索、跨节点搜索或真实状态探测，参考 S01、S09。

### Q45 已确认：最近新增优先，每次查询显示最新资料

- 场景：用户翻到第二页时，另一窗口新增、删除设备或修改排序字段；记录可能出现在不同页。
- 用户决定：最近新增的设备优先，每次查询反映最新资料，不定时自动刷新。
- 落实要求：按创建时间倒序，同值采用稳定次序；更新设备资料不因更新时间改变“最近新增”的排序含义。翻页和手动刷新读取查询时最新数据，不维持首次打开清单的长期快照；其他页面的新增或删除可以使后续页位置变化。
- 后端设计：保证确定性排序和分页，明确查询参数及刷新交互，不为本需求增加人工排序、固定快照导出或后台轮询，参考 S09。

### Q46 已确认：只统计设备数量

- 场景：节点自身被用户另外建成设备以承载本机服务；设备列表中还有手机、NAS 等记录。
- 最新答复：“你只用记录设备的数量，不用记录网络节点以及网关组以及服务的数量”。这项澄清收敛此前的物理去重讨论。
- 当前规则：设备数量只统计下挂设备记录，包括手动新增的网关自身设备；节点、网关组及服务不额外计入。节点卡片使用该节点下全部设备数，筛选列表总数按实际命中的设备记录计算。
- 范围：本需求不新增节点、网关组或服务的数量指标，不新增物理身份字段、硬件识别、跨记录合并或物理设备唯一性约束；查询中一条设备有多个服务时也不能把该设备重复计数。Q48 已确认不增加手动启停标记，不增加按该标记排除设备的计数规则。
- 保持的边界：原实例数仍表示运行网络实例，见 S09；不借本轮去除已有仪表盘或实例统计。“网关自身设备”标识每组最多一条（Q04），注册节点和自身设备资料不额外关联同步（Q10）。
- 代码事实：当前 `devices` 的 `(user_id, machine_id)` 标识注册节点，见 S01；新增设备计数应查询新设备记录，不能把既有注册节点的总数当作下挂设备数量，也不为计数新增探测或定时任务。

### Q47 已确认：展开设备时按需加载服务明细

- 场景：一个节点有较多设备，每台设备又包含多条服务；用户通常只展开少数设备查看服务。
- 用户决定：展开某台设备时加载其服务，操作完成或手动刷新时更新。
- 落实要求：设备列表返回设备所需字段，服务明细独立按需查询，不在初始列表携带当前页设备的全部服务。服务操作完成后更新相关已展示明细；不定时轮询，不新增服务数量指标。
- 边界：列表和展开明细的查询时点可以不同，读取及写入仍检查实时权限和对象是否存在，删除确认照常提示影响范围。Q41 已排除导出，不借展开功能增加全量导出；服务分页和请求上限结合 Q43 容量设计，参考 S09。

### Q48 已确认：首阶段不增加手动启停标记

- 场景：设备或服务暂时不用，用户希望保留资料并在列表中区别显示。
- 用户决定：首阶段不增加，先完成资料管理；设备和服务均不增加手动启用/停用标记。
- 影响：人工状态不等于运行状态、连通性或公网发布状态。首阶段 CRUD 不能让“停用”被误认为已经停止真实设备、进程或转发。
- 落实要求：不新增该状态字段、筛选、隐藏规则或操作限制，不为此改变设备计数；不增加在线探测、心跳、定时任务或远程启停。现有运行状态是节点/网络实例信息，不是下挂服务健康检查，保持原行为，见 [service.rs:169](/workspace/EasyTier-main-node-attributes/easytier-web/src/central_network/service.rs:169)。后续公网发布状态按对应阶段另行讨论，不由本决定取消。

### Q49 已确认：首阶段一个 Web 后端实例

- 场景：当前部署只有一个 Web 服务进程，或后续希望多个进程、容器同时管理同一份资产。
- 用户决定：一个 Web 后端实例即可。
- 落实要求：首阶段不增加多个 Web 进程共享写入、跨主机共享数据库或自动故障切换要求；服务内并发请求仍可能发生，必须保障唯一性、幂等和删除事务，不能因单实例放松数据一致性。
- 代码边界：进程内锁只协调当前实例，SQLite 当前实现不代表已具备跨主机水平扩展能力，见 S06、S10。具体事务和部署方案由后端结合该基线设计，不为当前规模擅自引入分布式组件。

### Q50 已确认：升级前手动备份，允许短暂停机维护

- 场景：新增资产表并升级服务时，需要保证现有账号、已注册节点、网络实例和配置仍可使用；恢复失败数据时可能需要短暂停机。
- 用户决定：升级前手动备份，允许短暂停机维护；停机和恢复时长暂不设硬指标。
- 落实要求：保留现有账号、节点资料、客户端连接能力和原页面操作。后续实施前准备明确的备份、迁移、失败回退与恢复步骤，不增加定时备份任务；允许维护窗口不等于可以任意丢弃已保存资料。
- 设计边界：没有确定故障情况下可接受的数据丢失时间，也不承诺零数据丢失或不停机升级。当前初始化会执行数据库迁移，旧二进制能否读取新迁移状态仍需实际验证，见 S10；备份应覆盖恢复所需的数据库及配置，清单导出不能替代完整恢复。
- 当前范围：只记录维护约束，未执行备份、迁移、停服、恢复或验证。具体技术方案由后端负责，本轮不要求用户选择 schema 或数据库备份命令。

## 后端负责，不要求用户选

以下是实现时必须自行承担的工程责任，不应变成让用户选择是否保障正确性的问题；具体实现尚未开始。

1. **租户与关联隔离。** 从既有认证会话识别操作者并由服务端校验角色；普通账号限定自己的资料，管理员按 Q37 在授权后可操作明确的目标账号资料，不能直接信任请求体 `user_id`。读取、创建、更新、删除、统计、搜索及关联检查采用一致的权限边界；创建资料继承目标父对象的所有者。保证设备、节点、可选组及服务宿主属于同一所有者，必要时采用含租户字段的关系约束；管理员跨账号管理也不能建立跨所有者的父子关系。
2. **原子级联与节点删除协调。** 按已确认规则原子删除设备和其服务；节点有下属资产、组内有设备时禁止删除。既有节点删除可能在数据库事务前先停止托管实例，必须在任何运行副作用前执行资产限制，并协调后续并发创建和最终删除。只在最终 SQL 前检查一次不能覆盖全部竞态；也不能持有长数据库事务等待远程网络响应。首阶段不支持移动，普通编辑必须保持登记时的归属。
3. **稳定身份、覆盖策略与幂等。** 名称和 IP 作为可编辑字段，不作为资产主键。普通资产编辑按 Q33 采用最后一次成功保存，不强制拒绝陈旧表单；保持必填、唯一性、固定归属和不存在记录的检查。依据 Q32/Q34 实现删除确认范围与同次创建重试去重，明确失败后的可重试性；不改动或复用网络配置的 `managed_config_revision`。
4. **权限与安全输入。** 现有权限查询在复用前需校验其用户过滤和管理员授权依据，普通账号及管理员操作均检查父子归属。沿用现有登录及 OIDC 身份，不改 config-server 认证协议，不放宽请求来源与会话安全边界。输入长度、控制字符、合法地址、未知字段、参数化 SQL 及已确认唯一性检查由后端完成。LAN/CIDR 不匹配采用已确认的提示但允许保存策略，不能把提示当作拒绝保存，也不能因此放宽标准网段格式或同节点非空内网 IP 唯一要求；不自动改写用户数据。
5. **错误契约。** 新接口使用稳定错误码和用户可理解的信息，区分未登录、无权限、记录不存在、字段校验、关联或唯一性限制、请求标识内容冲突和内部故障。同次新增重试按 Q34 返回原结果，不仅返回重复错误；不为资产普通编辑新增陈旧版本错误。不返回原始数据库错误、密码、令牌或其他账号的资产详情。字段错误应便于前端定位，数据库和内部栈信息留在受控日志。
6. **查询和容量。** 依据获批筛选和统计口径设计索引、分页、排序、请求上限和按需展开；避免服务展开产生无界查询，也不将全量 JSON 返回作为默认容量方案。事务、索引、SQL、分页编码和是否需要技术层面的快照由后端选择，不让用户填写技术答案。
7. **配置与认证兼容。** 首阶段资产写入只保存资产资料，不隐式改变组网 IP、`proxy_cidrs`、运行实例、端口转发或公网访问。既有中央托管与直接配置权限边界继续有效。人工管理状态不能冒充运行状态；不为本需求增加定时探测、心跳或后台重试机制。
8. **上线与恢复。** 按 Q43/Q49/Q50 的规模、单实例、升级前手动备份及允许短暂停机基线设计迁移与回退，保护既有节点、用户及配置数据；不未经验证承诺旧二进制兼容新数据库或硬恢复时限。后续实施时再安排明确的维护步骤与适当验证；本轮仅讨论文档，不运行测试、构建、CI 或文档校验。
