# 新增设备：先选择角色，再绑定网络实例

用户已确认[实体关系](require-12-overall-topology.md)，要求新增设备时根据“网关还是普通”选择“改网还是不改网”的网络实例，作为正向处理流程纳入需求。本文件记录确认的流程及其实现约束，尚未修改页面、接口或数据结构。

## 已确认操作顺序

在当前网络节点下新增网关设备或直属普通设备：

1. 确定当前管理账号与网络节点，沿用现有详情页上下文和权限。
2. 先选择网关或普通设备。本文称其为“设备角色”，用于与已有手机、NAS、OpenWrt等可维护的设备类型区分；角色决定拓扑归属和实例候选，硬件类型继续用于分类。
3. 再选择当前节点下符合角色的网络实例。角色和实例均须明确选择后才能完成新增；实例的改址情况根据其实际配置展示。
4. 根据所选实例读取相应的IPv4信息与规则，再填写设备资料并保存绑定关系。网关组网IP取自绑定实例；网关下设备的地址带出方式继续遵守require-11。

产品顺序是用户先选择角色，再选择网络实例；后端仍需检查实例配置与所选角色一致，不能只依赖前端筛选。

## 网络实例候选范围

|选择的角色|可选择实例的配置|说明|
|网关|普通子网代理，例如 `192.168.1.0/24`|不改址，但具有子网转发能力，属于网关|
|网关|网段映射，例如 `192.168.1.0/24->10.20.1.0/24`|改址，属于网关|
|普通（直属实体设备）|无子网转发规则|直接绑定该实例|

以上均限于当前账号权限范围、当前网络节点的实例。“改网/不改网”用于说明实例配置，不能仅凭是否存在mapped_cidr筛选直属设备；一个实例也可能包含多条普通代理或映射规则。

网关继续遵守同一节点内与实例一一绑定的既定要求，不能重复占用已绑定其他网关的实例。直属绑定的数量/排他性仍待后续设计，不因本次流程确认自动增加限制。

## 网关下新增实体设备

节点级新增网关或直属设备与网关下新增实体设备分别处理。网关下的实体设备仍属于该网关，沿用网关已绑定的实例及子网规则，按此前约定带出网段、填写主机部分生成地址；本轮不将它们改为每台独立选择无子网转发实例，也不新增嵌套网关。

可选网关自身设备及其服务的既定关系保持。服务继续挂在实体设备下，不直接归属网络实例。

## 实现约束与待设计边界

以下为落实已确认顺序和约束所需的工程处理，不表示新增产品范围：

- 提交前切换角色时，清除已选实例与依赖该实例带出的地址/规则，重新选择，避免残留不匹配的绑定；不据此开放保存后的设备迁移或角色转换。
- 没有符合条件的实例时说明原因，不能跳过必选关系；配置读取失败不能视为无子网转发，也不能自动修改实例配置以迎合所选角色。
- 保存时重新校验账号权限、节点归属、实例匹配及网关一一绑定，处理表单打开期间配置或占用状态的变化。
- 读取及刷新按用户操作触发，不增加定时查询、心跳或自动探测。新地址流程只处理IPv4，既有IPv6能力保持。
- 多规则选择、非/24主机输入、实例配置/运行IP优先级、配置变化后的已有资料处理及旧资料迁移仍按require-11保留设计边界；本轮不宣称这些已收口。
