物理身份识别与多记录去重讨论关闭，不新增物理实体、唯一物理设备约束、硬件识别或数据共享；每组最多一条自身设备标识、独立资料维护、不聚合和不移动等已确认规则保持。

## 3. 网关组的实体含义

网关组表示实际拓扑网络的设备组及其关联的内网网段。组内可挂设备，设备下挂服务；组本身不直接挂服务。每个组和直属单设备都有所属节点。用户已确认一条设备只归一个节点，最多归该节点的一个网关组；设备新增时选择归属，登记后不可修改。

|对象|已明确的属性/关系|仍需讨论|
|---|---|---|
|网络节点|现有注册机器，可挂组和单设备；与自身设备即使同物理机也分别维护，首阶段不额外关联或同步；不加入下挂设备计数|本轮身份与计数决定已收敛|
|网关设备组|所属节点、名称必填可重名、备注选填、至少一个手填 IPv4/IPv6 标准网络 CIDR；同组完全重复拒绝、不同网段包含/重叠允许，不同组可同段或重叠；编辑网段产生地址不匹配时提示但可保存；有设备时禁止删除；不考虑整组迁移|本轮网段与匹配规则已确认|
|单设备|名称必填可重名，型号与备注选填；组网 IP 一条必填可重复，内网 IP 零或一条选填，同节点非空禁重；纯 IPv4/IPv6，组内已填 LAN 不匹配任一同族网段时提示但可保存，空 LAN/直属免匹配、自身适用；登记后归属固定；确认删除及服务；不加手动启停|地址接入逻辑后置|
|自身设备|需要网关本机服务时由用户手动新增的设备记录；增加“网关自身设备”标识，每组最多一条，不强制存在；与注册节点分别维护，不额外关联或同步；作为设备记录计入数量|其他设备属性约束随设备字段继续讨论|
|服务|名称必填可重名、备注选填、单端口，协议选 TCP/UDP/两者；同设备组合禁重；统一由所属设备承载，连接信息不含目标地址；访问链接选填，仅 HTTP/HTTPS，新标签页打开，不加 SSH/RDP 唤起；图标仅选内置项，未选用默认，无外链图片/上传/图片存储/抓取；首阶段无公开开关/意图保存、手动启停或真实转发|目标地址及其变化策略、公网执行后置；链接展示跳转不等于公网发布|

网关本机地址与内网网段是不同字段，例如 `192.168.1.1` 是自身设备的主机 IP，`192.168.1.0/24` 是组的网段。第 6 组已确认设备纯 IP、网关组 CIDR 均支持 IPv4/IPv6；设备每类 IP 最多一条，组仍至少一个网段且允许多个。这是资产属性登记，不自动发布子网或建立路由，不代表实际转发链路已支持 IPv6。

D-13 原话先确认网关组网段由用户手工提供，不自动获取、推导或改写；后续 Q20/Q21 已补齐匹配规则：新增/编辑设备及修改/删除组网段条目时，已填 LAN IP 匹配任一同地址族网段即可，否则提示不匹配设备并允许保存，不额外确认、不改 IP、网段或固定归属。组内自身设备同样适用，空 LAN 与直属设备免此项匹配。提示不影响既定 IP/CIDR 语法、标准网络地址、至少一个网段、同组网段禁重及同节点非空内网 IP 禁重要求。

撤回把“普通组/网关组”做成同一实体两种类型的建议。设备组仅表示实际网关拓扑归属；手机、电脑等通过设备类型筛选，不增加其他集合或成员关系。

设备类型采用常用预置加用户新增/改名，撤回仅固定枚举的建议。设备通过稳定类型 ID 引用，类型改名不丢失关系，仍被设备使用的类型禁止删除。类型仅用于分类筛选，改为 OpenWrt 等类型不会自动创建网关组或改变设备的节点、组归属与服务；完整预置清单、类型重名规则及跨账号共享尚未冻结，不沿用网关组/设备/服务名称规则擅自外推。

服务统一由设备承载：需要网关本机服务时，用户先手动新增并标识“网关自身设备”，再挂服务；每个网关组最多一条，不强制存在。自身设备沿用设备的名称、型号、IP 等属性；标识不替代硬件类型，不自动创建，也不保留另一份直接属于组的服务列表。自身设备与普通设备一样展开服务表，组不提供直接新增服务操作。

Q10 已确认：若自身设备与现有注册节点代表同一台 OpenWrt，首阶段仍分别维护，不额外关联，不同步或改写双方属性。Q46 最新澄清只计下挂设备记录，不进行物理身份识别、多记录去重、记录合并或新增共享资料关系。

本需求新增网关组、设备与服务允许同名，通过稳定 ID 定位；不能以名称匹配代替记录身份或权限判断，不能因重名合并或覆盖资料。该规则不修改现有账号、权限组、网络配置的名称或唯一性约束。

网关组删除规则已由 Q01 确认：有设备时禁止删除。结合 Q02/Q03，首阶段不提供设备移动或整组迁移，须先删除组内设备；不自动将成员移到未分组，也不因删除组级联删除设备和服务。设备的同节点进组、换组、退组与跨节点移动均不支持，编辑界面不能修改归属，不自行把移动或整组迁移列入后续开发。

节点级删除规则已确认：存在任何下属网关组、设备或服务时禁止删除节点，先处理下属数据。

设备级删除规则已由 D-11 确认，并由 Q32 补充：二次确认后，按提交时的数据删除设备及其全部服务，包含确认弹窗后新增的服务，不因服务新增强制再次确认。该决定不等于允许级联删除节点或网关组。

Q31 已确认首阶段网关组、设备和服务永久删除，不提供页面恢复或回收站，删除前明确提示影响范围。后续公网按第 19 组决定直接删除对应本功能转发配置，不依赖运行时撤销确认；不据此改变首阶段的级联范围及节点/网关组删除限制。

### 已确认的查询与加载规则

- 网络节点必选，拓扑设备组、设备类型与关键词条件取交集；关键词仅查询设备名称、型号、组网 IP、内网 IP，不搜索服务名称。组、类型和关键词点击“查询”后统一生效。
- 组筛选只提供“全部设备”或具体网关组，不提供直属设备筛选；全部设备包含当前节点直属与组内设备。新增仍允许直属节点，始终默认直属，保存前可选组；筛选不改变归属，登记后归属固定。
- 设备最近新增优先，每次查询读取最新数据，不固定查询快照、不定时刷新；相同新增时间的稳定次序由后端保证。
- 设备行展开时加载其服务，允许同时展开多台设备；操作完成或手动刷新时更新，初始设备查询不附带当前页全部服务，不增加服务数量指标。

网关组通过筛选旁“管理网关组”弹窗管理，空组也能找到，网段按一行一个 CIDR 增删行。其他已确认填写、放弃输入、新增定位及不匹配警告行为以[前端分组答复](require-09-frontend-grouped-decisions.md)为准，不将旧建议视为已批准规则。

## 4. 公网服务器名称与边界

建议把“云端节点”称为“公网节点”，含义是有公网的服务器，不限定云厂商或部署地点。作为服务转发入口时称“公网入口节点”。不使用“公网出口”描述外部访问服务的入口。

用户已确认允许多台公网服务器；Q51 进一步确认每项服务只使用一个入口节点，由用户手动指定，不默认选择或支持同服务多入口，不据此增加负载均衡或自动切换。

第 19 组已回复：配置保存/删除结果与已有应用反馈分开展示，公网由用户自行验证；离线拒绝开启，恢复后用户手动重试。删除服务直接删除对应本功能转发配置，设备级联同理，不以运行撤销确认作业务删除前提；入口调整以必要配置写入/删除成功为操作成功，不等待旧停止、新监听或公网探测，不新增强制待撤销、长期端口保留或补偿任务。应用未知可显示未确认，不阻止配置成功；配置操作失败仍报错，保留定位自身配置所需最小关联以及既定权限、唯一、固定归属和手工规则冲突保护。

公网标识是一种能力/角色，不占用 OpenWrt/手机/NAS 等设备类型。本轮不推定服务器已安装或连接 EasyTier，不新增联网条件，不自动生成或应用转发规则。
