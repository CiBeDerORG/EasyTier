# 网络节点、网络实例与设备地址关系讨论

用户要求“首先讨论一下网络节点下的网络，设备ip之间的关系”，随后明确命名、网关实例绑定和地址带出方式。本文区分最新需求与现有实现；本轮仅更新讨论文档，不修改表结构、接口或页面。

## 最新已确认方向（2026-10-23）

- 网络节点：旧设备列表中注册到控制台的机器。实体设备：本轮下挂管理的设备。网络实例：网络节点上运行的EasyTier组网实例。
- **最新图示要求：先展示资产实体关系。** 网络节点直接下挂网关设备与直属实体设备；网关下挂实体设备，实体设备下挂服务。网络实例作为设备的绑定关系单独表达，不将实例与配置判断框插入资产归属主干。“改网/非改网”描述所绑定实例的配置方式，不能据此新增两类网络实体，也不能把普通子网代理误判为直属。
- **新增设备采用正向流程：先选网关/普通角色，再选匹配的网络实例。** 当前节点确定后，角色决定实例候选范围；普通子网代理与映射都在网关范围，无子网转发的实例在直属普通设备范围。此流程针对节点下新增网关或直属设备；网关下新增设备沿用网关绑定与规则。详见[新增设备正向流程](require-13-device-create-flow.md)。
- **直属实体设备也必须配置/绑定EasyTier网络实例。** 判断按所绑定实例的子网转发配置进行，不按设备型号或同节点另一个实例是否有规则进行，不能继续把“直属”解释为不关联实例的纯手工资料。
- **用户最新确认：普通子网代理与网段映射都属于网关设备。** 例如仅配置 `192.168.1.0/24`，或配置 `192.168.1.0/24->10.20.1.0/24`，均归为网关；没有子网转发规则的实例对应直属实体设备。业务角色相同，地址转换方式仍不同，不能只按mapped_cidr是否存在分类。读取配置失败不能当作没有规则。
- 新增网关设备必须选择所在节点的网络实例；同一节点内实例与网关设备一一对应。绑定需要包含节点身份，不能因为中央模式跨节点复用instance_id就做成全局实例ID唯一。未要求自动给每个现有实例创建网关资料。
- 网关设备的组网IP来源于所绑定实例，不再独立手填。下挂设备的组网侧/内网侧网段按实例已有转发规则带出；新增时用户填写主机号，由明确规则生成相应地址。这一方向替代之前仅手填网关组网段与设备双IP的方案，尚未实施。
- **用户最新要求“暂时忽略IPv6的处理”：本轮新增的实例绑定配套地址读取、网段带出、主机号输入及地址生成先只处理IPv4；IPv6适配后置。** 这不要求删除EasyTier原有IPv6能力、改写已登记IPv6资料或修改config-server/OIDC。
- 直属实例绑定的数量/排他约束、实例增删子网转发规则后既有直属/网关资料如何处理、配置读取失败时的展示，以及多条规则的选择方式、非/24的主机部分输入、实例配置IP与运行IP不一致/离线时取值、规则变更后的资料跟随与旧资料迁移，仍是后续设计事项；不将助手建议当作已确认产品决定。忽略IPv6不自动等同于IPv4只支持/24。
- 本轮仅确认需求方向，不代表绑定、读取映射或自动配置真实路由已实现；此前IPv4/IPv6均可手工登记的代码事实保留，不能用旧测试通过结果证明新方向已完成。

## 资产归属与实例绑定

|关系|约束|
|---|---|
|网络节点 → 网关设备|一个节点可管理多个网关设备，每个网关设备属于一个节点；此角色承接此前网关组的下挂管理职责|
|网络节点 → 直属实体设备|一个节点可管理多个直属实体设备；直属表示没有所属网关，仍须绑定实例|
|网关设备 → 下挂实体设备|一个网关可管理多个实体设备；每条设备只属于一个节点、最多一个网关，原固定归属规则保持|
|实体设备 → 服务|每个实体设备可登记多个服务，每个服务属于一条实体设备记录；网络实例不作为服务的资产父级|
|网关设备 → 网络实例|必须绑定所在节点的实例，同一节点内一一对应；该实例有普通子网代理或网段映射规则，亦可包含多条规则|
|直属实体设备 → 网络实例|必须绑定所在节点无子网转发规则的实例；直属绑定的数量/排他性仍未定，不由图示擅自补齐|

网关本机服务仍沿用已确认方式：手动创建一条“网关自身设备”，再在其下登记服务；每个网关最多一条自身设备。用户本轮调整主图层级，未要求取消此约定。网关下普通实体设备通过网关绑定的实例及子网规则表达网络访问关系，不自动要求各自独立绑定实例。

以上是业务实体关系，尚未决定将网关与实体设备合表或迁移现有数据结构。网络实例实际仍运行在网络节点上；资产主图采用设备到实例的绑定边，不改变EasyTier原有运行结构。

## 当前代码事实

1. 注册网络节点仍是旧 `devices`，身份是账号 + machine_id，例如OpenWrt。节点可以运行多个EasyTier实例；节点设置下看到的是本机实例/配置，不意味着这张共享逻辑网络只属于该节点。
2. 中央管理 `networks` 表示账号下的逻辑网络，`network_members` 记录节点参与关系；一个逻辑网络可含多个节点，一个节点也可加入多个逻辑网络。成员的 `device_id` 对应旧注册节点的machine_id，不是新asset_devices.id。
3. 节点本地配置表实际名称为 `user_running_network_configs`，有账号、device_id、network_instance_id和network_config。中央编译器令实例ID等于中央网络ID；普通实例不保证存在中央networks记录，不能把两个ID体系无条件合并。[compiler.rs](../../../easytier-web/src/central_network/compiler.rs#L119)、[旧实例接口](../../../easytier-web/src/restful/network.rs#L329)。
4. 中央成员的 `virtual_ipv4` 为手动指定，`allocated_ipv4` 为自动分配并保存；`runtime_virtual_ipv4` 为对应实例实际回报。配置值、分配值和运行值应区别，离线没有运行回报不代表没有登记地址。[成员模型](../../../easytier-web/src/db/entity/network_members.rs)、[运行信息](../../../easytier-web/src/central_network/service.rs#L944)。
5. 新 `asset_devices` 只有所属节点/可选组、`overlay_ip`、`lan_ip` 等字段，没有network_id或instance_id。当前组网IP按手工资料校验/保存，不自动分配、注册EasyTier成员或配置通信。[资产实体](../../../easytier-web/src/db/entity/asset_devices.rs)。
6. 网关组 `asset_gateway_subnets` 仅保存用户手填LAN网段，做地址提示；它没有网络实例关联，不会自动更新EasyTier实例的 `proxy_cidrs`。网络的虚拟地址池 `networks.virtual_cidr` 与这些LAN网段用途不同。
7. 实例 `proxy_cidrs` 支持 `real_cidr`（普通子网代理）和 `real_cidr->mapped_cidr`（网段映射）两种格式，内部有独立可选的 `mapped_cidr`；非空列表不等于一定存在改址映射。[解析器](../../../easytier-core/src/config/api_input.rs#L28)、[配置结构](../../../easytier-core/src/config/toml.rs#L287)。映射两侧前缀长度必须相同，转换保留主机位；普通代理使用原内网地址，不额外生成一套不同地址。[前缀约束](../../../easytier-core/src/config/toml.rs#L773)、[地址转换](../../../easytier-core/src/gateway/proxy/cidr_table.rs#L90)。
8. 原实例完整设置页有 `proxy_cidrs` 多值入口；中央网络成员详情的快捷输入按单IPv4 CIDR处理，目前不接受箭头映射写法。后续实现需明确实际使用入口，不能宣称所有旧页面已经支持相同映射输入。

## 说明示例（示例数据，不是用户已确认配置）

两种网关规则的地址生成示例（主机号均为20）：

|实例子网转发规则|设备角色|下挂设备的组网侧访问IP|下挂设备的内网IP|
|---|---|---|---|
|`192.168.1.0/24`|网关设备|`192.168.1.20`|`192.168.1.20`|
|`192.168.1.0/24->10.20.1.0/24`|网关设备|`10.20.1.20`|`192.168.1.20`|

网关本身的组网IP仍来自绑定实例，与表中的下挂设备访问地址分别表达。普通代理保持原地址；网段映射保留主机位并转换网段。两种情况都不表示给下挂设备创建了独立EasyTier虚拟网卡，也不证明实际网络已经可达。

- OpenWrt节点运行实例A，加入家庭网络，本机虚拟IP为10.10.0.1；也可运行实例B，加入办公网络，本机虚拟IP为10.20.0.1。
- 另一个云服务器节点也能加入家庭网络，使用其自己的虚拟IP，例如10.10.0.2。
- OpenWrt下的手机LAN地址可能是192.168.1.10，所属网关组登记192.168.1.0/24。手机如果没有自己的EasyTier实例，不会因登记在节点下自动获得虚拟IP。
- 后续通过OpenWrt代理LAN网段时，远端可能以手机LAN地址访问它；如果采用映射/转发，访问地址取决于实际规则。以上仅说明不同访问方式，未选择或实现接入方案。

## 早期讨论记录（最新方向以上节为准）

建议分开保存资产管理归属与网络访问关系：属于哪个节点/网关组回答资料放在哪里；通过哪个网络实例访问回答网络路径。IP需要带相应地址作用域，不能仅凭一串地址推断所属网络、可达性或转发目标。

设备当前“组网IP”的最终语义仍需讨论：是设备自己作为EasyTier成员的虚拟地址，还是经网关映射后的访问地址，或者引用网关地址形成访问路径。后者不能无条件当作设备独占虚拟IP。这是地址语义收口，不是自动决定所有设备都安装EasyTier。

若实际业务需要同设备在多张网络有地址，应考虑独立的网络地址/接入关系；本轮未决定单网络还是多网络、强制新增网络选择框、绑定层级、默认选择、迁移方案及地址跟随方式。现有一条必填组网IP、内网IP选填、登记overlay允许重复和同节点LAN唯一的规则暂不改变。

不同网络可以出现相同虚拟IP；同一虚拟网络中的独立成员地址冲突是运行层问题。当前资料允许重填overlay不意味着真实网络允许冲突，更不意味着这些记录已经成为网络成员。
