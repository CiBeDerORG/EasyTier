# 后端评审：实体、地址与服务数据契约

## 1. 阅读方式与已经确定的前提

本文列出 Q01—Q30；前 13 组已确认实体、字段、地址、服务、编辑重试及账号管理范围。第 14 组 Q39/Q40/Q41 已确认普通账号部署优先、Web 先行及单条 CRUD，external webhook 新资料管理与外部程序专门授权接入后续，不加导入导出。第 15 组 Q44/Q45/Q47 已确认设备搜索字段、筛选交集、最近新增优先及服务按需加载；第 16 组已确认预计规模、单个 Web 后端实例、升级前手动备份及允许短暂停机，具体方案由后端设计。后续公网第 17—19 组已回复，19/19 组答复齐全不代表全部细节冻结或扩大实施授权；不阻塞或扩大首阶段资料管理，不改变首阶段级联删除。可靠管理员判定/授权来源、链接输入及图标来源留实现设计，Q52 整个公网地址方案仍后置。

以下已经确定，不再重新询问：

- 第一阶段交付节点、网关组、设备和服务管理，公网发布另设阶段；设备接入与连接逻辑由用户后续补充。
- 不做聚合；网关设备组表示实际拓扑。组和单设备均能挂到网络节点；设备只归一个节点，最多归该节点下一个网关组。
- 网关组至少一个、允许多个 IPv4/IPv6 CIDR 网段，由用户手填，以填写内容为准；不自动获取或按运行配置改写。
- 含主机位的 CIDR 提示标准网络地址，用户手动修改后保存，不静默改写或原样保存。同组完全重复拒绝添加，不同网段包含/重叠允许；不同组同节点与跨节点均可相同/重叠。IPv6 等价 CIDR 按地址族、网络地址、前缀长度比较，不因此放宽同节点内网 IP 禁重。
- 所有设备（直属、组内、自身）组网 IP 恰好一条必填，内网 IP 零或一条选填，留空可保存；单条可为纯 IPv4 或 IPv6，不是每个地址族各一条，不混域名、URL、端口或 CIDR。组内已填 LAN IP 匹配任一同族登记网段即可，否则提示具体设备但允许保存；空 LAN 与直属免此项匹配，组内自身适用。
- 新增/编辑设备与修改/删除组网段条目均采用上述匹配提示，只比较手填数据，不增加强制确认，不自动改 IP、网段或固定归属；提示不是保存失败、离线或不可达，不新增定时任务。既有语法、标准 CIDR、至少一个网段、同组网段去重及同节点非空 LAN IP 唯一约束保持。
- 组网 IP 允许重复，不按 IP 合并设备；非空内网 IP 在同一账号、同一网络节点下所有设备间禁止重复，覆盖直属、全部组内与自身设备，不同节点允许重复。空值不冲突，IPv6 等价写法按同一地址比较，新增/编辑均约束且更新排除自身。只用于新登记资产，不改变原运行地址分配。
- 服务只挂在设备下；网关需要本机服务时，由用户新增自身设备，不自动创建，不在组上直接挂服务。增加“网关自身设备”标识，每个网关组最多一条；不强制组中必须存在自身设备。
- 注册节点与自身设备即使代表同一台机器，首阶段资料也分别维护，不额外关联或同步。按最新澄清，只统计下挂设备记录（含自身设备），不把节点、组、服务计入数量，不新增物理身份去重。
- 节点有下属数据、网关组内有设备时均禁止删除。设备经二次确认后连同提交时的全部服务删除，包括确认期间新增的服务，不因服务数量变化强制再次确认。
- 首阶段组、设备和服务永久删除，页面不提供恢复；删除前明确提示影响范围。设备登记后归属固定，不支持任何移动，不考虑整组迁移；非空组删除前须先删除组内设备。
- 不新增复杂心跳、探测定时任务，不改动既有 config-server 使用方式。
- 新增网关组、设备、服务名称均必填且全部可重名，不加名称唯一约束；设备型号选填；三类均提供选填备注。稳定 ID 定位记录，重名不合并或覆盖。首尾空白处理和长度由后端规范承担，不再追问大小写重名；现有账号、权限组、网络配置约束保持。
- 设备类型预置常用项，用户可新增和改名，仍被设备使用的类型禁止删除；稳定类型 ID 保留引用。类型只用于分类筛选，修改类型不改变固定归属或服务，不将设备转换成网关组。完整预置清单、类型重名和跨账号共享规则未冻结。
- 首阶段设备和服务均不加手动启停标记，不因此新增探测、定时任务或运行控制；公网发布仍归后续阶段。
- 服务协议可 TCP、UDP 或两者同时，每服务仅一个端口；同设备每个具体协议+端口组合禁重，双协议同时校验两个组合。新增/编辑原子校验、编辑排除自身，不跨设备限制；名称仍可重，本期仅登记，不真实监听或公网转发。
- 首阶段服务连接信息只记录所属设备、协议、端口；目标地址选择与引用/快照/跟随规则留公网阶段，不新增来源 IP、覆盖地址或运行下发。暂不展示公开开关，不保存公开意图、不自动发布。
- 服务增加访问链接和可选图标，名称及选填备注保留；URL 可含路径，只展示与点击跳转，不作为转发目标，不随设备 IP 自动改写，不探测 URL 或抓取图标。具体输入及图标来源留 UI/API 设计，不擅自新增上传系统或强制所有服务必填链接。
- Q33 普通资料最后一次成功保存为准，旧表单可覆盖之前修改；仍守校验、唯一性、权限和固定归属，已删除记录不复活，不改既有网络配置 revision。Q34 同次新增重试返回原结果，主动再次新增为新操作，不能按名称/IP 猜重复。Q36 首阶段不增加操作记录或审计模块，保留既有技术日志，不增加定时清理。
- Q37 首阶段增加管理员跨账号查看、新增、修改和删除；普通账号只操作自身资料，Q38 不提供普通账号间共享/协作。服务端验证管理员身份及目标账号权限，数据引用和唯一性在目标所有者账号内校验，固定归属、禁移动/迁移与删除限制保持。可靠管理员判定与授权来源待实现设计，不宣称现有权限已完整具备。
- Q42 账号永久删除政策留独立需求，不新增本阶段入口；管理员资料 CRUD 不另建手工网络节点注册、不修改 config-server/OIDC，不因权限增加审计模块，自定义类型不默认跨账号共享编辑。
- Q39 首阶段先支持普通账号/本地用户登记部署，external webhook 模式新增资料管理后续；OIDC 沿用现有本地用户映射，不改认证、config-server 或外部模式既有功能。Q40 Web 及其正常 API 先行，外部程序专门授权接入后续，不新增程序令牌或全局 API。Q41 单条 CRUD 先行，不加导入导出；数据库备份恢复按第 16 组决定另行设计。
- Q43 预计未来一年 1–5 个账号、每账号 2–3 个节点、每节点 0–10 台设备、每设备 1–2 项服务、1–2 人同时操作 Web，仅作设计基线，不设数量配额或最低数量，不代表已通过压测。Q49 只部署一个 Web 后端实例，无多实例、多主机高可用要求。Q50 升级前手动备份，允许短暂停机，停机/恢复暂不设硬时限；后端设计具体方案并保持原有用户、节点、客户端连接和页面，不据此立即执行操作、允许任意丢失数据或承诺零损失。

本文只审查数据契约，不实现、不运行测试，不把填写地址等同于地址在线可达。所有代码引用相对于当前仓库根目录，行号为本轮阅读时的位置。

|**Q21 已确认**|修改或删除组网段条目后，组内设备的已填 LAN IP 不再匹配时怎样保存？|检查修改后至少一条有效标准 CIDR；对组内已填 LAN IP 比较修改后的任一同族网段，给出受影响设备提示，不自动改设备或建立额外网段归属。|同 Q20：不匹配提示但可保存，无额外强制确认，不改 IP/网段/固定归属。每组至少一条、标准 CIDR、同组完全重复拒绝、同节点非空 LAN IP 唯一等约束不放松。|
|**Q22 已确认**|设备地址和网关组网段使用什么格式？|设备 IP 与组网段分别校验，禁止把域名、URL、带端口地址或 CIDR 当作设备纯 IP；网段字段解析为 IPv4/IPv6 CIDR。|设备填写纯 IPv4 或 IPv6，网关组填写 CIDR，不混域名、URL、端口。服务端口使用服务字段，未增加域名地址字段。|

“手填为准”与语法合法性、跨字段匹配是三个不同概念。现已确认手填来源、合法格式及标准 CIDR 要求，以及不匹配时提示但可保存；不能自动探测后推翻填写值，也不能用当前实例配置的默认值替代资产地址。例如 `easytier-core/src/config/toml.rs:683` 对既有 IPv4 配置有 `/32` 转 `/24` 的读取行为，新资产输入不能直接复用后继承这一副作用。

## 5. 后端必须自行承担的实现责任

以下是落实已确认业务规则的技术要求，不再作为让用户决定“要不要正确实现”的问题：

- 设备查询要求必选节点，组、类型与关键词条件取交集；关键词仅匹配设备名称、型号、组网 IP、内网 IP，不搜索服务名称。按最近新增优先查询，每次读取最新数据，后端保证相同新增时间的稳定次序，不固定查询快照或增加定时刷新。设备行展开时加载其服务，操作完成或手动刷新更新；设备初始查询不附带当前页全部服务，不增加服务计数，设备与服务请求均遵守既定账号权限。
- 服务端验证字段类型、合法 IP/CIDR、端口范围、协议枚举和必填规则；前端校验不能代替 API 校验。
- 服务组合禁重按所属设备、具体 TCP/UDP 协议和单端口校验；双协议拆成两个待校验组合，一并检查与原子保存，任一冲突整次失败，新增与编辑均适用，编辑排除当前服务自身。不能仅按“设备+端口”禁重，否则会误拒绝两个独立 TCP/UDP 同端口服务；不能把双协议当第三种值绕过单协议占用，也不能跨设备限制。本期不探测系统端口、不真实监听或转发。
- 服务访问链接和可选图标只作展示资料，与后续转发目标独立；不自动随设备 IP 改写链接，不探测 URL 或自动抓图标。目标地址选择/引用/快照/跟随尚在公网阶段，不提前引入来源 IP、覆盖地址、公开意图保存或自动发布。链接校验和图标来源由 UI/API 设计具体化，不擅自扩张为上传系统或所有服务必填链接。
- 稳定 ID、资料所属账号和对象关系用于查询与权限判断，名称、IP 和外观标签不能代替身份。普通账号限自己的资料；管理员须由服务端验证身份及目标账号操作权限，不能仅信任客户端角色或目标 `user_id`，也不能将所有请求都限制为操作者 `user_id`。保存关联验证父对象属于同一目标账号与节点，管理员不能借跨账号操作移动资料或改变所有权。
- 管理员判定与授权来源须在实现设计中明确，当前需求决定不等于现有权限实现已满足要求。新登记资产的唯一性仍在目标所有者账号范围内执行；自定义类型不默认跨账号共享编辑，不因管理员 CRUD 新增节点注册、审计或账号永久删除入口。
- 普通资料编辑不以陈旧表单版本为强制拒绝理由，按最后成功保存生效，但仍在当前权限、字段、引用与唯一性约束下更新；目标已删除则不得恢复或转为新增。不要复用或改变既有网络配置 revision 的冲突策略。
- 同一次新增请求的重试识别与结果返回由后端实现，不能因重复提交再建记录，也不能把重名或同 IP 当作同一次操作。用户主动再次新增使用新操作，仍校验既有约束；重放原结果不复活随后已删除的数据。该技术保障不扩展为用户操作记录、审计模块或定时清理。
- 新增网关组、设备、服务的名称全部可重复；同名创建不合并或覆盖，修改和删除只针对指定 ID。后端统一承担名称去首尾空白、空白名称拒绝、字段长度及可空字段规范，不将这些实现细节重新变成重名政策问题。该规则不修改既有账号、权限组或网络配置约束。
- 类型按稳定 ID 引用，改名不丢关系；使用中的类型删除检查与设备引用变化保持一致，不能只依赖前端禁用按钮。修改类型不触发拓扑转换、服务变更或运行控制，也不把组/设备/服务名称可重复的决定外推为已确认的类型重名规则。
- 新资产组网 IP 可重复；非空内网 IP 的唯一范围覆盖同一账号、同一节点的全部设备。地址先按 IP 语义解析，IPv6 等价写法不能绕过约束；空值不冲突，编辑排除自身，新增与并发编辑均须保持一致。该规则不改动原运行地址分配，也不因网段可跨组相同或重叠而豁免。
- CIDR 含主机位时给出标准网络地址提示，等待用户改正后保存；不静默改写、不原样保存。以地址族、网络地址、前缀长度识别同组完全重复，拒绝重复而允许不同网段包含/重叠及跨组相同/重叠，维持至少一个手填网段。
- 落实 Q20/Q21 的提示与保存结果分离：设备新增/编辑、网段修改/删除条目时只比较手填 LAN 与任一同族网段；对不匹配设备给提示但不阻断保存或增加强制确认。空 LAN/直属免匹配，组内自身适用，不自动改数据或固定归属，不派生离线/不可达结论，不增加定时任务。提示机制不能绕过其他语法、数量与唯一性约束。
- 设备及其服务按已确认删除范围保持事务一致；节点存在下属数据时，在停止网络或删除注册信息之前拒绝删除。二次确认要清楚展示将删除的设备和服务范围。
- 不把当前运行实例的期望地址、自动分配地址、观察到的运行地址与资产手填地址混为一谈；现有 `easytier-web/src/central_network/service.rs:169` 已分别表达前三类值。
- 不复用有副作用的配置转换来“顺便校验”资产表单。`easytier-core/src/config/api_input.rs:352` 会过滤空 IP 或不能解析成 `SocketAddr` 的转发项，新服务 API 不能把这种静默丢弃包装成保存成功。
- `easytier-core/src/config/gateway.rs:22` 的 protobuf 协议转换可能把未知值回落为 TCP，而运行转发只接受 TCP/UDP；新服务 API 应明确拒绝非法枚举，不依赖这种回落行为。
- 底层函数和 UI 中的默认值、唯一条件只适用于其现有用途。新增资产的数据规范要按已确认契约实现，不能直接继承权限组的全局唯一组名、运行配置的默认前缀或单个中央网络的地址分配策略。
