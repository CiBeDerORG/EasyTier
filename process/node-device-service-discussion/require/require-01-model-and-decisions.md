# 节点详情、下挂设备与服务：模型与待决策事项

## 1. 本轮范围与已表达的需求

用户要求先讨论需求，由产品经理结合实际代码指出问题。本阶段不实现功能；下文“建议”不等于已确认需求。D-01 至 D-07 已收到回复，最新 D-07 明确“不聚合”，模型修订详见 [网关组与入口](require-02-gateway-groups-and-entry.md)。

- 左侧“网络节点”下增加二级菜单“节点详情”。
- 实例数字保留网络实例数含义，0 时也能展示设备列表；用户允许另设设备数量标识进入详情。
- 节点可标识为有公网的服务器，允许多台；建议名称为“公网节点”，承担服务公开时称“公网入口节点”。
- 页面先展示筛选条件：网络节点必选且单选，设备组和设备类型可筛选。
- 网关设备组代表实际拓扑网络，绑定至少一个、允许多个内网网段；设备组和单设备均能直接挂在节点下。
- 用户最新答复明确不做聚合；保留设备类型筛选，不新增聚合视图、聚合类型字段或自定义聚合成员关系。
- 第一阶段交付节点、网关组、设备和服务管理；公网发布另一个阶段。有下属数据时禁止删除网络节点。一条设备记录只归一个节点，最多归其中一个网关组。新增时可选择直属节点或节点内一个组，登记后归属固定；首阶段不提供同节点进组、换组、退组或跨节点移动，不考虑整组迁移。
- 删除设备时二次确认，并按提交时的数据连同其下全部服务一起删除，包含确认弹窗展示后新增的服务，不因此强制再次确认。非空网关组禁止删除；当前不支持移动，须先删除组内设备。首阶段网关组、设备和服务均永久删除，删除前明确提示影响范围，不提供页面恢复或回收站。
- 所有设备（直属、组内、自身）的组网 IP 必填且恰好一条，内网 IP 选填、零或一条。两类设备地址都支持 IPv4/IPv6，填写纯 IP，不混入域名、URL、端口或 CIDR；单条允许任一地址族，不是各族各一条。
- 组网 IP 允许重复，不按 IP 合并设备；已填内网 IP 在同一账号、同一网络节点下禁止重复，覆盖直属设备、所有网关组内设备及自身设备，不同节点允许相同内网 IP。多个内网空值不冲突；这些规则只用于新增资产登记，不修改原运行组网地址分配。
- 网关组的网段由用户手工设置，采用 IPv4/IPv6 CIDR，至少一条且允许多条；不自动获取或按运行信息改写。组内已填内网 IP 不属于任一同地址族登记网段时提示受影响设备但允许保存，不增加强制确认，不改 IP、网段或固定归属；空内网 IP 与直属设备免此项匹配，组内自身设备适用。资料支持 IPv6 不代表已支持后续实际转发。
- 网段含主机位时提示标准网络地址，由用户手动修改后保存，不静默改写或原样保存。同组完全重复网段拒绝添加，不同网段的包含/重叠允许；不同组无论同节点或跨节点均可填写相同或重叠网段，不豁免同节点非空内网 IP 禁重。
- 设备类型预置常用项，用户可自行新增和改名；被设备使用的类型禁止删除，以稳定类型 ID 维持引用。OpenWrt、手机、NAS、智能家居为此前提及的示例，不据此冻结完整预置清单、跨账号共享或类型重名规则。
- 类型仅用于分类与筛选；更改设备类型不把设备转换成网关组，不改变固定归属或服务。首阶段设备和服务均不增加手动启用/停用标记，也不因此增加探测、定时任务或运行控制。
- 节点详情列出设备，支持新增设备；设备行展开其服务列表，提供新增服务、删除等操作。
- 设备明确属性：名称、型号、组网 IP、内网 IP。其他属性必须讨论。
- 服务首阶段维护名称、所属设备、协议、端口、备注、访问链接及可选图标；原始“是否公开”及云端自动转发目标保留到公网阶段，首阶段不展示公开开关、不保存公开意图、不自动发布。
- 服务连接信息首阶段只记录所属设备、协议与端口，不新增目标地址来源或覆盖 IP；目标地址选择以及引用、快照、随设备 IP 变化的规则留公网阶段。访问链接选填，仅接受 HTTP/HTTPS，可含 URL 路径，在新标签页打开，不增加 SSH/RDP 唤起；与转发目标独立，不随设备 IP 自动改写。图标只选内置项，未选使用默认，不提供外链图片、上传、图片存储或抓取，不探测链接。
- 服务协议可选 TCP、UDP 或两者同时；每条服务只填一个端口。同一设备下每个“协议 + 端口”组合只能属于一条服务，双协议同时校验两个组合；不同设备不跨范围限制，服务名称仍可重复。本期仅登记，不真实监听端口或执行公网转发。
- 第 4 组已确认：网关组、设备、服务的名称均必填且全部允许重名，不设置名称唯一约束；设备型号选填；三类对象均提供选填备注。以稳定 ID 定位，重名不合并或覆盖记录。名称去首尾空白、空白名称校验及字段长度由后端规范承担，不再追问大小写重复规则。
- 以前已明确 OpenWrt 节点本机也会运行服务，必须覆盖这个场景。
- 网关需要本机服务时，用户可以在网关组内手动新建自身设备，再在设备下挂服务；增加“网关自身设备”标识，每个网关组最多一条，不强制存在。组不直接挂服务，不自动创建本机设备。
- 自身设备与注册网络节点即使对应同一台物理机器，首阶段也分别维护，不额外关联或同步。按第 3 组最新澄清，只统计下挂设备记录，包含用户手动新增的自身设备，不将网络节点、网关组或服务加入设备计数；本需求不新增这三类对象的数量指标，原实例数量及既有仪表盘保持不变。
- 用户明确后置设备是否连接 EasyTier 以及连接逻辑；当前继续讨论资产模型，不再以回答连接方式作为前提，也不替用户推定接入策略。
- 延续约束：保持现有节点设置和 config-server 工作方式；不新增复杂心跳、后台探测定时任务。状态依靠正常接口查询与用户操作。
- 第 12 组已确认：本需求普通资料编辑以最后一次成功保存为准，允许后提交的旧表单覆盖先前修改，但仍遵守权限、字段校验、唯一性和固定归属，已删除记录不得复活，不修改既有网络配置 revision。同一次新增的重试返回原结果、不重复创建；用户主动再次新增是新操作，仍受已有约束，不能按名称或 IP 猜重复。首阶段不增加操作记录或审计模块，保留既有技术日志，不增加定时清理。
- 第 13 组已确认：首阶段增加管理员跨账号查看、新增、修改和删除资料；普通账号仍限自己的资料，不提供普通账号间共享或协作。服务端校验管理员身份及其对目标账号的操作权限，关联对象仍归目标账号且遵守固定归属、禁移动/迁移及删除限制。管理员授权来源与可靠判定仍待实现设计，不能将权限组存在等同于已有完整管理权限。账号永久删除政策留到账号删除需求，首阶段不新增该入口。
- 第 14 组已确认：首阶段先支持普通账号/本地用户登记部署，external webhook 模式的新增资料管理后续处理；OIDC 沿用现有本地用户映射，不改 config-server、认证或外部模式既有功能。先完成 Web 及页面所需正常 API，外部程序专门授权接入后续，不新增程序令牌或全局 API。先交付单条 CRUD，不加导入导出；数据库备份恢复按第 16 组决定另行设计。
- 第 15 组已确认：关键词只查询设备名称、型号、组网 IP、内网 IP，不搜索服务名称；网络节点必选，组、类型与关键词条件取交集。设备按最近新增优先，每次查询读取最新数据，不固定快照、不定时刷新，同值稳定次序由后端保证。展开设备时加载其服务，操作完成或手动刷新时更新，不在初始设备查询中附带当前页全部服务，不新增服务计数。
- 第 16 组已确认：未来一年按 1–5 个账号、每账号 2–3 个节点、每节点 0–10 台设备、每设备 1–2 项服务及 1–2 人同时操作 Web 作为设计基线，非配额、最低数量或已通过压测的结论。部署一个 Web 后端实例，无多实例、多主机高可用要求。升级前手动备份、允许短暂停机，停机和恢复暂不设硬时限；后端设计具体方案，保持原有用户、节点、客户端连接及页面，不据此立即执行备份、允许任意丢数据或承诺零损失。

基线是当前 `feat/node-attributes-main` 工作树，包含此前节点属性和未部署的卡片/导航修改。不得把其他生态分支、用户管理分支的设计当作本基线已有能力。

## 3. 按用户回复修订的实体边界

```text
网络节点：现有 EasyTier 注册机器
├─ 网络实例：现有组网能力，可多个
├─ 网关设备组：实际拓扑归属，绑定一个或多个内网网段
│  ├─ 组内单设备
│  │  └─ 服务
│  └─ 自身设备：有需要时由用户手动新增并标识，每组最多一条
│     └─ 网关本机服务
└─ 直属单设备
   └─ 服务
```

以上反映用户要求的拓扑与服务归属。自身设备仍是一条设备记录，增加“网关自身设备”标识；每组允许零条或一条，不自动创建，也不强制存在。用户已确认每条设备记录只归一个节点，至多属于该节点的一个网关组；新增时选择归属，登记后不能在编辑中改动。具体数据库模型尚未冻结。

当前范围仅保留实际拓扑中的网关设备组。用户已明确不聚合，不设计普通分类组或聚合成员关系。节点有任何下属数据时禁止删除；设备经二次确认后连同提交时的全部服务删除；网关组内有设备时禁止删除，当前须先删除组内设备。此前“删组直接移为未分组”的统一建议保持撤回；设备移动与整组迁移已关闭本轮讨论，不自行列入后续开发。

服务统一挂在设备记录下。网关自身设备保存所需名称、型号、IP；不再要求网关组直接维护一套本机服务。Q10 已确认：若自身设备与现有注册节点指向同一台机器，首阶段仍分别维护，不额外关联、同步或自动创建。此前固定本机行与服务直接归属节点/组的建议撤回。

Q46 已由最新补答收敛为只统计下挂设备记录，包含手动新增的自身设备；节点、网关组和服务不加入计数。节点卡片统计该节点下全部设备，筛选后的列表统计命中的设备。物理身份识别与多记录去重讨论关闭，不新增物理设备实体、唯一物理设备约束、硬件识别或数据共享，也不改变不聚合、不移动的已确认范围。

不根据设备是否安装 EasyTier 决定是否允许登记。地址自动发现、资产和运行实例关联、子网发布与连接方式均由用户后续补充；现阶段不自动建立连接或路由。

设备、组和服务的所有引用均须校验目标账号与节点归属，不能仅凭客户端提交的 ID 关联。普通账号只可操作自己的资料；管理员跨账号操作须由服务端验证身份及目标账号权限，不能简单把目标 `user_id` 限定为当前操作者，也不能接受客户端自报管理员身份。所有下属关系仍在同一目标账号与节点内，不能借管理权限移动、迁移或转移所有权。`devices` 和权限 `groups` 的既有含义保留；新增实体名称和表结构在模型确认后再冻结。

管理员新增资料能力不另建手工网络节点注册流程，原节点登记、config-server/OIDC 和既有网络配置版本机制保持。Q36 不新增操作记录的决定也不因管理员能力而改变；自定义设备类型不默认成为跨账号共享编辑资源。

## 4. 页面和属性规则（按已确认回复更新）

### 页面流程

沿用左侧菜单、右侧功能区域，保留现有页面操作。前端已确认细则见[前端分组及收尾答复](require-09-frontend-grouped-decisions.md)：F02–F15 和 F19–F21 已答，F16–F18 未答撤回。问答已结束，不追加问题；下列仍明确标为建议的实现细节不视为用户批准。

1. 保留原实例数，另设计独立的设备数量入口（用户已允许此方向）。从该入口进入时携带节点身份，预选必选节点；节点离线、实例数为 0 或设备数为 0 时仍允许进入，空设备列表提供新增操作。节点卡片统计该节点下全部设备记录，含手动新增的自身设备；筛选列表展示命中的设备数量。不额外增加节点、网关组或服务数量指标，不修改既有仪表盘，详见第二份需求文档。
2. 从侧边栏直接进入且未指定节点时，恢复当前账号上次访问且仍有权限的节点；没有有效选择时先选节点，不默认任意第一项。刷新或重新打开详情链接仅恢复节点，组、类型与关键词重置；有效显式目标不被上次节点覆盖。管理员跨账号管理时先选目标账号，再选该账号的节点，页面明确显示目标账号；服务端校验授权，资料归目标账号，不因操作者是管理员而改变所有权。
