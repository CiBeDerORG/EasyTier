### 具体工作

1. 新增节点扩展元数据、网关组及子网、设备类型、下挂设备、服务、协议绑定、操作幂等表；使用 P01 中 `node_asset_metadata`、`asset_*` 名称。
2. 网络节点以 owner `user_id` 和 `machine_id` 引用旧 `devices`；新增业务记录用 UUID。给组、设备、类型建立同 owner 的组合关联，设备的可选组还必须与其节点一致。
3. LAN 以规范值存储，可空且同 owner/节点内非空唯一；组网 IP 无唯一索引。自身设备标记在 group 内至多一条，直属设备不能标为网关自身设备。
4. 子网持久化标准网络地址/前缀/地址族或等价规范列，建立同组完整 CIDR 唯一约束。至少一个子网由 T05 的事务校验承担，不用空字符串占位。
5. 服务协议用独立 binding 记录，每条为一个具体协议与端口，建立设备/协议/端口唯一索引；保证 binding 的设备、服务及端口引用一致，主记录与 binding 由 T07 同事务维护。
6. 设备删除级联服务和 binding；组有设备及节点有组/设备时通过约束兜底拒删。节点自身元数据可随节点删除，不能单独构成“有下属数据”阻挡。账号永久删除仍是后续需求，不增加本期账号删除流程。
7. 操作表支撑 actor/owner/操作类型/请求 ID 唯一、请求摘要及稳定结果；幂等记录不能随资源删除一起消失从而允许原请求复活资源。
8. 增量迁移保留旧用户、节点、来源 IP/地区、地点/型号、网络配置与会话。索引覆盖节点内创建时间排序、组/类型过滤和计数；不引入 Redis 或全实体 JSON 存储。

### 可审阅验收与风险

可审阅条件：同名对象可并存；同节点非空 LAN 和同设备协议端口被数据库约束；空 LAN 可多条；组/节点不能留孤儿；设备删除覆盖服务和 binding；旧节点主键和已有列值保留；重试记录删除资源后仍有效。

重点风险是 SQLite 外键启用状态、组合父对象约束、Nullable 唯一性、双协议原子性及迁移保留数据。交付实现和待验证数据，不把静态文档描述当验证结果。本轮未执行任何迁移或测试；调试模式不自动运行测试、构建、类型检查、lint、CI，后续按 T15/T16 授权执行。
