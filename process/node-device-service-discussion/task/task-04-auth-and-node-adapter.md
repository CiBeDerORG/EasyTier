### 具体实施

1. 实现按当前登录 user_id 限定的管理员关系查询，使用既有 `users_groups`/`groups` 的 `admins` 关系。不能直接调用未限定 `_user` 的现有权限查询作为可信结果，也不能按用户名 admin、固定 ID 或前端字段赋权。
2. 构建统一 actor/owner 上下文：普通账号只能 owner=self；管理员可选目标账号，但每次调用仍核实身份、账号存在和资源所属。返回安全的账号 ID/名称，不返回密码、token 或会话数据。
3. 提供资产能力/部署模式响应和受权账号列表、节点目录。管理员先账号后节点；普通账号无需先选别人账号。external webhook 模式关闭新资料管理接口，保留其原登录和节点流程。
4. 节点目录按 DB 注册记录查询，离线、零实例和零设备可见。标识使用 owner+machine_id，不能仅凭 machine_id 读取或写入另一账号。
5. 从 `node_asset_metadata` 读写手工 `is_public_server`，未登记视 false；可多节点同时标记。不从公网 IP 自动判定，不引入公网地址/监听字段、公开开关或转发下发。
6. 输出节点设备记录数批量查询能力，包含网关自身设备；不计节点/组/服务，不改变现有实例数或仪表盘指标。旧页面如何调用由 T14 实现，不把查询加入每秒循环。
7. 设计并实现节点资产存在检查和受权删除入口的适配函数：任何网关组（含空组）或设备存在即拒删。新资产目录不提供手工注册节点；管理员删除应转交统一旧节点删除服务，不能直接删表绕开原配置流程。
8. 明确创建组/设备与原节点删除共用 `CentralNetworkService::lock_mutations()` 的接入顺序。原方法名已核对为 `lock_mutations`，不是 `mutation_guard`；T13 在原服务内部已有锁之后插入保护，避免重复加锁死锁。

9. 明确实现受权的 `DELETE /api/v1/assets/nodes/{machine_id}?owner_user_id=...`，保留已有可选 `block` 语义；handler 在调用服务前校验 actor/owner/节点，再将目标 owner 传给 `CentralNetworkService::delete_device`。不能让管理员调用旧 `delete_machine` 并错误使用操作者 ID。无资产时保持原合法删除与拉黑行为，有资产时由 T13 在服务持锁区、任何运行副作用之前拒绝。
10. 节点 metadata PATCH 除新 `is_public_server` 外，还允许受权管理目标账号已有的 `site_location`、`device_model`，接口路径/字段按 P01。新角色存 `node_asset_metadata`，地点/型号继续写已有节点字段并复用既有校验，不重复存储；自动连接 IP、地区和 machine 身份不可修改。旧用户自身属性接口、卡片与注册流程保持，不能借节点资料修改增加手工注册。

### 验收条件与边界

本任务不改 config-server、OIDC、本地用户创建流程、用户名作为现有 token 的行为，不新增账号管理/删除、分享、程序授权或审计。代码已写入并接入，验收场景未执行；后续测试、构建、lint、CI 仅按 T15 的用户授权范围运行。授权错误和删除前置保护仍是必须验证的集成项，不能以界面隐藏代替。
