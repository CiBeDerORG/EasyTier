### 目标、来源与基线

将 T01 的统一资产契约映射到现有 ApiClient，使 T09–T12 能按同一份 DTO 与组件边界并行。来源：Q33/Q34 的覆盖与重试、Q37–Q40 的账号权限与部署范围、Q44–Q47 的查询；F02–F15、F19–F21 的页面交互与链接图标政策。

实际代码：`easytier-web/frontend/src/modules/api.ts::ApiClient` 的 axios `client` 是 private，构造器配置 `/api/v1` 与 cookie，响应拦截器统一解包及 401 回调；旧 `ConsoleInfo` 没有完整管理员能力。`MainPage.vue` 向页面传现有 api，`centralEnabled` 只是 webhook 部署模式。本轮已新增 `types/node-assets.ts` 及 `assets*` 方法，通过资产 context 获取管理员能力。

### 唯一写入范围

- 新建 `easytier-web/frontend/src/types/node-assets.ts`：DTO、查询、表单值、错误和组件 Props/Events 的共享类型。
- 修改 `easytier-web/frontend/src/modules/api.ts`：新资产方法和必要的能力类型，复用现有 axios 实例。
- 新建 `easytier-web/frontend/src/composables/useAssetMutation.ts`：统一创建请求身份、未知结果重试和错误提取。

### 实现步骤

1. 领取 T01 冻结结果，统一注册节点与新资产命名；ID 按服务端契约视为稳定不透明标识，不用名称或 IP 充当 ID。
2. 增加 `/api/v1/assets` 下账号能力、目标账号/节点目录、节点元数据、设备数量、组/类型/设备/服务 API，具体路径与方法逐项采用 T01，不自行创造相似旧 `/machines` 接口。
3. 查询和写入上下文包含目标 `owner_user_id`、`machine_id`；操作者身份从会话能力获取，不将客户端声明的 actor 当授权。普通账号和管理员共用受服务端校验的契约。
4. 明确设备分页/总数、默认排序、可选组/类型/关键词、设备与组的非阻断警告、服务协议集合/单端口、链接和内置图标字段。类型可空等工程默认采用 P01，不能漏回被撤回的必填建议。
5. 类型化字段错误、无权限、父对象失效、资源冲突、请求结果未知和部署不支持。保留现有 401 流程，不增加认证机制，不把查询失败转成空数组或数量 0。
6. 新增方法透传 T01 约定的幂等操作身份；同次重试复用身份和内容，主动新建另生成。API 层不通过名称/IP 猜测重复，也不对失败请求进行无界自动重试。
7. 冻结下列组件契约，交付给 T09–T12。纯组件开发可使用相同类型的本地数据，不宣称真实后端已接通。

### 组件交接契约

|组件边界|输入|输出/约定|
|---|---|---|
|页面上下文|可信能力/操作者、目标账号、节点及 api|完整上下文对象；切换时使旧上下文请求失效|
|设备表格|设备行、加载/失败、总数/页码、展开 ID 集合|翻页、展开/收起、编辑、删除事件；`services` slot 向父页面提供设备记录|
|设备弹窗|上下文、可选原记录、组和类型选项、保存回调|保存成功结果和关闭事件；创建操作身份在重试中保持，编辑不发送可变归属|
|组/类型弹窗|所属范围、现有资料、契约内 CRUD/预览函数|稳定 ID 的变更结果；类型为账号范围，组为节点范围|
|服务面板/弹窗|完整设备上下文、服务读取与写入函数|局部加载/错误及成功变更；不修改外部设备列表或节点选择|

Props/Events 的最终标识写入类型文件后再交接，不让各任务使用不同含义的 `deviceId`。增加类型化纯校验方法：`POST /assets/validation/gateway-subnets`（T05）和 `POST /assets/validation/device-address`（T06），均位于 `/api/v1` 下；上下文、可选原记录 ID、待校验值及响应字段采用 T01 冻结版本。响应可表达 `field_errors`、`warnings`、受影响设备与标准 CIDR 建议，不保存、不自动修改；保存 API 仍最终校验。只允许用户失焦/明确操作触发，禁止定时预览，不在前端复制 IPv4/IPv6 网段算法或擅自引入新依赖。
