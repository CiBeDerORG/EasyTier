### 来源与代码现状

D-04/D-05/D-06/D-07、Q01–Q10、Q17–Q22、Q34、F07–F09 定义拓扑组、类型、网段与弹窗需求。现有 `db/entity/groups.rs` 是权限组，不是拓扑网关组，名称唯一策略不能复用。旧前端 CIDR 控件仅支持 IPv4 并补 `/24`，新接口必须按 T03 标准 IPv4/IPv6 CIDR 契约处理。

### 独占范围与并行边界

- T01–T04 已交接；实际由同一 store owner 维护 T03/T05–T07，前端各组件仍按独占文件并行。
- 实际存储文件为 `easytier-web/src/db/assets/groups.rs`、`types.rs`；handler 和路由集中在 `easytier-web/src/restful/assets/mod.rs`，未新增同名 REST 分文件。
- schema 与 REST 各有独立 owner；存储层直接读取冻结的数据库关系，不调用其他领域的 HTTP handler。

### 工作内容

1. 在 owner+节点上下文提供网关组列表、单条新增/编辑/删除，管理列表包含空组，不受设备列表当前筛选限制。名称必填可重，备注选填，组所属节点登记后固定。
2. 每组至少一条手填标准 CIDR，逐项使用 T03 解析；同组完整重复拒绝，不同条目的包含/重叠允许，不同组相同/重叠允许。
3. 新增组使用 T04/T13 规定的节点写入协调，再校验节点存在并事务写入组及全部网段；禁止边循环边提交而留下半组资料。
4. 编辑组网段时，同事务更新集合并返回已登记组内设备的不匹配提示。空 LAN 免检查；只比较手填数据，不探测网络、不自动改设备 IP，不匹配允许保存。
5. 删除组发现任何设备（含自身设备）即拒绝；不自动移出或级联设备，不提供迁移接口。仅删除空组及其网段，结果为永久删除。
6. 类型按 owner 独立提供列表、新增、改名、删除。工程默认预置 OpenWrt、手机、电脑、NAS、智能家居、其他；种子建立须可重复执行且不重建用户已删除/改名的类型，具体初始化标记遵循 P01/T01。
7. 类型稳定 ID 不因改名变化；被任意该 owner 的设备引用时禁止删除，不自动改为其他。工程默认允许设备 type_id 为空、不追加类型名称禁重；这些是 F16–F18 撤回后的设计默认，不写成用户新确认。
8. 新增组、类型使用 T03 幂等；普通更新最后成功保存生效，已删对象不能 upsert 复活；权限和 owner/节点关联每次检查。

补充只读预览：提供 `POST /api/v1/assets/validation/gateway-subnets`，输入 `owner_user_id`、`machine_id`、可空 `gateway_group_id` 和拟保存 `subnets`。复用 T03 校验后返回字段错误、标准写法建议及受影响设备 ID/名称的非阻断警告。新组没有既有设备时返回空受影响集合；编辑组必须先校验所指组归属。预览不写 DB、不下发配置、不取代保存时校验，仅供表单失焦或明确操作触发，不引入轮询。

### 交接与验收

给 T10 提供包含空组的列表、逐行网段字段错误、标准 CIDR 建议、保存成功附带设备警告、类型在用禁删、同次新增重放样例；给 T13 提供路由注册及锁调用片段。组与类型都不会直接挂服务。
