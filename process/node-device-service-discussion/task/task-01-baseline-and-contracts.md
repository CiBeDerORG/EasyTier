## 工作与交付物

1. 记录实际开工代码版本与已有修改边界，不替用户重置或整分支覆盖。
2. 在本需求 `plan/contracts/` 写明 DTO/字段空值、索引/关联、操作权限、请求响应、错误/警告和路由；逐条引用 P01，不自行加产品功能。
3. 固定类型初始化的持久“一次”机制，初始化是显式写操作且可重试，删除预置后不被读请求重建。记录类型选填、账号独立、管理弹窗等工程默认来源。
4. 明确创建幂等作用域、请求摘要、原子结果、已删重放、未知结果重试及修改草稿的处理；给出至少成功、重复、冲突、已删除四种响应示例。
5. 明确节点删除副作用前保护、锁获取顺序、调用者不能二次取锁、事务不跨网络等待；明确服务新增/设备删除与组/类型删除竞态如何收敛。
6. 固定前端 DTO、Props/Events、翻译 key 命名清单、分页后新设备定位、管理员账号→节点和当前上下文清理协议；不改变已答交互。
7. 给 T02/T08 发布同一契约版本，交接给其他任务；后续变更必须先更新该版本，再通知受影响 owner，避免各自补字段。

## 唯一写入范围与并行边界

仅 `plan/contracts/*`、本任务/P01 的契约补充；技术 owner 维护契约，不占有其他任务代码文件。T02 实现 Rust 实体，T03 实现 DTO/错误与校验底座，T08 实现 TS 类型，避免同一类型文件被多 agent 改写。契约冻结后 T02 与 T08 并行；不能让各领域自行修改公共接口。

- 文档能够明确区分注册节点、网关组、资产设备、服务、权限组和网络实例，不出现 `device_id` 同时表示 machine 与资产两种含义。
- API 覆盖已定 CRUD、批量设备计数、节点静态标记、账号目录和两个只读预览；无公开开关、转发或定时状态字段。
- 每个公共代码文件都有单 owner，所有未答项注明工程默认而非用户批准；未承诺时长或吞吐数字。
- 风险：旧工作树改动尚未形成单独版本，需先记录才能区分回归范围；不以用户管理分支功能已存在作为本次 main 基线前提。
