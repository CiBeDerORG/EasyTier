### 工作步骤

1. 提供指定设备下服务列表、单条创建、编辑、删除。每次检查 owner/node/设备链，服务只挂设备，不挂网关组或节点；新服务归父设备所属账号。
2. 字段为必填名称、一个端口、非空 TCP/UDP 协议集合，选填备注、HTTP/HTTPS 访问链接、内置图标键。名称可重，链接可空，未选图标用默认键或规范空值映射。
3. 同设备同具体协议+端口只能归一条服务。单条 TCP+UDP 服务在 `asset_service_bindings` 写两条，任一冲突则整个事务失败；TCP 53 和 UDP 53 两条服务可以并存，不同设备同组合也可以并存。
4. 编辑时排除自身旧 binding，服务和全部新 binding 同事务替换，不能先删旧记录并提交后再尝试新组合。保留旧数据直至完整事务成功；普通编辑最后成功保存生效，不能改设备归属。
5. 创建使用 T03 持久幂等。已有成功创建的响应丢失时重试返回原结果；主动新增使用新 operation ID，仍遵守端口唯一约束。已删服务不能由旧编辑/原创建重放复活。
6. 服务列表只在设备展开、操作后或手动刷新时由前端请求，不加入后台刷新；支持多设备独立请求，接口失败不伪装为空列表。规模小，具体列表形状沿用 P01，不额外提供服务数量指标。
7. 删除是永久删除服务及其 binding，不操作实例、端口监听或转发。设备级联删除由 T06 DB 事务完成，本模块保障设备被删后不能再插入孤立服务。
