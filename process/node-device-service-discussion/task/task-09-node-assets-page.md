### 实现步骤

1. 建立操作者/资料所属账号/节点三个概念。管理员先选账号再选其节点，持续显示目标账号；普通账号固定自身。能力未知、获取失败和 external webhook 不支持时不得假定可写。
2. 按授权核对显式链接节点；无显式目标时恢复当前登录身份上次仍授权节点，首次或失效停在待选状态。账号/节点记忆隔离，失效记录不得让页面静默展示其他账号资料。
3. 详情链接只定位节点及其必要所属账号身份；刷新/重开不恢复组、类型、关键词。账号或节点切换清除旧行、选项、展开内容和未保存表单，直接丢弃、不弹确认。
4. 维护查询草稿和已应用查询。组筛选只有全部设备/具体组，类型和关键词取交集；点击“查询”才应用。首次加载、分页、CRUD 后的必要读取使用明确已应用条件。
5. 设备按最近新增优先、稳定同值次序分页，显示实际命中设备总数；区分未选节点、加载、无设备、筛选无结果和读取失败。展开 ID 集合允许多设备；服务按需加载由 T12 面板负责。
6. 按 T08 错误和请求代次隔离晚到响应；节点切换后旧数据不能覆盖新页面。不得新增周期请求或接入 MainPage/DeviceList 现有计时循环。
7. 新建设备始终默认直属当前节点。创建成功关闭表单、定位并展开新设备；不符合已应用条件时同时清空表单和已应用的组/类型/关键词再查询，保持当前节点。符合条件则不额外清空；失败不清空输入或筛选。
8. 在所选节点上下文呈现及维护静态 `is_public_server`，名称与 P01 一致；只是手填角色，不从 IP 自动识别、不发布服务或承诺公网可达。
9. 正常返回旧网络节点列表时给 T14 明确的初始状态导航意图；不保存返回前的查询/页码/滚动，也不删除已有视图/语言/主题偏好。
