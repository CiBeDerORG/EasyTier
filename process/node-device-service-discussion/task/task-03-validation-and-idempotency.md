### 实施步骤

1. 按 P01 定义 AssetContext、请求/响应 DTO、分页/筛选、警告结构、创建 operation ID、对象 ID 与错误码。普通更新不接受可改 owner/node/group 的归属字段；服务更新也不能换所属设备。
2. 实现名称/备注/型号的空白、长度和控制字符规则；名称必填可重，型号与备注可空。长度是统一工程限制，不借此增加名称唯一约束。
3. 纯 IP 解析支持 IPv4/IPv6，拒绝 URL/域名/端口/CIDR；规范表示用于唯一性比较，LAN 空值统一为 null。组网 IP 必填且一条，LAN 最多一条。
4. CIDR 检查支持两族，含主机位时返回标准值供用户手工改正，不能静默保存修正值；同组完整规范 CIDR 去重，包含/重叠不作冲突。组设备 LAN 不匹配返回非阻断警告，空 LAN/直属设备免匹配。
5. 服务端口限制有效端口范围；协议展开为 TCP/UDP 具体集合，集合非空且去重；HTTP/HTTPS 链接可空、保留合法路径，仅作访问资料；图标只能使用 P01 内置键或默认值，不接受文件/远程图片来源。
6. 创建 operation ID 按 actor、owner、操作种类隔离，和业务写入同事务持久化请求摘要、资源 ID 及返回结果。并发同键只创建一次；同键不同内容返回业务冲突；重放仍重新授权。
7. 成功响应丢失、进程重启或资源随后删除后，原 operation 重试都不能重建资源。对已删资源返回原创建结果并标明其已不存在或按 P01 规定返回可识别终态；禁止将“当前查不到对象”解释为重新创建许可。
8. 事务失败不留下虚假成功记录；普通编辑按最后成功写入生效，不使用网络配置 revision，不 upsert 已删资产。业务冲突与内部错误分开，内部 SQL/凭据不直接泄露到响应。
