第 2 组最新决定：首阶段登记后设备的所属节点和可选网关组固定，不提供进组、换组、移出组成为直属设备或跨节点移动；不考虑整组迁移。新增时仍可选择直属节点或该节点下的网关组，普通资料编辑不得成为变更归属的绕过入口。Q35 移动冲突不适用并关闭，Q33 普通并发编辑按第 12 组的最后一次成功保存规则处理；不自动安排迁移为后续实施任务。

第 3 组最新决定：手动新增的设备可标记为“网关自身设备”，每个网关组最多一条，不强制存在或自动创建。即使注册节点和自身设备代表同一台 OpenWrt，首阶段也分别维护资料，不额外关联或同步。用户补充明确“只用记录设备的数量，不用记录网络节点以及网关组以及服务的数量”，据此数量按下挂设备记录统计，含自身设备，不把节点、组、服务额外计入，也不新增这些对象的数量指标。节点卡片展示该节点设备总数，筛选列表总数为命中设备记录数；原有网络实例计数保持。关闭此前待定的物理身份识别与去重讨论，不新增去重实体、合并记录、硬件唯一性约束或数据同步能力。

第 4 组最新决定：新增网关组、设备、服务的名称全部可以重复，不限制重名；三类名称均必填，设备型号选填；三类均提供选填备注。资源以稳定记录 ID 定位，不能通过重名合并或覆盖资料，不新增这些资源的名称唯一约束；此规则不改动既有账号、权限组或网络配置的命名约束。Q30 的服务备注已确认，不再重复提问；URL、路径和图标仍待后续服务分组讨论。

第 5 组最新决定：设备类型预置常用选项，并支持自行新增和改名；被设备引用的类型禁止删除。类型用于分类与筛选，修改类型不自动将设备转换为网关组，不改变固定归属或服务关系。首阶段设备和服务均不增加手动启用/停用标记，先完成资料管理；不新增相应状态字段、筛选或计数排除规则，不改动现有节点/实例运行状态。类型需保持稳定标识，改名不丢失引用；具体存储与权限设计结合后续讨论，不擅自将所有账号的自定义类型共享。

第 6 组最终决定：每台设备组网 IP 必填且恰好一条，内网 IP 选填且最多一条，适用于直属、组内及自身设备。两类设备 IP 及网关组网段均支持 IPv4、IPv6；设备字段填纯 IP，网段填 CIDR，不混入域名、URL 或端口。单条 IP 可选任一地址族，不是每个地址族各一条；网关组仍至少一个且允许多个手填网段。用户已对补问明确“允许保存，内网 IP 选填”，关闭 Q13；地址重复、网段重叠和手填地址匹配未因此决定，也不承诺实际双栈接入或转发。

第 7 组最新决定：组网 IP 允许重复，不以 IP 识别、合并或覆盖设备。已填写的内网 IP 在同一网络节点内禁止重复，不同节点允许；同节点直属设备、所有网关组成员和自身设备共同受此约束，不按组另设地址空间。空值不构成冲突；比较按 IP 地址含义处理等价 IPv6 写法，并在账号范围内校验，新增和编辑均需保证。该规则针对新登记设备，不改变既有运行网络的地址分配策略，也不将内网唯一限制扩展到组网 IP。

第 8 组最新决定：网关组输入含非零主机位的 CIDR（如 192.168.1.7/24）时，提示标准网段 192.168.1.0/24，由用户手动修正后再保存，不静默换算或原样保存。同组拒绝完全重复网段，允许不同网段之间包含或重叠；不同组无论是否同节点均允许相同或重叠网段。重复判断按地址族、网络地址与前缀含义处理 IPv6 等价写法。网段可重复不豁免已填内网 IP 同节点唯一；不自动发现、发布路由或改设备地址。设备地址匹配按第 9 组决定提示但不阻止保存。

第 9 组最新决定：新增/编辑设备或修改/删除组网段条目后，已填内网 IP 不在所属组任一同地址族网段中时，提示哪些设备不匹配，但允许保存；不自动修改设备 IP、组网段或固定归属。此项只比较手填数据，适用于组内设备及自身设备；内网 IP 留空、设备直属节点时不做匹配检查。保存成功与提示要明确区分，不新增强制二次确认，不把不匹配显示成网络离线或服务不可达。组至少一个标准网段、同组网段去重、内网 IP 同节点唯一等规则保持。

第 10 组最新决定：每条服务只登记一个端口，传输协议可选 TCP、UDP 或同时两者；同一设备下同一协议与端口组合只能属于一条服务记录。双协议记录同时参与 TCP 和 UDP 的唯一性校验：已有 TCP+UDP 53 时不能再建 TCP 53 或 UDP 53；TCP 53 与 UDP 53 两条单协议记录则互不冲突。新增与编辑均保证约束，编辑排除自身，两个协议一并成功或失败；不同设备不共用该唯一范围。服务名称可重复规则不变；本阶段不实际监听端口、不自动公网转发。

第 11 组最新决定：首阶段服务记录所属设备、协议和端口，目标地址选择及跟随规则留到公网阶段；保留已确认名称和备注，并增加可点击访问链接及可选图标。访问链接可包含路径，只作为展示和跳转信息，不据此生成转发目标或 HTTP 路由，不自动随设备 IP 改写，不探测链接状态。首阶段暂不展示“是否公开”开关，公网功能上线时再增加；不借此新增公开意图保存、自动发布或计划任务。图标素材来源、链接的具体输入细则在页面/API 设计中明确，未自动授权上传系统、图标抓取或全部服务强制填写链接。

第 12 组最新决定：普通资料编辑以最后一次成功保存为准，允许旧页面提交覆盖先前修改；仍校验必填、唯一性、权限和固定归属，已删除记录不能通过旧表单重新创建。同一次新增操作重试返回原结果、不重复创建，用户主动再次新增是新操作，仍遵守已有唯一规则；请求标识与并发保证由后端设计，不能按重名或相同 IP 猜测同一次操作。首阶段不增加操作记录功能，既有技术日志保持；不改动网络配置已有版本机制，不增加后台重试或清理任务。

第 13 组最新决定：首阶段增加管理员跨账号查看、新增、修改、删除节点及下属资料的能力，仍遵守固定归属、非空节点/网关组禁删、设备确认后级联删除等规则；普通账号只管理自己的资料，不增加账号间分享、协作或分级授权。管理员操作需明确目标账号与资源，后端验证管理员身份及目标资源归属，不信任客户端自行声明管理员或所有者；不因此允许资产转移、自动注册节点或绕过原节点注册/配置流程。未来永久删除账号的资料处置暂不决定，留到独立需求，不新增首阶段账号删除入口。设备类型的授权范围需随权限模型明确，不默认所有账号共用可编辑类型；操作记录仍按第 12 组不纳入。

第 14 组最新决定：首阶段新增资料管理先支持普通账号部署，OIDC 沿用既有本地账号映射；external webhook 模式的新增资料管理后续再做。先完成网页登录后的操作，不新增 EasyADB 等外部程序专门授权和接入能力；先做单条新增、编辑、删除，不增加导入导出。既有登录、config-server 连接、外部模式原有功能及页面正常接口保持，不能将本轮范围收敛理解为删除既有能力；不因管理员 CRUD 自动增加程序全局令牌、批量写入或文件导出。完整数据库备份恢复约束仍在第 16 组单独讨论。

第 15 组最新决定：在必选节点内，关键词搜索设备名称、型号、组网 IP、内网 IP，不扩展到服务名称；已选设备组、类型和关键词取交集，设备结果及数量按记录去重。默认最近新增的设备优先，采用稳定的同值次序；每次查询显示当时最新资料，不维持首次查询的长期快照。展开某台设备时加载其服务明细，操作完成或手动刷新时更新，不在首次列表查询中携带全部服务，不增加定时刷新或服务数量指标。具体匹配、分页和索引由后端设计，未据此承诺已经支持某个容量。

第 16 组最新决定：未来一年预计 1–5 个账号，每账号 2–3 个网络节点、每节点 0–10 台设备、每设备 1–2 个服务，同时操作 Web 的人数为 1–2 人；这些是容量设计输入，不作为必填数量、业务配额或已验证的性能承诺。首阶段一个 Web 后端实例即可，不要求多进程或跨主机共享写入、故障切换。升级前手动备份，允许短暂停机维护，停机及恢复时长暂不设硬指标；保留既有账号、节点、客户端连接与原页面操作。备份/迁移/恢复方案仍由后端结合 SQLite 和现有迁移机制设计，未据此执行备份、停止服务或新增定时任务，也未承诺任意故障下零数据丢失。

第 17 组最新决定（后续公网阶段）：每个服务只选一个入口节点，由用户手动指定；多台公网服务器仍可作为候选，不自动选择默认入口或做多入口发布。入口地址方案留到公网阶段实施前确定，地址类型、数量及具体监听配置不在本轮冻结。公网映射端口由用户手填，冲突时提示，由用户修改后重试；不自动分配、替换端口。监听冲突需结合实际主机、绑定地址及协议处理，不能把不同网络实例当作独立的主机端口空间，也不能以保存成功代替实际监听结果。以上不提前加入首阶段公开开关、配置下发或转发能力。

第 18 组最新决定（后续公网阶段）：平台只配置 EasyTier 转发，主机防火墙、云安全组及 DNS 由用户处理；公网第一版先做 TCP/UDP 端口转发，不增加 HTTP 域名/路径分流或证书管理。TCP 转发可以承载已有 HTTPS 流量，不代表平台代理或管理其证书。只管理本功能创建的规则，遇到手工规则占用、或本功能规则被手工修改导致冲突时提示，不自动覆盖，也不增加旧规则认领功能。规则归属、变更范围和应用证据由后端结合既有中央配置路径设计，不修改 config-server/OIDC，不增加定时探测、自动防火墙或外部凭据管理。

第 19 组最终决定（后续公网阶段）：展示配置保存结果及已有下发/应用反馈，公网访问由用户自行验证；入口离线时拒绝开启，恢复在线后由用户手动重试。公开与业务删除不做运行状态强绑定：删除服务时直接删除该服务对应的本功能转发配置，删除设备时同样处理其级联服务；关闭公开也按删除对应配置处理，不因入口离线而要求等到运行时确认撤销后才能删除。入口调整以必要配置写入/删除成功作为操作成功标准，不新增旧入口停止、新入口监听或外网可达的强校验，不承诺运行时切换顺序、无中断或短暂双入口。配置成功可以与应用结果未确认并存，界面不能将其标成公网已验证；配置操作本身失败必须反馈。保留定位本功能规则所需的最小关联、权限和冲突保护，不额外增加强制待撤销流程、长期端口保留、自动补偿或定时探测。
