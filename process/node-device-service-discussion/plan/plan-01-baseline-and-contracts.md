### 命名与模型

数据库/Rust/JSON 字段使用 `snake_case`；TypeScript 类型用 `PascalCase`、局部变量及方法用 `camelCase`；Vue 组件 `PascalCase.vue`。前端显示“网络节点”不重命名旧注册表或改变 config-server 字段。新业务组件使用 `NodeAssetsPage`、`AssetDevice*`、`AssetService*`；不复用旧 `DeviceDetails` 的语义。类型词条可改名，不能以名称作 ID。

|实体/规划表|关键字段与关系|关键约束|
|---|---|---|
|既有 `devices`|`user_id + machine_id`；已有运行/地点型号属性|不以在线 session 为资料存在条件，不因改前端名称改主键|
|`node_asset_metadata`|相同复合节点键、`is_public_server`|只扩展静态角色；不作为下属资产计数或阻止删除的子资源；心跳不得覆盖|
|`asset_gateway_groups`、`asset_gateway_subnets`|组 UUID、owner、node、名称/备注、CIDR 独立行|组名可重复；至少一段；标准 IPv4/IPv6；同组完全重复拒绝、重叠允许|
|`asset_device_types`|UUID、owner、名称、初始化来源信息|只分类，稳定引用；使用中禁删；不等同权限 `groups`|

|`asset_services`、`asset_service_bindings`|服务 UUID、设备、名称、单端口、协议集合、备注、可空 HTTP/S 链接、内置图标标识；每协议占用一行|设备+协议+端口唯一；TCP+UDP 原子写两行；服务/设备删除级联对应占用|

### API 契约草案

新命名空间 `/api/v1/assets`，与旧 `/machines`、实例管理分开。列表上下文显式包含 `owner_user_id`；节点级请求还含 `machine_id`。这些值只定位，授权从会话读取。普通用户只可选自己；管理员先选账号再选节点。所有请求都按普通部署范围检查，不依赖浏览器开关。

|资源|计划操作|交付任务|
|---|---|---|
|`GET /context`|当前 actor、是否可跨账号、资产功能是否可用；不暴露认证秘密|T04|
|`GET /accounts`|仅管理员可选的账号 ID/名称；不返回密码、session、OIDC token|T04|
|`GET /nodes`、`GET /device-counts`|目标账号的离线/在线节点目录；批量设备记录数。零与请求失败明确区分|T04|
|`PATCH /nodes/{machine_id}/metadata`|受权修改手工公网角色，以及目标账号节点原有地点/型号；角色存扩展表，原字段复用，不开放修改自动 IP/地区或机器身份|T04|
|`DELETE /nodes/{machine_id}`|管理员/所有者作用域核实后转交原节点删除服务；资产检查在副作用前，合法无资产删除保持原有行为|T04/T13|
|`/gateway-groups`、`/gateway-groups/{id}`|列表/新增/查询/更新/删除；节点内含空组|T05|
|`/device-types`、`/device-types/{id}`|目标账号类型目录与 CRUD，初始化方案由 T01 明确|T05|
|`/devices`、`/devices/{id}`|节点内列表/新增/查询/更新/级联删除，过滤组/类型/关键词，固定归属|T06|
|`/devices/{id}/services`、`/services/{id}`|设备服务列表/新增，单服务查询/更新/删除；不含公网发布|T07|
|`POST /validation/gateway-subnets`|纯预览：owner/node、可空 group ID、候选 subnets；返回格式错误/标准值建议与受影响设备|T05 调 T03|
|`POST /validation/device-address`|纯预览：owner/node、可空 group/device ID、地址；返回地址错误与所属网段警告|T06 调 T03|

除明确 `PATCH` 的节点角色外，创建 POST、完整资料编辑 PUT、删除 DELETE；GET 不提交业务修改。每个创建携带 UUID `request_id`，同次超时重试保留 ID 和原提交内容，主动新建采用新 ID。请求示例、初始化接口及参数最终放到 T01 的接口附录，不允许各任务自行设计不同版本。

设备列表返回 `items,total,page,page_size`，排序 `created_at DESC,id DESC`；只有设备匹配条数，没有新增服务/组计数指标。关键词只查名称、型号、组网 IP、内网 IP。服务只在展开时取；列表不预装所有服务。创建结果返回稳定新 ID，页面据此定位；分页和并发插入时具体定位策略由 T09 明确，不靠名称/IP猜测新记录。

统一错误响应至少含 `code,message,field_errors`；成功保存的非阻断提示放 `warnings`。错误示例：未登录 401、无权限 403、资源不存在 404、冲突 409、已删除幂等结果 410、字段不合法 422；external webhook 新资产能力禁用的状态码与 code 在 T01 固定。CIDR 不标准返回建议但不替用户修正；LAN 不匹配网段是 warning，不能改为保存失败。预览只在编辑失焦或明确操作请求，不自动保存、不定时请求，也不能替代提交事务的最终校验。

### 并发与前后端交接

节点删除与新增组/设备复用 `CentralNetworkService::lock_mutations()` 的同一协调域，锁顺序统一为业务写锁再数据库写事务。T13 在原删除副作用前检查组/设备存在，包含空组；禁止锁内再次获取同一锁。数据库事务不跨网络停止等待；在单后端模式下业务锁保护等待期间的父子关系，事务/FK完成最终完整性约束。若需细化锁粒度，T01 记录等价证明，不增队列或后台任务。

设备删除与服务新增由同一数据库事务/约束协调：已提交服务全部级联，删除后新增失败；永久删除的记录不能通过 PUT 或原创建重放恢复。last-write-wins 不免除权限、固定归属和唯一性。无新的资产版本弹窗，也不删除旧网络配置 revision 机制。

T08 独占 TS DTO 和 `ApiClient`；组件共用 `AssetContext`（actor/owner/node）、表单值、错误/警告、分页以及事件类型。T09 管理账号/节点/路由、已应用查询、展开状态和晚到响应隔离；T11 设备表用具名 services slot，T12 提供服务面板；T10–T12 不写 Page 或公共语言文件。表单取消直接弃输入，打开状态请求失败保留；异步创建结果未知时不换 request ID 盲重试。
