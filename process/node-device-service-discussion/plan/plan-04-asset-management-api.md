### 代码事实与复用限制

目前 `easytier-web/src/db/entity/` 没有下挂设备、网关组、设备类型、服务目录实体。旧 `entity/groups.rs` 是权限组，其名称唯一规则不能用于新的拓扑组。`restful/network.rs` 的机器接口围绕注册节点和运行实例；`db/devices.rs:259` 删除注册节点会处理中央网络配置与可选拉黑，不能用作新设备删除。

沿用当前 Axum/serde 请求处理和 SQLite 存储机制，但新 API 在 `/api/v1/assets` 下独立建模。具体路径、字段与错误码由 P01/T01 冻结，T03 提供共享 DTO，不允许各领域各自发明前端无法统一处理的响应格式。

### 规则落实

- 三类名称必填可重，型号/备注可选；固定归属按 stable ID 校验，不按名称或 IP 归并。
- 组含至少一个用户输入的标准 IPv4/IPv6 CIDR；不同组可同段/重叠，同组完全重复拒绝，包含关系允许。内网 IP 与组网段不匹配只提示，不阻止保存。
- 设备组网 IP 恰好一条必填，可重复；LAN IP 零或一条、同节点非空唯一。组内自身设备手工新增，每组最多一条。
- 类型只分类筛选，不改变节点/组/服务；预置可维护、引用中禁删。按 owner 独立、类型可空、类型名称不新增禁重是本轮工程默认，F16–F18 没有被用户答复，不能误记成用户选择。
- 服务一个端口，TCP、UDP 或双选；同设备同具体协议/端口只能归一个服务。双选原子写入两条 binding，任何一项冲突整体失败。
- 服务链接选填 HTTP/HTTPS，图标仅内置标识；不追加图片上传、抓取、状态检测或公网开关。
- 普通编辑最后成功保存生效，不能复活已删对象或变更归属；所有新增使用事务持久幂等，真正再次新增必须使用新请求 ID。

### 查询与交互对接

设备必须在单一节点上下文查询，网关组、类型和关键词取交集。关键词只搜名称、型号、组网 IP、LAN IP；组筛选只有全部或具体组，不另加直属筛选。按 `created_at DESC` 加稳定 ID 次序分页；每次查询最新资料，不建立长期快照。初次列表不附带所有服务；服务按设备展开时加载，允许多设备分别请求。

组编辑返回保存结果及不匹配设备提醒；设备列表返回对应提醒信息，让前端在 LAN IP 旁展示。创建响应包含稳定 ID 和定位所需资料，支持 F12/F14 保存后定位展开；若清空筛选，仍留在同一 owner/节点。接口不自行安排轮询或后台刷新。

编辑前提示通过两项只读预览接口具体落实：T05 提供 `POST /api/v1/assets/validation/gateway-subnets`，T06 提供 `POST /api/v1/assets/validation/device-address`，共用 T03 校验及授权上下文，返回 `field_errors`、`warnings`、受影响设备 ID/名称和标准写法建议。预览不写库、不下发配置，在失焦或明确用户操作时请求，不定时查询；正式保存必须重新校验，不能把预览结果当作跨请求锁定。
