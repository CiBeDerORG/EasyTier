### 数据设计边界

拟新增 `node_asset_metadata`、`asset_gateway_groups`、`asset_gateway_subnets`、`asset_device_types`、`asset_devices`、`asset_services`、`asset_service_bindings`、`asset_operations`。名称和字段由 P01/T01 冻结；这些是待创建的表，当前代码中不存在。可搜索、过滤、关联及唯一判断字段使用列和索引，不把全实体装进一个 JSON 字段。

注册节点仍以 owner `user_id` 加 `machine_id` 定位；新组、类型、设备、服务使用独立 UUID。节点扩展资料只存手工 `is_public_server` 角色，不承载公网地址、监听状态或发布意图。设备必须引用同账号、同节点的父对象；类型按 owner 独立是本轮工程默认，不是用户对类型共享的新增答复。

约束包括：非空 LAN IP 在同一 owner/节点内唯一；组网 IP 可重复；每组自身设备至多一条；同组标准 CIDR 去重；同设备每个传输协议和端口组合唯一。TCP/UDP 双选使用两条绑定记录，并与服务主记录原子写入。至少一个网段、固定归属及跨字段匹配由事务中的领域校验补足，不能指望单个普通外键表达全部规则。

设备删除在事务内级联其全部服务/协议绑定；组有设备和节点有组或设备时拒绝删除。节点自身扩展元数据不是阻止删除的下属资产。父对象检查、唯一性、创建与删除都须协调竞态；节点删除的运行副作用保护另见 P03/T13，数据库拒绝不能代替服务层前置保护。

创建幂等记录与业务写入同事务持久化，以操作者、目标 owner、操作种类、请求 ID 隔离；保存请求摘要及稳定结果。同键同请求重放返回原结果，同键不同内容冲突，资源后来被删除也不得重新创建。普通更新仍最后成功写入生效，不套用既有网络配置 revision。
