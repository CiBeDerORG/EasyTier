# 节点资产契约 v1

2026-10-23，实施基线 `feat/node-attributes-main` / `e307dadb` 加既有节点属性和菜单未提交修改。用户已授权开发；调试模式下不运行测试、构建、类型检查、lint、CI，不部署提交。此文件是各 agent 的共同接口，改动先通知调用方。

## 传输与身份

所有接口前缀 `/api/v1/assets`，沿用 session/cookie。查询参数 `owner_user_id: number` 必传（context/accounts 除外）；节点操作另有 `machine_id: UUID string`。单记录和服务接口也携带此 scope，后端从数据库确认完整归属，不能只信 ID。类型仅 owner 作用域。

管理员从当前会话 user_id 对数据库 `admins` 组成员关系作精确查询；不调用未限定用户的旧权限集合，不修改登录/OIDC/config-server。普通用户 owner 必须是自己。external webhook 模式 context 返回 available=false，其余新接口拒绝；旧功能保持。

统一错误 `{code:string,message:string,field_errors:Record<string,string>}`；HTTP 401/403/404/409/410/422/500 分别表示登录、权限/模式、对象消失、约束/幂等冲突、已删操作重放、输入错误、内部错误。不暴露 SQL/秘密。warning `{code,field,message,device_id?:string,device_name?:string,suggestion?:string}`。

资源 ID 全是 UUID 文本，owner ID 是 i32，时间是 UTC RFC3339 字符串。可空字符串提交空白时归 null；名称 trim 后必填最多128字符，model128、remarks2000、URL2048。前后端不扩展资产版本锁，合法 PUT 最后写入生效；归属字段固定。

## DTO（JSON 使用下列原名）

```ts
type AssetScope = {owner_user_id:number; machine_id:string};
type AssetAccount = {id:number; username:string};
type AssetContextResponse = {actor:AssetAccount; can_manage_others:boolean; available:boolean};
type AssetNode = {owner_user_id:number; machine_id:string; hostname:string; alias:string;
  site_location:string|null; device_model:string|null; connection_ip:string|null;
  ip_country:string|null; ip_region:string|null; ip_city:string|null;
  is_public_server:boolean; device_count:number};
type GatewayGroup = {id:string; owner_user_id:number; machine_id:string; name:string;
  remarks:string|null; subnets:string[]; created_at:string; updated_at:string; warnings:AssetWarning[]};
type DeviceType = {id:string; owner_user_id:number; name:string; created_at:string; updated_at:string};
type AssetDevice = {id:string; owner_user_id:number; machine_id:string;
  gateway_group_id:string|null; device_type_id:string|null; name:string; model:string|null;
  overlay_ip:string; lan_ip:string|null; is_gateway_self:boolean; remarks:string|null;
  created_at:string; updated_at:string; warnings:AssetWarning[]};
type AssetService = {id:string; owner_user_id:number; machine_id:string; device_id:string;
  name:string; protocols:('tcp'|'udp')[]; port:number; remarks:string|null;
  access_url:string|null; icon:string|null; created_at:string; updated_at:string};
type Preview = {field_errors:Record<string,string>; warnings:AssetWarning[]};
```

列表返回 `{items:T[]}`，设备分页返回 `{items,total,page,page_size}`。POST/PUT/PATCH 返回记录本身（不是 item 包装），DELETE 204。Group/Device warnings 动态计算，不保存健康状态。

## Schema 与一致性

全部新表采用下列字段名供 raw SQL/SeaORM 共用，不改变现有devices含义：

- node_asset_metadata(owner_user_id,machine_id,is_public_server)，PK复合键，FK到devices(user_id,machine_id)，合法删除时cascade；它自身不算下属资产。
- asset_catalog_state(owner_user_id PK,initialized_at)：类型种子一次性标记，和种子同事务写；后续查询/初始化不得复活已删种子。
- asset_device_types(id PK,owner_user_id,name,created_at,updated_at)，UNIQUE(id,owner_user_id)，无名称唯一约束。
- asset_gateway_groups(id PK,owner_user_id,machine_id,name,remarks,created_at,updated_at)，UNIQUE(id,owner_user_id,machine_id)，node FK RESTRICT。
- asset_gateway_subnets(group_id,owner_user_id,machine_id,cidr)，PK(group_id,cidr)，composite group FK CASCADE。
- asset_devices(id PK,owner_user_id,machine_id,gateway_group_id nullable,device_type_id nullable,name,model,overlay_ip,lan_ip nullable,is_gateway_self boolean,remarks,created_at,updated_at)，UNIQUE(id,owner_user_id,machine_id)；node/group/type 作用域复合FK，node/group/type删除RESTRICT。LAN unique(owner_user_id,machine_id,lan_ip)，null可多条；partial UNIQUE(gateway_group_id) WHERE is_gateway_self=1；CHECK(self=0 OR group IS NOT NULL)。服务端统一规范IP后写入。
- asset_services(id PK,owner_user_id,machine_id,device_id,name,port,remarks,access_url,icon,created_at,updated_at)，UNIQUE(id,owner_user_id,machine_id,device_id)，device composite FK CASCADE；protocols从bindings读取。
- asset_service_bindings(service_id,owner_user_id,machine_id,device_id,protocol,port)，PK(service_id,protocol)，UNIQUE(owner_user_id,machine_id,device_id,protocol,port)，service composite FK CASCADE。port CHECK 1..65535，protocol只tcp/udp；两协议写同一事务。
- asset_operations(actor_user_id,owner_user_id,operation,request_id,payload_hash,resource_kind,resource_id,response_json,created_at)，PK(actor_user_id,owner_user_id,operation,request_id)，不随资源删除级联。request hash包含scope+父ID+规范化payload。资源已删除重放410，不回写创建。

索引覆盖owner/node、group/type筛选、created_at/id排序、device_id服务查询。强制FK不能仅靠SQLite默认；实际连接启用foreign_keys（集成owner负责确认配置实现，不运行检查）。所有写入用SQLx事务，BEGIN IMMEDIATE可参考旧Db写法；没有跨网络await的数据库事务。

组必须至少一CIDR，标准网络地址由用户手改；重复拒绝但重叠可。IP使用std::net::IpAddr解析规范化（IPv4-mapped IPv6等价策略统一转换为IPv4），CIDR用已有cidr crate，不添加依赖。匹配warning只比较同族，空LAN/直属豁免。保存必须重新校验；预览失焦/明确操作一次，不timer。

admin授权、所有父归属、固定归属、唯一约束所有写入均重新校验。节点删除与创建组/设备获得同一个CentralNetworkService::lock_mutations()；原delete_device已持锁，前置检查不再加锁。事务前锁、结束事务后释放；原删除网络等待期间保留业务锁但无数据库事务。

幂等actor+owner+operation+request_id，事务内先查已完成结果、再写业务和操作结果。相同键不同规范化payload→409；同键相同数据且资源仍存在→原响应；资源已删→410；相同资源名/IP不当作幂等键。事务失败不保留完成记录。跨后端重启保留，首期无定时清理。

## 2026-10-23 集成补充

- IPv4-mapped IPv6 设备地址与完全位于 mapped /96 内的网段统一为 IPv4 表示，例如 `::ffff:192.168.1.0/120` 对应 `192.168.1.0/24`，避免等价地址/网段重复及错误提醒。网段有主机位仍要求用户手动改正。
- 关键词字面匹配在当前节点、组和类型作用域内由 Rust 执行 Unicode 小写转换后比较，再进行后端计数与分页，避免 SQLite 原生 lower 仅支持 ASCII 的差异；当前容量预期未变成硬限制。
- 资产路由沿用全局会话层，在自身 handler 内认证并输出统一 JSON 401。其合并点位于旧 login_required 路由层之后；旧接口认证行为保持。
- 页面查询失败保留上次成功结果并明确提示；首次失败不显示成功空列表。失败重试保持当前已应用条件。新建定位使用设备行标记，多弹窗和账号/节点切换均忽略旧响应。
