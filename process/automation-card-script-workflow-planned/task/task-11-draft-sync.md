## 2026-10-27 实际交付

- `automation-api.ts` 和 `types/automation.ts` 新增 T10 草稿 API 类型、GET 列表/读取、POST 新建、PUT 带修订 CAS、DELETE 带修订删除；区分首次完整响应和网络重试的 `request_replayed` 精简回执。
- 新增 `automation-draft-sync.ts`：唯一的 `AutomationDraftWorkspace` 仍由 `AutomationCenter.vue` 持有；纯服务端工作草稿同步器按内容指纹检测变化，**防抖 + 单通道顺序 PUT**，每次接收成功修订后再提交下一次变更。单次操作 UUID + 原始 immutable body 固定，网络超时保留并在 online 事件或主动重试时使用同一个请求；幂等重放 GET 读取最新草稿并核对修订，其他页面已更新即 409 停止覆盖。
- 初次进入自动读取当前账号草稿列表；只有没有本地改动时才尝试恢复最近草稿（ID/步骤顺序完整恢复）。用户可选其他服务端草稿恢复、刷新列表、手动保存当前、冲突时另存独立工作草稿及显式删除。列表只储存摘要；敏感步骤不保存到浏览器本地持久化存储。
- `AutomationCenter.vue` 在工作台和脚本库共用同步状态条；切换账号、恢复/替换工作区或浏览器刷新时，存在未确认落库内容会提示风险。切换工作台/脚本库标签不会复制或清空草稿；网络已恢复时通过原 UUID 安全重试。
- `PhoneCard.vue`、`CardStepTimeline.vue` 以及 `ScriptLibrary.vue` 均同步显示工作草稿的准确状态；脚本库原「保存草稿」改名「保存正式脚本」，说明 **草稿自动同步 ≠ 正式脚本发布**。
- 保护：初始化时不会用服务端恢复覆盖用户已开始编辑的内容；按 owner / workspace generation 防止迟到请求覆盖新账号；脚本库打开另一份正式脚本时自动与旧工作草稿解绑；恢复草稿不会自动保存至已发布脚本的 ID。
- **联调补充**：服务端草稿新增 `script_id` / `script_revision`（均可空，必须同时设置）用于记住正在编辑的正式脚本。恢复时不丢弃这两个身份字段；正式脚本写入仍单独走 `/scripts` 的 CAS，不会被草稿同步自动覆盖。
- **已知边界**：T10 后端继续使用正式脚本完整步骤验证，未完善的 key/待填写控件等步骤无法自动保存，界面会显示未同步错误；敏感 `input_text.text` 明文值明确拒绝写草稿，必须换成参数名。用户未看到「已同步」就刷新浏览器依然可能丢失未落地变更，浏览器离开会警告但无法对浏览器崩溃/强制退出提供绝对保证。服务端版本冲突需要人工恢复/另存，不做无条件自动合并。
- **后续建议验收**：多标签页 CAS 409 / 断网重试 / 服务重启恢复 / 账号权限 / 多步骤连续录入与快速切页 / 脚本库正式保存后继续编辑。
