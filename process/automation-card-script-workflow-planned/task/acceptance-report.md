## 2. 可复核的版本及只读环境检查

在 FnOS 服务器上由授权操作者执行以下**只读**检查（不拉镜像、不安装、不重启），并把输出存入脱敏证据文件：

```sh
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
docker inspect easytier-automation-executor --format 'image={{.Config.Image}} image_id={{.Image}} started={{.State.StartedAt}} state={{.State.Status}}'
# Web 容器名按真实环境填写，避免误查其他镜像：
# docker inspect <实际 Web 容器名> --format 'image={{.Config.Image}} image_id={{.Image}} started={{.State.StartedAt}}'
```

登录自动化中心后，在**当前用户授权范围**内仅用浏览器 Network 的只读请求收集：
`GET /api/v1/automation/context`、`GET /api/v1/automation/devices?owner_user_id=<授权owner>`、
`GET /api/v1/automation/drafts?owner_user_id=<授权owner>`；
进入实际执行历史后记录相应 `GET /api/v1/automation/runs/{run_id}` 的状态。只保存必要状态字段，脱敏 IP、cookie、Bearer、密码、配对码及输入文本。**不要**为采证补发 `POST /runs`、`/prepare` 或控制 websocket 消息。

每个步骤固定证据标识 `QA-T18-<AC编号>-<日期>-<序号>`，记录以下内容：机型/浏览器/已部署 SHA/Digest、操作者、时间、设备 ID 的脱敏标识、测试动作、预期与实际、截图/日志路径、对应会话 ID 或 `run_id + device_id + step_id`，结果为 `通过/失败/阻塞/未执行` 中恰好一个。

## 3. 12 项验收操作卡

### AC-01 · 原画面进入和退出拾取

1. A 机授权 ADB 已连接，工作台卡片打开实时画面，记录视频是否可见。
2. 在该卡片点搜索/拾取图标；记录 `off → preparing → on` 的实际状态以及初始化失败时的错误态。
3. 原画面上点退出拾取，确认进入 `off` 后仍然显示原视频、恢复正常手控。重复开关两次。

**通过标准：** 拾取状态只作用于当前卡片；视频不因进入/退出拾取被关闭；准备失败可退回安全状态。**证据：** 同一会话 ID、四态画面、出入拾取时视频状态和浏览器 Console 截图。

### AC-02 · 鼠标右键/触屏长按与真实有效像素

1. A 机拾取 `on` 时，桌面在视频中央右键，观察快捷菜单，记录坐标和实际屏幕相应控件；点击视频黑边或控件外侧，确认不误取屏幕坐标。
2. 点击菜单外部后仍可在原视频继续右键；禁用拾取后检查原有手控/菜单行为。
3. 在 Android 触屏浏览器上用长按替代右键；手机旋转及浏览器全屏后重复，检查弹层不被裁切。

**通过标准：** 右键只触发拾取菜单，不触发 Android tap；坐标基于视频有效区域，触屏替代一致。**证据：** 桌面右键和触屏长按录屏、无 Android 控制动作日志、全屏前后截图。

### AC-03 · 真实控件树/候选/属性

1. 在 A 机测试页面选择唯一控件，检查选中节点的父子树、矩形 bounds、可点击性、资源 ID/描述和候选唯一性。
2. 更换页面使前一控件树过期；测试两个同名控件、受密码保护的字段、树截断或无候选情况。
3. 编辑动作、超时、输入参数；选择合法唯一定位条件后才确认。

**通过标准：** 不能用旧树或非唯一候选无提示保存；密码字段不能泄露明文；不要求强行生成 XPath 索引。**证据：** 树采集时间、目标指纹、候选数量、唯一性标记和无隐私的属性截图。

### AC-04 · 第一条确认后自动回卡片

1. A 机拾取模式选择并确认第一个测试控件。
2. 检查属性配置对话框自动关闭、仍在原 A 机卡片、拾取开关仍然 `on`，步骤列表增加**恰好一条**。
3. 快速连续点击确认或模拟迟到的同一提交响应，检查无重复步骤。

**通过标准：** 恰好一个新的 `step_id`；不切换脚本库、视频无中断。**证据：** 确认前后列表和同一 `step_id`。

### AC-05 · 连续四步录入

1. 重复右键并确认四个**不会导致实际业务副作用**的测试动作，例如只读控件检查或等待条件。
2. 不主动进入脚本库，检查 1→2→3→4 的序号、顺序及四个不同 `step_id`。
3. 关闭一个卡片的视频，再次打开同手机画面，确认四步仍然存在。

**通过标准：** 单份共享草稿只追加四步；确认后可继续在原视频拾取。**证据：** 四步列表、草稿 ID/revision、卡片重新打开后的截图。

### AC-06 · 卡片脚本与保存状态

1. 折叠及展开步骤条，检查名称、当前草稿和步骤类型/序号；不应遮挡主要手机画面。
2. 修改一条步骤，观察 `未保存/保存中/已保存或未同步` 提示；用 Network 核实实际保存状态与响应 revision。
3. 故意断开浏览器网络，检查不能把未收到响应的草稿显示为“已保存”。

**通过标准：** 服务器尚未确认时状态不冒充已同步；视频操作仍可用。**证据：** 前后 UI 与对应草稿 GET/写请求状态（脱敏）。

### AC-07 · 旧步骤编辑与重新拾取

1. 点击第 2 步，修改非目标参数并确认，核查数组长度不变且 `step_id` 不变。
2. 对第 2 步使用“重新拾取”，下一次右键只更新目标定位；保留动作类型、其它参数和条件分支。
3. 取消一次编辑和一次重新拾取，验证没有新增步骤，也没有覆盖旧步骤。

**通过标准：** 只改变经确认字段；同一 `step_id`、原序号，其他步骤完全不变。**证据：** 修改前后草稿 JSON 的脱敏 diff、原步骤 ID。

### AC-08 · 定位演示非真实执行

1. 对某个带唯一 selector 的已录步骤点击“定位演示”，观察只读树刷新、只高亮一个目标。
2. 切换到没有目标、两个匹配目标、控件树过期、旋转/分辨率变化、XPath 特殊情况。
3. 对照浏览器 Network 和执行历史，确定没有为定位演示提交 `POST /runs`，也没有 Android tap/input 指令。

**通过标准：** 只读高亮与真正试跑视觉上可区分；未匹配/歧义/旧树给明确提示。**证据：** 视频高亮截图、Network 只读请求摘要、运行记录前后数量。

### AC-09 · 单步试跑自动准备及资源移交

1. 在 A 机卡片选择一个安全测试步骤，开启单步试跑，记录 `设备授权 → ADB → 需要时准备 UiAutomator2 → 只读跨机核验 → 确认实际执行`。
2. 分别制造 ADB 离线、UiAutomator2 未就绪、执行器不可达及无线配对未授权场景，确认可理解的失败阶段，**不能自动配对**。
3. 在 A 机打开本页预览时试跑，应仅释放本页实际持有的会话；第二浏览器先占用 A 机时应拒绝释放其预览。
4. 只有明确点“确认执行此步骤”后才能创建运行记录；副作用步骤需要二次确认。

**通过标准：** 显示真实进度/超时/失败；后台独占有效；不存在准备中就执行动作。**证据：** ADB/组件状态、会话 ID、`run_id`、准备日志及 UI 阶段序列。

### AC-10 · 失败→原步骤修复→新的手动再验证

1. 在专用测试应用中构造一个必然失败的只读控件断言，完成单步试跑；记录旧 `run_id`、设备、`step_id`、失败原因。
2. 从试跑面板及执行历史分别点修复，确认定位到原手机卡片的同一草稿步骤，修改 selector 或重新拾取。
3. 明确发起**新**单步试跑，确认新 `run_id` 与旧不同，旧的失败历史快照不变。
4. 单独测试 `outcome_unknown`：未核对手机现场时不能自动重放或绕过确认；执行器清理未确认时禁止再试跑。

**通过标准：** 修复的是工作草稿，不是历史记录；实际副作用不能被重复请求误触发。**证据：** 前后两个 `run_id` 和同一 `step_id`、截图、旧运行 JSON 只读对比。

### AC-11 · 草稿保存/重开/跨另一 OEM

1. 命名 A 机上完成的共享草稿，确认服务端保存 revision；关掉投屏、切到其他 Tab，再回来、刷新并恢复草稿。
2. 在授权 B 机打开同一草稿，先用 selector 操作做只读匹配，再换含 A 机参考屏幕尺寸的坐标步骤进行试跑前复核。
3. 当 B 机宽高或方向不一致时，预期明确**阻断**；相同尺寸但布局风险时要求人工确认，不能静默缩放。
4. 用第二个 owner 账号尝试访问前 owner 草稿，确认跨账号无内容泄露。

**通过标准：** 跨机复用不复制丢步；输入参数不在服务端草稿存储；绑定指纹/坐标安全。**证据：** 两设备分辨率、授权 owner、revision 与兼容性问题列表。

### AC-12 · 断开/切页/放弃编辑/竞争时不丢数据

1. 四步草稿保存成功后断开 ADB/关闭投屏、切内部 Tab，确认步骤仍在共享草稿中。
2. 修改一个本地参数但不确认，触发路由离开及浏览器刷新，检查脏编辑警告，取消离开不丢失数据。
3. 让草稿写请求超时/断网，检查“未同步”；联网后按原请求编号安全重试，不生成重复草稿。
4. 两浏览器编辑同一服务器草稿 revision：先在浏览器 A 保存，再在 B 保存旧 revision；B 必须提示 CAS 冲突，不能覆盖 A。
5. 主动放弃局部参数编辑后，已确认并服务端持久化的四个步骤仍存在。

**通过标准：** 已确认数据不会因断线和导航消失；未确认的本地数据得到明确风险警告，不说“已保存”。**证据：** 两浏览器的 revision、409 conflict 网络响应、恢复结果，禁止录制 token。
