# P09 · 脚本新建、选中、克隆与 CAS 防丢失

> **状态：待开发**｜**FINAL V3 计划**｜**目标分支：** `feat/automation-center`｜**产品主合同：** `../require/require-05-final-card-script-workflow.md`。

## 业务目标
用原 Script API 与共享 Draft 工作区，在浮窗窄下拉提供已确认的新建、选中加载、克隆改名与编辑保护。

## 前置条件与关联任务
- 前置：P07；UI 浮窗依赖 P08。
- 开发任务：[T25](../task/task-25-empty-script-backend.md)、[T26](../task/task-26-script-selector.md)、[T27](../task/task-27-script-clone.md)、[T28](../task/task-28-draft-switch-cas.md)。

## 交付要求
1. 下拉触发框位于脚本名左侧紧凑区，不遮挡右侧 x/100 步与折叠图标；展开首行就是“输入名称 + 新建”，不重复展示当前名称标题。
2. 每个已保存脚本行左侧选中载入，当前脚本由 ✓ 标记；右侧克隆独立操作，弹可拖动改名窗后确认才产生新脚本 ID。
3. 空脚本保存后立即可选、0 步不可执行；需要适配 Rust validation::steps 现在强制 1–100 的业务限制及 ScriptLibrary 保存校验，不误改 run 校验。
4. 脚本克隆完整复制已保存脚本动作/定位/分支结构但生成独立身份；不复制历史、运行参数值和授权；后端回执确认后自动选择。
5. 切换/新建/克隆不能覆盖未同步草稿或污染已发布版本；网络未知、修订冲突、跨浏览器 stale 更新失败回退原工作区。

## 可验收判据
- [ ] 0 步创建真实服务端记录并进入列表，点击后显示 0/100；空脚本不能运行。
- [ ] 克隆源脚本前的改名确认、后生成独立 ID/revision；原脚本和历史不改变。
- [ ] 脚本切换原子化：名称、步骤、修订、步数一致，无“名字新/步骤旧”半状态。

## 边界与风险
服务端脚本校验明确拒绝 0 步，必须与空脚本可创建和空脚本不可执行的两个校验层分开；列表需要保证同 owner 授权。

## 禁止提前声称完成
当前仅完成需求与任务拆分；无新增业务功能验收证据时状态必须维持“待开发/待联调”，不把文件创建计作交付。
