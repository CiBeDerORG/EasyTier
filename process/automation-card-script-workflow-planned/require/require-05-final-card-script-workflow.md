# FINAL · EasyTier 自动化中心最终产品需求 V3.0

> 日期：2026-10-27　|　分支：`feat/automation-center`　|　状态：**产品需求已更新，新增功能待开发、待实机验收**  
> **最高优先级要求：所有自动化操作全部基于“自动化中心 → 手机卡片列表”中的该手机原实时画面。** 不允许自动化操作时切到另一套视频、另开一个手机画面、为了编辑跳走，也不允许后台另造一个 WebRTC 预览。  
> 本文是唯一 FINAL 产品需求主入口；`require-04-single-screen-observable-trial.md` 为观看/写锁技术设计参考，`require-01-acceptance.md` 原 AC01～AC12 保留。本文件 V3 **取代旧版 V2 的“红框内嵌脚本面板”布局**，但保留其下拉、克隆、全步骤删除及执行语义。

## 1. 最终产品原则（不可降级）

1. **唯一真实画面：** 唯一操作对象是自动化中心手机列表里该卡片已有的 `PhoneCard.vue` 原主 `<video>` 及其 WebRTC `MediaStream`。脚本选择、控件拾取、步骤编辑、定位演示、单步真实执行、整个脚本执行和结果观察，都必须基于这个画面。允许在其上叠加可移动窗口，但**窗口内绝不放第二个手机视频播放器**。
2. **浮窗即工作区：** 原嵌在卡片下方的“自动化草稿 + 脚本步骤”工作区调整为**可拖拽的“自动化脚本”悬浮面板**，可由手机卡片视频上的悬浮菜单图标打开或关闭。原位置不再展示第二套完整脚本编辑模块；不重复渲染步骤列表。
3. **所有编辑也在浮窗里：** 步骤编辑、克隆改名、脚本新建校验、删除条件块确认、参数输入、只读定位属性与必要运行结果均采用**同一套悬浮窗口/子悬浮窗口机制**，不打开另一个遮挡/替换手机视频的页面。子窗可以前置，不得离开原视频工作上下文。
4. **旧页面保持原样：** 除原脚本模块迁移到浮窗、悬浮 icon 位置调整及其必须的布局接线外，手机列表、卡片宽高、视频比例、清晰度/码率、其它功能按钮、脚本服务端数据和执行历史均不做无关改动。
5. **全屏完整可用：** 全屏时原视频仍是相同主媒体会话；悬浮菜单、脚本主浮窗、子编辑浮窗、右键拾取/定位高亮、单步及整套执行按钮、滚动/输入/拖拽都应可见可操作。退出全屏不丢已编辑/已保存步骤。
6. **真实动作的安全不降低：** 画面允许只读观看，动作操作权仍互斥；后台执行/准备不应主动关闭原视频。用户主动点 ▶ 不等于可绕过权限、控件唯一性、坐标尺寸、错误后幂等或未知结果保护。

## 2. 悬浮工具栏布局：自动化替换唤醒位置

### 2.1 原有组件

现有 `PhoneCard.vue` 在视频内有可拖动的圆形悬浮主按钮（main orb），展开后有 `input-actions`、`side-actions`、`nav-actions` 三组操作。原 `side-actions` 含关闭投屏、全屏、**唤醒（power-off 图标）**、录制。视频本身由 `phone-screen` 元素进入浏览器全屏，浮动按钮是其内部子元素。

### 2.2 最终排列合同

- 在**原“唤醒”按钮所在位置**放置新的 **“自动化” icon**（建议 `pi pi-bolt` 或明确的脚本图标，必须有 tooltip / aria-label `自动化脚本`）。
- **原“唤醒”按钮上移一格**，保持原有唤醒手机功能、可用/不可用状态与既有安全门禁；不要把唤醒删除或改为执行自动化。
- 关闭、全屏、录制、返回、主页、最近任务、文字输入、解锁等原有按钮仍存在、原功能不变；为了容纳唤醒上移而调整相邻浮动按钮位置时，不能遮挡手机视频或超出屏幕。
- 自动化图标是**开关按钮**：第一次点击打开当前手机的脚本主浮窗；再次点击关闭。打开时 icon 给出激活态；也可以通过浮窗右上角 × 关闭。关闭仅是隐藏 UI，**不删除草稿、不停止正在执行的脚本、不关闭视频会话**。
- 自动化 icon 不必依赖手动触控 `manualAllowed` 才能打开：运行中手控可能禁止，但脚本状态仍要可查看；授权失效时禁止执行操作，仅显示适当的错误/状态。
- 这是**每张手机卡片自己的浮动按钮**；某卡片自动化浮窗内点单步 ▶，目标始终是这一台手机，不能误操作别的手机。

### 2.3 浮动菜单开合和层级

- 悬浮主按钮仍支持现有位置拖动与左右停靠；新增自动化菜单项不改变“短按展开/收起”和停靠逻辑。
- 打开脚本主浮窗后，即使悬浮菜单按照原定时机制自动收起，**脚本浮窗也不得随之消失**；浮窗的打开/关闭有独立状态。
- 脚本/编辑/定位浮窗与菜单拥有明确的层级顺序，不会被 dismiss 遮罩误关闭；除编辑器输入区外，视频的有效像素映射、拾取和高亮可照常工作。
- 同一账号多个手机卡片可以各有一个显示入口，但**正式脚本数据与当前工作草稿是共享工作区**；不同手机的浮窗不能各自写一份互相冲突的脚本。优先采用同一页面仅一个当前激活“编辑浮窗”，切换手机时保留草稿并重新绑定单步目标；不能让浮窗落在非目标手机却向另一台手机发动作。

## 3. 自动化主浮窗设计

### 3.1 浮窗外观与位置

```text
自动化中心 / 手机卡片 A 的同一个实时视频
┌──────────────────────────────────────────────┐
│  原手机画面（同一个 HTMLVideoElement）        │
│                                [悬浮按钮组]  │
│                                [自动化 ●]    │
│      ┌── 自动化脚本 ─────────────── [×] ┐    │
│      │ [智能家居巡检 ▼] [1/100步 ⌃]      │    │
│      │  草稿已同步       [▶ 运行全流程]  │    │
│      │  ① 点击 · 文字定位  [▶][✎][🗑]   │    │
│      │  ② 等待 · ID定位    [▶][✎][🗑]   │    │
│      └────────────────────────────────┘    │
│        （面板标题栏可拖动，视频继续播放）      │
└──────────────────────────────────────────────┘
```

- 主浮窗为非模态、可移动、可在当前浏览器视口/全屏边界内拖动的窗口；**拖动手柄仅为标题栏**，内容区点选、滚动、文本输入、步骤按钮不能误拖。
- 默认放在不遮挡手机核心区域和悬浮工具栏的位置；允许用户拖到另一边或合理的位置，不能拖到完全看不见的边界外；窗口内容过多时**内部纵向滚动**，不使手机卡片和实时视频变形。
- 非全屏：允许浮窗在卡片附近浮于其上方，尽量不压住右侧计数或其它工作台内容；窗口坐标与卡片/视口边界关联。
- 进入全屏：窗口仍可见、可拖、可点击、可滚动，可在**当前全屏 video surface 内**呈现，不因 `z-index` 或 PrimeVue 默认 `appendTo=body` 被浏览器 Fullscreen top layer 遮挡；不能为了显示它退出全屏。
- 退出全屏：映射/约束位置到非全屏可见区，不闪到屏外；维持展开状态、脚本选中、草稿与正在编辑的数据。窗口被视频容器销毁时妥善处理组件生命周期，不关闭仍在执行的任务。
- 浮窗开闭及拖动本身**不触发手机 tap / ADB 命令**；拖窗时 pointer event 被浮窗消费，原视频不能误收触控。移动端触屏也须兼容。
- 浮窗关闭不等于放弃编辑：有未保存/未确认参数时保留工作状态并标未同步；切账号、正式放弃才按已有草稿保护处理。位置存储如要实现，只允许保存不敏感坐标/尺寸，不保存脚本、selector 或明文参数。

### 3.2 内部编辑弹窗全部浮窗化

- 在主浮窗点击 **✎ 编辑步骤**，弹出独立可拖动的子浮窗；可以压在主窗上，但原手机视频依然能看到，至少应允许拖开查看目标。
- 点击 **克隆**，弹出“克隆脚本”子浮窗，用户修改名称并点击确认才复制；点击取消不创建记录。
- 新建脚本仍在脚本下拉**第一行输入并创建**，需要校验错误时就地展示；如果需说明/高级设置，用浮动子窗口，不切其他 Tab。
- 删除普通步骤可直接进行并提供撤销；删除条件节点时，独立浮动确认窗列明影响范围。
- 只读定位候选/UiAutomator 控件树与动作参数配置也使用同一视频上的浮窗/子浮窗，**不另放一个缩小版视频**。选择树节点应直接高亮原卡片视频相应矩形。
- 单步试跑时状态与修复入口在主窗步骤行或运行子浮窗，真实画面一直可见。子窗有明确标题、关闭/取消/确认行为、层级和焦点处理；失去焦点不应提交或取消手机动作。
- 小屏或全屏下采用受视口限制的可滚动浮窗，**不得让子窗实际不可见、不能输入或保存**。

### 3.3 脚本选择下拉（保留 V2 最终确认）

收起：左侧 `智能家居巡检 ▼`，右侧 `1/100 步 ⌃` 始终可见。**宽度保持用户原红框里左侧名称所占的紧凑比例**，不可撑满主浮窗或盖住右侧步数。

展开时，弹层**直接从名称处展开**；第一行是 `[输入新自动化名称][新建]`，下面按授权列出现存脚本：

```text
[智能家居巡检 ▼]            [1/100步 ⌃]
┌──────────────────────────────┐
│ [输入自动化名称…]     [新建]  │
│ ✓ 智能家居巡检        [克隆]  │
│   回家场景            [克隆]  │
│   设备检查            [克隆]  │
└──────────────────────────────┘
```

- 不增加重复的“当前：智能家居巡检”标题行，**列表中的 ✓ 是唯一的选中显示**。
- 选中某行只加载其已保存的脚本步骤；原未同步草稿要提示保存/取消，不能静默覆盖。
- 第一行新建成功后生成**新的空白自动化记录/身份**并立即选中；保存回执未确认不能假报创建成功；名称 trim/空值/重名校验。
- 克隆对话在**子浮窗**打开，默认“原名称 - 副本”，必须允许修改并由用户确认；成功后复制该条脚本**服务端已保存**的步骤生成**全新正式脚本 ID/revision**，自动选中加载，原脚本不变，不复制执行历史或秘密参数；失败不得残留半成品。
- 关闭下拉、脚本切换/克隆均不影响原视频，脚本同步 CAS 继续有效。

### 3.4 所有步骤可删、可编辑

- 当前脚本明细**每一行**（含普通点击、输入、等待、断言、截图、条件/分支子步骤）固定 **`▶` `✎` `🗑`** 操作位，窄面板中也必须可触达；条件节点不能单步执行时只禁用 ▶，不隐藏 🗑。
- 普通步骤删除当前一条并提供撤销；条件块删除须显示范围和影响步骤数量，确认后安全删除；删掉分支最后一步导致结构不合法时提供“删除所属条件块”操作。
- 删除后立即更新步骤序号和 `x/100 步`，其余 `step_id` 不变；服务端草稿使用 CAS 修订/冲突保护，历史运行快照不受影响。
- 编辑/重拾/重新定位只修改确认过的字段，保持原 `step_id`；在运行中的脚本不可篡改已冻结的执行快照。

## 4. 自动化执行：同画面原则贯穿始终

### 4.1 单步绿色 ▶

1. 在手机卡片 A 的自动化浮窗点击第 N 步 ▶，**只在 A 手机**自动准备并执行一次；不换页面、不弹第二视频、不关闭原画面。
2. 直接进入 `准备中 → 执行中 → 动作已发送/断言通过/失败/结果未知`，步骤行反馈，运行 ID 与 `device_id+step_id+request_id` 对齐。
3. 不再出现普遍性的“需要确认定位风险”大卡/额外勾选，也不需要重复点“自动准备试跑”；不过输入参数缺失、真正敏感动作、权限错误、无唯一目标、坐标尺寸不符时必须提示/阻断，不能绕过校验。
4. 自动准备、UiAutomator2 控件初始化、步骤执行全过程中**原 WebRTC 视频仍在播放并展示实际效果**。脚本临时独占操作权，用户只能观看，不能借 API 偷发手控；结束并确认清理后再恢复。
5. 网络超时/浏览器关闭/结果未知不自动再次执行，已有 UUID 幂等保护继续有效；执行结果和修复入口可以在同一悬浮窗口打开。

### 4.2 全局 ▶ 运行整个流程

- 按钮位于自动化脚本主浮窗中（不另开一个全局脚本页面）；用户点击后，对工作台**明确勾选、已授权**的手机执行当前脚本所有步骤。**本浮窗所处的手机不自动等于全局目标全集**。
- 冻结脚本 revision、步骤快照和目标设备列表；不同手机可并行、每台手机内依次执行，失败设备互不拖累。弹出浮动运行状态面板，按设备/步骤查看结果。
- 在手机卡片 A 上看 A 的原实时视频，在 B 上看 B 的原实时视频；**每台设备复用各自卡片原媒体，禁止为全局执行另外拉取一条预览**；全屏查看哪个卡片就显示哪个设备的运行画面/状态。
- 复用已有 `runs` API、CAS 与 executor Journal；同设备已有 manual/script/prepare 写锁时必须等待/拒绝，不能抢其他浏览器的控制权。旧“脚本库独立投屏预览”不能被新的浮窗路径调用。
- 同步草稿与正式发布状态保持不同；执行参数只在运行内存，不落盘到脚本或浮窗位置配置。

### 4.3 只读观看和独占动作（技术架构不可省略）

现状：`PhoneCard.vue` 的真实 video 位于 `phone-screen`；`Journal.claim()` 是 EasyTier 自研手控/prepare/script 独占规则。当前 `CardTrialPanel.prepare()` 还会主动调用 `releaseOwnedTrialPreviews()` 关闭会话；只增加悬浮窗**不能**满足不中断视频目标。

最终需设计:
- `video_lease`：可持续观看唯一原视频，绑定 owner/device/session/target fingerprint，拥有只读能力。
- `action_lease`：同一手机最多一个写入者，在 manual、prepare、script 之间原子交接并安全清理；操作被锁时前端+Rust+Executor 层都须拒绝 tap/input/key/unlock。
- 全屏/悬浮窗只改变 UI，不改变实际视频 lease 或操作 lease；窗口关闭不释放正在运行的执行写锁，也不假报恢复控制权。
- `cleanup_pending/outcome_unknown` 期间仍允许按授权只读看屏幕，但禁止再次发手机动作；断网不自动重新配对/重发动作。

**实施底线：** 不能单纯删掉 `Journal.claim()`、跳过 `active_session/run_occupied` 或绕过预览回收检查；需要 Rust 与 Executor 的双层授权/互斥调整和真机证明。

### 5.1 浮窗架构及全屏技术约束

1. 建议独立 `AutomationFloatingPanel`（主窗）+ `AutomationFloatingEditor`（编辑/克隆/条件确认/参数）+ `useFloatingLayer`（位置/层级/拖动/边界/焦点），仍从**唯一** `draftWorkspace` 和已有脚本 API 读取。
2. 全屏目前只把 `PhoneCard.vue::screen` 放进 Fullscreen top layer；**所有自动化主/子浮窗都必须在该 fullscreen element 的层级内**，或通过受控 Teleport 切到该元素；不能默认为 `body`，也不能复制新的 video。
3. 非全屏与全屏需共用窗口业务状态、不同的安全定位约束；`fullscreenchange` 时更新容器几何及 drag clamp，不能关闭运行任务或清空编辑。
4. 悬浮按钮原有 `anchorFraction/dock` 和 6 秒菜单自动收起逻辑保留；主浮窗不受 `menuOpen` 状态控制。拖主按钮、拖编辑窗、视频手控 pointer 需要分离捕获机制。
5. 面板要可键盘操作，Escape 关闭最上层可关闭的浮窗但不停止后台动作；点击移动条不触发脚本保存；触控拖动不能变成手机滑动。
6. 宽度遵从原卡片/全屏视口可用空间，长脚本名称截断；过多步骤内部滚动。合理弹层 z-index：视频 < 定位高亮 < 可操作主浮窗 < 子编辑/确认窗 < 危险提示，不出现控件被遮挡但继续接收点击。
7. 若 Android 媒体源确实断开，UI 必须显示视频中断和原任务真实状态，不能假称原画面持续，也不能为了强制恢复画面自动发一次 Android 动作。

| FF-01 | 原自动化中心手机卡片主 video 是**唯一真实画面**；打开任何自动化窗口没有另一条投屏、第二播放器或独立浏览器预览。 |

## 8. 状态/禁止事项

- 本轮**只整理需求和任务**；没有把“新浮窗、全部同视频、全屏兼容”说成已实现。
- 不允许为了悬浮 UI 复制/打开第二套手机画面，或切到另一个脚本库独立预览。
- 不允许为了浮窗全屏显示而强制退出全屏、把 modal 挂 `body`、或者让不可见编辑窗吞掉输入。
- 不允许为了执行画面不断而删独占控制锁、绕过授权、自动配对无线 ADB 或自动重试 `outcome_unknown` 动作。
- 不在脚本运行后把另一个设备上保存的脚本私自同步为本设备独立副本。正式脚本和当前草稿共享，同一手机执行上下文独立。
- 原 AC01～AC12 与 V2 已确认的新建/选择/克隆/删除要求继续有效，V3 增补浮窗及全屏新范围。
