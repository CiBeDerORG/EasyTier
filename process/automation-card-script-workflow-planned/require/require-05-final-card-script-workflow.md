# 自动化中心最终交互需求：卡片一键执行、脚本切换/克隆、全局运行与步骤删除
**版本**：产品方案 V1.0（2026-10-27）　**状态**：需求确认稿，待开发　**分支**：`feat/automation-center`  
**相关文档**：`require-01-acceptance.md`（原 12 项验收不变）、`require-04-single-screen-observable-trial.md`（唯一实时画面、无重复定位勾选、观看/操作权限分离）。

## 一、业务目标与决策

原手机卡片成为自动化中心的**唯一日常操作工作台**：
1. **单步**：点击卡片步骤行的绿色 ▶，不再跳单步试跑弹窗；自动在**当前这张卡片绑定的手机**上执行该步，视频不断、状态就地反馈。
2. **整套**：自动化草稿/当前脚本栏有全局“运行整个脚本”按钮；使用**当前选中的脚本版本**在工作台**已勾选且授权的手机**上并行发起，执行历史按每台手机和每步呈现。
3. **多脚本**：原“自动化草稿”标题区域替换为**脚本下拉选择器**。第一行固定输入“新建脚本名称”并可创建；列表内每个已有脚本提供**选中/打开**和**克隆副本**两种独立操作。
4. **步骤**：卡片下方当前脚本的步骤列表新增删除入口；普通步骤可以就地删除，条件分支则使用已有安全删除整个条件块规则；编辑、重拾和 ▶ 原有入口保留。
5. **唯一实时画面**：属性和控件树停靠侧边，复用 `PhoneCard` 原视频；自动准备和执行期间仍可观看动作，不重建视频会话；动作手控由脚本独占。

这些是本期最终业务方向。不得把代码级提交等同于完成，必须补充真实设备验收。

## 二、唯一共享工作区与数据模型

```text
账号 owner
├─ 脚本清单 Script {script_id, revision, name, steps, ...}  —— 正式持久化
├─ 当前工作草稿 Draft {draft_id, revision, script_id?, script_revision?, steps...}
│   └─ 当前打开的 Script ID（有正式脚本时）或“新建未发布”身份
└─ 手机卡片 A/B/C...
    ├─ 各自 MediaStream / 观看状态 / 操作写锁 / 单步试跑状态
    └─ **读取同一份当前草稿的步骤**，不复制 per-device 脚本实体
```

- 脚本选择器选择的是**本账号当前工作脚本**，改变所有卡片展示的当前脚本；**不会**让每台手机持有不同脚本副本。
- 下拉选中正式脚本时，使用现有 Script API 读回最新 `script_id+revision` 并载入同一工作区，保留所有步骤与顺序。不可只按名称判断唯一性。
- 未保存编辑自动进入服务端草稿（原有 CAS）；**切换脚本不能静默丢弃当前已修改内容**：已同步先切换，未同步/冲突提示“保存当前、另存副本、继续留在此页”；明确放弃时才能覆盖本地编辑。
- “草稿同步成功”与“正式脚本已发布”是两种独立状态；允许在卡片新建/编辑，但执行用的步骤必须形成提交时不可变快照。
- 断开 ADB、停投屏、切工作台 Tab、设备临时下线不删除已确认并服务端持久化的步骤；执行历史保持不可修改。

│ ├────────────────────────────────────┤ └───────────────────────────────────┘ │

**全局按钮的位置与语义**：`▶ 运行全流程` 在共享的“当前脚本/自动化草稿”栏只显示一份（可以位于工作台上方的全局草稿栏，卡片内显示只读快捷入口），不能每张卡片都各自出现一个容易误会作用范围的“全局运行”按钮。**只操作工作台勾选的手机，不默认运行全部授权手机**。0 台勾选时按钮禁用并提示先选择目标手机；运行前显示准确的设备范围与步骤数量。

### 交互 1：点击当前卡片内的单步 ▶
1. 用户在**华为 mate30 卡片**第 1 步点击 ▶；这是一次明确的真实执行意图，**无需再点“自动准备”或“确认执行此步骤”，也不弹重复“定位风险确认”复选框**。
2. 同一条步骤进入 `排队中→自动准备→执行中→动作已发送/检查通过/失败/结果未知`；开始后该行 ▶ 禁用并显示进度；原视频继续播放。
3. 后台自动检查：手机与 owner 授权、fingerprint/绑定、ADB 连接、UIA 组件、快照新鲜度、selector 唯一性、坐标宽高严格一致。自动连接仅适用于**已授权** ADB；不自动进行无线配对。
4. 参数化输入如果本次缺少运行参数，仅就地展开安全的**参数输入行**，收集后继续原操作；不得持久化输入值。对系统不可逆、敏感/外部副作用动作实行明确的针对性保护（例如拒绝或专项确认），**不恢复普遍性的定位风险勾选**。
5. 校验失败、控件不唯一、尺寸不兼容等**硬错误直接阻断**，本行提示“刷新控件树/重新拾取/修复定位”；不允许用户通过普通勾选跳过。
6. 完成后显示状态和用时，关联 `run_id/device_id/step_id/request_id`；失败时本行“修复”和“再次试跑”，**后者是用户主动新发起**，未知结果绝不自动重复动作。
7. 若手动控制/其他运行持有操作锁，等待、明确拒绝或超时取消，不关闭别人的会话或强行抢占。脚本执行与原视频观看分权后，准备及运行中的原画面必须持续展示；不能用关闭原媒体会话来解决写锁冲突。
8. `if/else` 结构节点、上下文不完整步骤不能当独立 Android 动作执行，▶ 不可用且解释原因；整套流程仍支持这些条件节点。

### 交互 2：全局 ▶ 运行全流程
1. 用户在草稿栏选定脚本，并在工作台勾选 A、B（可单选）；点击全局 ▶。
2. 系统冻结脚本的 `script_id` / `draft_id`、revision 和步骤快照；按当前勾选设备列表申请运行，不得因之后改编辑器内容修改在途 run。
3. 自动预检每台设备，失败设备单独标记，不拖垮其他已授权设备；采用**按设备并发、设备内按步骤顺序**，进度展示“总设备数/排队/运行/完成/失败”，可按设备查看单步结果。
4. 运行策略默认**允许从当前已同步工作草稿发起**，与“保存/发布为正式脚本”分开；未同步且没有被服务端确认的草稿不可冒充已发布，可选显式执行当前不可变快照并标记“草稿运行”，但不能自动覆盖正式脚本。
5. 同一手机已有单步试跑/完整脚本/手控写锁，设备级排他必须阻断二次真实动作；全局执行不抢别的浏览器视频。停止某设备只停该设备；停止全部需用户明确操作。
6. 默认并发受用户在 EasyTier 设置中配置的推荐值约束，并提供实际容量/队列进度；用户此前要求**不要简单写死最大设备数量**，需核查并移除现有 UI 的固定 20 台上限与相应服务端限制，必要时采用分批调度、设备级队列及实际执行器硬容量校验。
7. 仍按服务端 `request_id` 幂等处理，网络未知不自动重复提交；历史可按 run、device、step 追溯。

### 交互 3：脚本下拉第一行新建
1. 展开选择器，第一行固定为 `[请输入新脚本名称][＋新建]`，支持回车创建；名称不能为空，去除首尾空格，重复名称应提示并允许用户改名，内部以新 UUID 唯一标识。
2. 新建是**空白、未发布工作草稿**；新 `draft_id`、新身份，无历史步骤/源脚本 `editingId`，创建后自动成为当前选中项。
3. 如果旧脚本有未同步编辑，先按切换保护处理，不可覆盖旧数据；新建不自动复制旧脚本步骤。允许后续右键拾取追加。
4. 新脚本至少在服务端保存成功后进入下拉持久列表；失败显示未同步，不冒充已创建成功。

### 交互 4：下拉选中与克隆
- **选中/打开**：读取选中脚本最新受权 revision，替换当前共享工作草稿；所有卡片的步骤列表同步切换。若卡片正在执行，**运行快照不变**，但编辑区/切换应禁止干扰执行中的当前脚本；确认并等运行状态稳定后再切换。
- **克隆副本**：选中清单里任意一条，点击其独立的 `克隆副本` 操作（也允许克隆当前脚本）。新名称默认 `原名称 · 副本`，名称冲突自动递增；使用**新 script/draft ID、新 revision**，按需重建 step ID/层级引用，绝不复用原源脚本的 CAS revision；成功后切换到该副本。
- 原脚本保持不变，克隆后的步骤内容/selector 可复制，但**不复制运行时参数值、密码、历史执行记录、设备操作锁**。跨不同手机使用克隆脚本仍需重新匹配设备与坐标；不能靠克隆绕过检查。
- 克隆和“另存新草稿”是同方向操作，但必须明确选择**克隆正式保存版本**还是**复制当前未发布改动**：下拉单条的 `克隆副本` 默认复制该条**服务端已保存**版本；复制当前编辑内容使用独立 `另存当前副本`，避免来源歧义。
- 下拉列表可按名称搜索、显示修订和当前/未同步标识。删除整个脚本属于单独“管理”操作并需明确确认，**与删除某个步骤不是同一动作**。

### 交互 5：步骤行删除
1. 每个普通步骤末尾增加 `🗑`，与 ▶、编辑并列；点删除立即从当前工作区移除，余下步骤重排，`step_id` 不变、序号自动重算。
2. 删除通过共享 draft 的服务器 CAS 持久化，显示保存中/已同步/冲突；在服务端回执前不能说删除已保存。允许短时“撤销删除”，撤销同样经 CAS，失败提示冲突而不是偷偷覆盖。
3. 删除 `if_gone`/ `if_else` 条件节点使用已存在的 `removeFlowBlock` 安全逻辑：需向用户列出将连带删除的条件范围并确认。禁止单独删除导致 Then/Else 悬挂；最后一个分支步骤若会破坏结构则禁止且给出替代路径。
4. 删除当前正在试跑的步骤时不能修改已提交的运行快照；执行中禁止删除或者明确分开编辑未来修订，**不能改变正在运行的任务和结果**。
5. 删除后原脚本的已发布版本不直接受影响，只有用户执行正式“保存/发布”才产生新脚本修订，旧历史 run 保持不变。

## 六、新增验收项（与 AC01～AC12 累加）

- **F-01**：在卡片 A 的第 1 步点一次绿色 ▶，不弹独立试跑窗口，不重复点击确认；A 自动准备并执行一次，B 不受影响，A 原视频从准备到结果不主动关闭。
- **F-02**：▶ 进度附于 A 的该步骤行；知道精确的 `run_id/device_id/step_id`，结果分别区分动作发送、断言成功、失败、未知；网络超时不再自动创建第二个 UUID。
- **F-03**：自动准备/真实执行中原视频连续可看，手动 tap/输入/解锁/群控无法从客户端或直连 API 穿透动作独占；完成清理后才能恢复手控。
- **F-04**：顶部脚本下拉第一行输入名称新建空脚本；创建后成为当前，另一台同账号手机看到同一份新脚本，旧脚本不丢。
- **F-05**：下拉中选中任意正式脚本，所有卡片步骤同步更新；旧工作草稿有未同步/冲突时不得无提示覆盖。
- **F-06**：下拉每条都能点“克隆副本”，包括当前脚本；克隆产生全新身份，编辑/删除新副本不修改原脚本、不复制秘密或旧历史；可选源版本明确。
- **F-07**：卡片步骤每行带删除，普通步可删除/撤销；删除条件块不能破坏树；步骤编号自动调整、其他 `step_id` 不变、服务器 CAS 版本与旧历史一致。
- **F-08**：草稿栏全局 ▶ 只对被勾选且授权的手机运行完整脚本，按设备并行；0 台不可执行，设备失败相互隔离，运行结果分设备/分步骤可看。
- **F-09**：保存/发布状态与服务端草稿同步状态明确区分；运行和编辑同时发生时不改变正在执行的不可变脚本快照。
- **F-10**：Inspector 使用唯一主视频与停靠属性工作台；同视频右键拾取第 1～4 步，关闭 dock 或重拾不中断观看，全屏正确。
- **F-11**：两浏览器同时操作、切 owner、断 Wi-Fi/ADB、执行器重启、双任务竞争、清理未完成、坐标参考不匹配均不能重复下发动作或泄露脚本/参数。
- **F-12**：FnOS + 两台 OEM Android + 双浏览器提供真机录屏、脱敏运行结果与脚本 revision 证据，才可宣布需求已验收。

## 七、不做什么

- 不为了“点击即执行”取消服务端账号授权、有效定位、控件唯一性、坐标尺寸或幂等安全。
- 不自动配对无线 ADB；不伪造手机预览持续播放；不在脚本执行时开放 manual 输入。
- 不默认向账号所有手机群发脚本；不克隆密码/运行参数值；不默默覆盖当前草稿。
- 不拆出第二套 WebRTC、UiAutomator2 控件树、脚本持久化或执行历史业务逻辑。
- 本需求文档只记录用户最终业务方向；**当前版本未实现上述新交互，不代表已完成测试。**
