## 1. 一句话产品目标

**原自动化中心页面不变；只在手机卡片底部，提供紧凑脚本选择/新建/克隆，以及每条步骤的操作管理。** 用户可在当前手机选择并编辑同一个脚本，单步 ▶ 和整套流程 ▶ 的目标范围明确，未来执行时都能在原手机实时画面观察效果。

## 2. 范围冻结：分两阶段交付

| 范围 | 本轮 A：红框内局部改造（优先） | 后续 B：执行体验与独占架构（保留为需求，不混做） |
|---|---|---|
| 页面区域 | 手机卡片底部“自动化草稿/脚本步骤”红框内部 | 单步/全流程执行过程、执行器与控件树面板 |
| 脚本名称 | 改为**原位、原宽度**脚本下拉 | 无 |
| 创建/选择/克隆 | **实现并接入现有脚本/草稿 API** | 无 |
| 每步删除 | **每一行都有删除按钮**，包括条件步骤 | 无 |
| 全局整套执行入口 | **只在红框内安排一个“运行全流程”入口**，使用已有运行 API；可按依赖分阶段接线 | 多设备完整运行时视频保持、并发及跨会话排他联调 |
| 单步 ▶ | **保留现有位置、图标、尺寸**，不因为脚本管理改造挪动 | 由“打开试跑弹窗”升级为当前手机一键自动准备并执行、行内反馈 |
| 视频/布局 | **完全不动**视频、顶部工具栏、手机卡片宽度及其它区域 | 原画面试跑不断流；只读观看/独占动作分离 |
| 控件拾取 | 原逻辑不动 | 唯一视频 + Inspector 停靠面板；移除第二个视频播放器 |
| 风险确认 | A 阶段不改已有试跑逻辑 | 去掉重复“定位风险确认”，保留后台硬校验 |

**验收边界：** A 阶段不得因为 B 阶段未实现而阻塞脚本管理的独立交付；B 阶段不得为了保留视频而删除权限检查或执行器操作独占锁。所有记录单独标注“代码已交付”和“真机已验证”。

## 3. 红框内最终布局（必须严格遵守）

### 3.1 收起状态

```text
┌──────────────────────── 原手机卡片（宽高保持不变） ───────────────────────┐
│  …………………………  原实时画面，不改动  …………………………………………                   │
├────────────────────────────────────────────────────────────────────────┤
│ ● 实时画面                                                    设备 IP │
│                                                                        │
│ [智能家居巡检 ▼]                            [1/100 步   ⌃]            │
│  尚未发布正式脚本 · 工作草稿已同步        [▶ 运行全流程]              │
│ ┌────────────────────────────────────────────────────────────────────┐ │
│ │ ① 点击 · 文字定位                                      ▶   ✎  🗑 │ │
│ │ ② 等待出现 · Resource ID                                ▶   ✎  🗑 │ │
│ │ ③ If/Else · 条件分支                                   ○   ✎  🗑 │ │
│ └────────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

- **名称选择器的触发框**严格放在原“自动化草稿”文字/脚本名称占用的**左侧区域**，宽度不突破截图红框中给名称预留的空间；不能扩成整张卡片宽的输入框。
- 右侧 `x/100 步` 与展开/折叠按钮**始终固定、可见、可点击**，不因长名称或浮层而被遮挡。左侧名称超长省略，悬停可看完整名字。
- **触发框与下拉浮层左侧边线一致，浮层宽度不超过左侧名称栏可用宽度**。小屏优先内部文本截断与弹层纵向滚动，而非撑大卡片或盖住步数。
- 共享脚本的**全流程 ▶ 按钮**放在红框内现有状态说明所在行的右侧，采用紧凑尺寸；不挤压名称与 `x/100` 的主行，不影响原手机视频的纵向尺寸。
- 原有步骤顺序、播放/编辑图标和提示文字尽量保持；仅补充删除入口，不重设计卡片或顶部操作按钮。

### 3.2 展开状态：直接从脚本名称处开始

```text
  [脚本名称当前位置 ▼]      [1/100 步  ⌃]  ← 右侧绝不被覆盖
  ┌────────────────────────────────┐
  │ [输入自动化名称……]     [新建]   │  ← 浮层第一行，没有重复标题
  ├────────────────────────────────┤
  │ ✓ 智能家居巡检          [克隆]  │  ← 当前选中只用列表勾选标明
  │   回家场景              [克隆]  │
  │   设备状态检查          [克隆]  │
  │   日常打卡              [克隆]  │
  └────────────────────────────────┘
```

**不可偏离的细节：**

1. 点击脚本名，弹层**从这个位置展开**，不是额外弹出宽面板或重新创建一块脚本管理区。
2. 展开后的内容**第一行立即是“名称输入框 + 新建按钮”**；**不要重复显示一行“智能家居巡检”标题/当前值**。它已在脚本列表里以 `✓` 表示当前选中。
3. 每条脚本行分为两个**互不混淆的点击区域**：点名称区域＝选中并加载；点右侧“克隆”＝打开克隆命名弹窗，不能顺便选中或执行。
4. 下拉可以内部纵向滚动、关闭时还原到原脚本名称位置；点击外部或 Esc 收起。列表为空时仍能看见第一行新建。
5. 克隆/新建弹层只影响脚本工作区，不改变其它手机画面，也不触发 ADB 动作。

## 4. 脚本生命周期的交互契约

### R01 · 新建脚本
- 在下拉**第一行**输入名称，点击“新建”或按 Enter。
- 名称 trim 后必须非空；不允许仅空白字符。重名应给出明确反馈，避免用户误以为克隆/切换了同名记录；唯一身份始终靠 `script_id/draft_id`，不是名称。
- 创建**全新空白自动化记录**：新 ID、0 步、不携带上一个脚本的步骤、执行历史或运行时参数；创建成功后自动选中，卡片步骤列表更新为“暂无步骤”。
- 在正式 Script 与服务端 Draft 之间需要明确：**用户看到“新建成功/出现在已保存脚本列表”时必须已得到服务器保存回执**；保存前显示“创建中/未同步”，失败不能伪装成功。
- 旧工作区未保存时先触发 R05 防丢失保护，不直接清空旧步骤。

### R02 · 选择已有脚本
- 下拉展示**当前账号有权限访问的已保存脚本**。显示名称、当前选中勾选；必要的修订/步数可以用较小的副标题，不能影响窄列表布局。
- 点击目标脚本名称，使用其服务端 `script_id + revision` 获取步骤、顺序、分支数据并载入**同一份共享工作区**。
- 切换完成后：下拉收起、左侧名称更新、步骤列表替换、右侧步数随新脚本变化；所有同账号手机卡片**在此网页的共享工作区中**同步显示该脚本。跨浏览器必须通过服务端记录刷新/冲突提示，不假设另一浏览器会瞬时同步。
- 重复点击已选中的脚本不创建副本、不覆盖本地未保存编辑，也不发出真实设备动作。
- 服务端加载失败保持原脚本，提示可重试，禁止出现“名称已切换、步骤还是旧脚本”的半更新状态。

### R03 · 克隆副本（必须改名确认）
- 对**任何一条已保存脚本（包括当前脚本）**，点击独立“克隆”按钮。
- 弹出小型命名框：标题“克隆脚本”，输入框默认 `原名称 - 副本`，**允许且要求用户确认新名称**；`取消`不产生写入。
- 确认后**复制被点击的原脚本的已保存步骤内容**，创建一条**全新正式自动化记录**（不是原脚本的一次修订），新 `script_id`、独立 revision；按结构引用安全重新生成步骤 ID，保持步骤次序、动作、定位方式和条件分支关系。
- 服务端创建成功后**自动选中并加载克隆记录**，名称/步数与新脚本一致；源脚本完全不变。失败保持原工作区和列表，不生成半成品副本。
- 不克隆运行历史、输入参数实际值、密码、旧请求 ID、设备锁或会话状态；坐标/selector 的设备兼容性不能因为复制而跳过预检。
- “克隆列表脚本（已保存版本）”与“把当前未发布编辑另存副本”是不同来源操作，后者如需使用须单独标为“另存当前草稿”，不能静默混用。

### R04 · 每条步骤都有删除按钮
- 卡片每条脚本明细行最右侧提供 **`▶` / `✎` / `🗑`**；包括普通点击、输入、等待、断言、截图、条件标记及其所有子步骤。条件不能单独试跑时 ▶ 可以禁用，但**删除入口始终可见**。
- 点击普通步骤的 `🗑`：在当前草稿中删除该项，剩余顺序自动重排、`x/100 步` 即时更新，**其余步骤 ID 不变**；短时间提供“撤销删除”。
- 条件分支节点的删除要先列明将受影响的范围与步数，明确确认后按已有 `removeFlowBlock` 安全删除整个结构。删除分支内最后一个步骤会导致分支无效时，也要让用户有一个可执行的“删除整个所属条件块”选项，而不是隐藏 `🗑`。
- 删除写入**当前工作草稿 CAS**，状态“保存中/已同步/冲突”如实显示；**不直接删除旧正式发布版本**，只有后续保存/发布才形成正式脚本新修订。
- 运行中不能篡改历史运行快照：删除操作要么限制在下一工作版本，要么在当前同脚本执行时禁用并给出原因。操作结果不可影响当前 `run_id` 既有步骤或历史记录。
- 删除 UI 不应引起画面滚动跳动、列表整体宽度变大；在窄卡片中保持所有操作按钮可触达。

### R05 · 切换/新建/克隆时保护已有草稿
- **禁止静默丢失**当前正在编辑的步骤、已确认录入内容、服务器已同步的草稿。
- 若当前草稿未同步、遇到保存冲突或编辑面板有未确认输入，则弹出明确选择：**保存当前并继续 / 留在当前脚本 / 明确放弃未确认修改**。可附加“另存副本”，但不能隐式替代正式克隆。
- 服务器草稿保存需要 `draft_id + revision` 的 CAS 校验；脚本发布使用正式脚本 ID/修订，不能混用。网络超时不得生成第二条重复脚本记录。
- 操作完成后更新列表选中、名称、步骤及保存状态；在手机断线或停投屏时仍可管理已保存的脚本。
- 账号切换时清空前账号不可见数据；服务端做 owner 授权，不能单靠页面筛选。

## 5. 与执行入口的关系（保留用户之前的确认，不扩大 A 阶段）

### R06 · 每行绿色 ▶：仅在本卡片对应的手机上执行一步
- 最终目标是**点击一次直接自动准备并执行当前一步**，不用再次打开独立单步试跑弹窗，也不弹普遍性的“定位风险确认”复选框；状态在此行展示：准备中→执行中→动作已发送/验证通过/失败/结果未知。
- 后台仍强制检查 owner、ADB 授权、UiAutomator2、控件唯一性、旧树、设备绑定及坐标尺寸；不兼容直接阻断，必要的参数行内输入与敏感副作用特定确认保留。
- 目标固定为**当前卡片绑定的设备**，不得误用全局勾选的其它手机；执行时冻结 `step_id`、请求 UUID 与脚本快照。未知结果不能自动再次发动作。
- **A 阶段**：仅保持按钮位置与原现有流程，不私改 Executor 控制逻辑。**B 阶段**：完成点击即执行 + 原视频可观察及行内修复，须另行按 R08 验收。

### R07 · 运行全流程：当前脚本 + 工作台已勾选的手机
- “▶ 运行全流程”是**脚本工作区的全局入口**，不要理解成“只跑本卡片”；仅发送到当前工作台明确勾选、且有授权的设备，0 台时禁用并提示。
- 按设备并行、设备内按步骤顺序，冻结脚本版本与目标列表；不同设备的准备/失败相互独立，按设备和步骤显示进度和历史。
- 复用现有 `ScriptLibrary` / `runs` API；清楚区别“草稿已同步”和“正式脚本已发布”，不允许未确认的草稿被标成正式版本。
- 布局在 A 阶段限定于红框状态行；完整一键调度和执行期间视频保持是 B 阶段联调，**不能为了提前显示按钮绕过旧排他**。
- 对曾提出的“执行器只有推荐最大配置、不写死最大限制”的要求，后续要复查前端固定 20 台限制及服务端实际容量，不能通过默默丢弃所选设备完成运行。

### R08 · 后续专项：同一个实时画面、试跑不关投屏
- **这是独立专项，非本轮红框 UI 修改。** 视频卡片及顶栏、全屏、投屏质量、控件拾取弹窗保持现状直到本专项实施。
- 最终要求：原卡片一个主 WebRTC `MediaStream`；控件树/属性作为停靠工作台，不重复第二个播放器；单步自动准备和运行期间视频保持播放，用户看得到手机真实动作。
- 需要将自研 `Journal.claim()` 的写入独占与只读视频观看解耦：viewer lease / action lease。控制权移交时冻结手控、服务端和执行器双层拦截，任务结束清理确认后才恢复手控；`cleanup_pending/outcome_unknown` 保持只读与禁止重复下发。
- `CardTrialPanel.vue` 当前准备前主动关闭本页预览，不能直接删除 close；必须同步调整 Rust `active_session/run_occupied` 和 Executor `runtime.py/journal.py` 的安全契约。
- 详细技术与专项验收采用 `require-04-single-screen-observable-trial.md`，并且**不新增第二条 WebRTC 作为替代**。

## 7. 可执行验收清单

### A 阶段：本轮红框内局部验收（必须全部满足）
- **A-01 布局**：脚本下拉的触发框与浮层均只位于原左侧名称区域；右侧 `1/100 步` 和折叠按钮在任何脚本名称长度、展开/关闭操作中始终可见；卡片、视频、工具栏尺寸未变。
- **A-02 展开**：点击“智能家居巡检”即原位展开；浮层第一行“名称输入框 + 新建”；没有重复当前名称标题行；旧脚本列表只有一条 `✓` 当前选中。
- **A-03 选中**：从脚本 A 切换脚本 B，显示 B 全部步骤、正确排序及步数；失败仍停在 A，不产生手机动作。
- **A-04 新建**：填写合法名称创建新空脚本，服务端保存成功后自动成为当前；错误、网络未知、重名不生成假成功或重复记录。
- **A-05 克隆**：点任意脚本“克隆”，先弹编辑新名称、确认后生成**新独立正式记录**并自动加载，源脚本步骤/修订/历史保持不变；取消不写入。
- **A-06 删除**：每行都含 `🗑`，包括条件节点、分支子步骤；普通步删除/撤销，条件块范围确认，非法分支删除被阻断并可选择安全处理。
- **A-07 草稿**：CAS 同步成功才标“已同步”；切换/新建/克隆期间的未保存修改、网络超时、另一浏览器旧 revision 不会被静默覆盖。
- **A-08 原貌**：原实时视频、投屏与设置按钮、卡片宽度、播放/编辑按钮、脚本步骤列表结构不发生范围外 UI 重设计。
- **A-09 全局入口**：红框状态行有明确全局 ▶ 且只针对选中设备；无法调用安全既有执行流程时不能假装“已执行”，等待 B 阶段真实接线。
- **A-10 权限**：切账号、设备离线、另一浏览器打开同一脚本时，列表按 owner 隔离、没有跨账号脚本暴露；执行和历史不会被脚本切换篡改。
