# R01 用户列表、逻辑删除与网络禁用

## 用户原始要求

新增用户管理菜单，展示所有用户，支持删除。删除时仅禁用该用户全部网络，网络节点—设备—服务资料暂不处理。

## 根据实际代码落实

- `users`的删除会级联到`devices`、`networks`和配置记录，资产引用又有限制。因此使用`users.deleted_at`逻辑删除，保留原ID及唯一用户名，不执行`DELETE FROM users`，不清空下属表。
- 菜单与接口仅现有`admins`组的有效管理员可用；普通用户不能调用列表或删除接口。沿用现有本地账号部署，external webhook不开放此功能。
- 列表包含正常和已删除用户，显示用户名/ID、角色、状态、节点数量及禁用/全部持久网络实例数量。数量不冒充在线状态，不回传密码哈希、令牌或网络密钥。
- 删除前二次确认影响。禁止删除当前账号和最后有效管理员；事务内重新验证操作者权限。删除后不能密码登录、继续使用旧Web会话或通过OIDC/自动注册复活；原OIDC映射和config-server连接协议保持。
- 一次事务标记账号已删除，将其全部持久网络实例置为禁用并失效配置revision。网络定义、成员、凭据、配置内容、注册节点、实体设备和服务均保留。
- 中央发布器遇到已删除账号停止发布并回收该账号的服务端Gateway运行实例；不能发送会删除配置记录的空Full。旧心跳/运行来源同步及在途保存不得重新启用网络。
- 对该账号在线节点执行有界停止RPC，再关闭其管理会话；不能把断开管理连接等同网络已停止。离线/超时如实提示“配置已禁用，节点运行未确认”，重复删除请求可重试停止，保留首次删除时间。
- 页面手动刷新，不增加心跳、轮询、cron或自动探测任务。已有任务仅增加账号删除状态判断。

逻辑删除、用户名占位、自删保护与运行未确认反馈是为满足“删除账号且保留资料”的实施选择，不扩为账号恢复、数据迁移或自动重新接管。
