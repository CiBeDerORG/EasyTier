# 需求范围

用户反馈日常改 BUG 后等待镜像构建过慢，并在耗时分析后授权实施。

## 目标

- 消除同一流水线中的共享前端库重复构建。
- 配置生成器底层输入未变时复用完整 WASM 产物。
- 页面修改无需重新编译没有变化的 Rust 后端。
- 冷缓存时前后端并行准备；失效、缺失或损坏的缓存回退重新编译。
- 一个镜像继续提供当前四个程序入口，现有 deploy 用法直接使用。
- 镜像与复用二进制的源码来源分别记录，不能误标版本。

## 本轮约束

- 工作分支为 feat/node-attributes-main，push 后自动构建 amd64。
- 改 BUG 模式：不运行本地测试、构建、类型检查、lint 或验证命令，不手动触发 CI。
- 保留现有 release 优化配置；本轮通过减少重复工作、分离产物和准确缓存提速。
- 不新增构建机器或额外部署容器。

## 2026-10-24 第二阶段

- 当前交付分支为 `feat/automation-center`；用户授权“你优化一下”，提交推送后沿用现有 amd64 自动构建。
- 解决三轮串行 Rust 编译：合并 Web 产物，将发布回归编译移到并行任务，测试成功仍是发布条件。
- 保留网页管理、API-only 默认行为、现有两个 Web 启动名称及 deploy 接口。
- 生产 release 优化级别维持当前策略；测试命令采用单独编译参数。
- 修正 workspace 产物不持续保存的问题，减少无关输入导致成品缓存失效，并保证变化源码不会误用旧缓存。
- 记录实际构建、测试、发布结果与耗时；没有执行的本地检查明确标记未执行，不用历史通过代替本轮结果。
