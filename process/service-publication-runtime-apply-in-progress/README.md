# 服务公开映射写入运行网络

## 本轮问题

用户反馈：保存公开服务后，在选中的公网服务器 / 运行网络编辑器中仍看不到新增端口转发。

对照基础提交 `ebb3f69e5c9ce88c8d819b1e6ce8ab9247da999d`：资产事务已经把服务映射写入 `user_running_network_configs.network_config.port_forwards`；但 REST 保存只通知心跳协调器，没有等待运行配置更新或回读确认。正常网络编辑器的“运行网络”直接调用 `RunNetworkInstance`。此前只修复候选网络筛选，未补齐本次要求的即时应用与反馈。

## 实现

- 在同一共享修改锁范围内捕获修改前目标配置；资产事务提交后将映射即时应用到准确的公网机器和网络实例。
- 复用“运行网络”的 `RunNetworkInstance` / overwrite / Web source 语义，仅替换已读取的运行配置中的端口转发，其他运行参数保持原样。配置改变时可能触发该网络实例重建，和编辑器运行操作一致；相同映射不重复重启。
- 使用网络编辑器同源的 `GetNetworkInstanceConfig` 读取运行配置，并核对实例标识、映射内容和运行状态。不是读数据库后假定成功，也不等价于公网端到端连通测试。
- 取消公开、改绑、服务删除、设备地址和绑定变更同时处理旧目标。改绑先移除旧实例映射，再处理新目标。
- 保留运行中额外的手工映射；冲突不静默替换。只移除本次前后配置差异中的服务映射。
- 新增和编辑服务响应附带 `publication_sync`，区分 applied / pending / failed。服务删除现在以 HTTP 200 JSON 返回 deleted 和 publication_sync，前端同步接收，旧客户端忽略响应体仍可删除。
- 服务面板区分资料保存与运行映射确认；取消公开或删除但未确认清理时提示公网入口可能仍可访问。
- 已经公开的服务无需删除重建；部署新版本后重新保存可重新下发并回读确认。
