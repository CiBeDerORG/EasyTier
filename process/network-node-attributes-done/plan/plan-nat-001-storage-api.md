# 属性存储与 API

[计划汇总](README.md) · [任务 NAT-001](../task/task-nat-001-storage-api.md)

## 现状与目标

main 的 `devices` 已按用户和机器登记节点；`upsert_device_heartbeat` 维护上报信息，别名独立更新。直接在此模型扩展八个属性，手填属性使用独立 UPDATE，不修改节点主键或新增另一套节点表。

## 实施内容

1. 在 main 现有迁移后新增 `m20261022_000011_node_attributes`，一次增加六个自动属性和两个手填属性。旧记录保留，状态默认 `unknown`，其余新列可空；回滚仅移除新增列。
2. 扩展实体、列表 DTO 和现有元数据导出。心跳写入列不得包含两个手填字段，手填更新不得覆盖自动 IP 快照。与 root 协调 IP 观察结构，DB 源文件仍由本任务独占。
3. 按[固定契约](../require/README.md)实现属性 PUT：会话归属、中央认证边界、字符串规范化、未知字段拒绝、原子更新和缺失节点 404。两个键都必填，空字符串清空；不存在节点不做 upsert。
4. 保留既有列表字段和别名/删除接口；外部 webhook 模式拒绝手填更新并维持该模式的列表兼容性。

## 交付与验证

交付迁移、实体、持久化、API 和相关测试源码，列出执行结果供 root 汇总。验证重点为旧库迁移、租户隔离、原子写入、清空、参数边界、心跳/IP 写入不覆盖手填字段；对应 NAA-01、NAA-02 和 NAA-04 的持久化部分。当前验证结果待记录。

本任务与前端编辑器并行，前端使用已固定契约。root 负责连接层 IP 采集；不得因实现方便从用户管理分支引入其迁移、账号 API 或测试身份结构。
