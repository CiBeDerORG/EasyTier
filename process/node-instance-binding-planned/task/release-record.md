## 两次检查脚本错误及恢复

首次部署后检查脚本请求实例目录漏传必填`role`，接口正常返回422。第二次检查已通过接口、原数据及外键，但脚本只识别`/assets/...`，未识别首页的`./assets/...`相对路径。两次都按预案停止新版并恢复成套旧程序＋一致数据库，旧服务重新登录成功；客户端未重启。

这两处错误发生在本轮部署检查脚本，未修改产品参数约束或放宽验收。修正后先在隔离新服务验证JS路径与hash，再重新备份升级；最后完整部署检查全部通过。错误与恢复证据保留在[attempt 1](artifacts/2026-10-23/deployment-attempt-1.json)、[attempt 2](artifacts/2026-10-23/deployment-attempt-2.json)。
