# 实例绑定增量工程契约 v2 草案

本契约已完成T01冻结，供本轮多个agent实现；冻结表示协议确定，不表示API已实现或验证。原[资产v1契约](../../../node-device-service-discussion/plan/contracts/v1.md)继续约束账号、名称、服务、归属、计数、删除及幂等。本文件明确覆盖新建/地址/绑定分支；第9节为精确字段、DDL和模块接口，优先于前文概念性描述。v2为内部契约版本，HTTP仍使用 `/api/v1/assets`。

## 1. 角色、身份和存储

- `device_role = gateway | ordinary` 用于新增流程；手机/NAS等仍为 `device_type_id`，不能互相替代。网关用现有groups资源，普通用devices资源。
- 实例引用为 `(owner_user_id, machine_id, instance_id)`；不得只以instance_id全局查找或绑定中央network_id。
- 本轮采用保留groups/devices分表的增量方案：网关/直属设备增加可空的 `network_instance_id`、配置记录 `id/create_time`、相关配置指纹与精简绑定快照。网关子设备增加 `address_mode`、`rule_key`、`host_offset`及所采纳规则/配置身份快照。实际列名/DDL由T01→T02交接。
- `address_mode = legacy_manual | direct_instance | gateway_rule | gateway_self`。仅升级前已有记录可为legacy_manual，新建接口不得接受该模式。
- 用标量列实现作用域查询、网关实例唯一、子设备归属与LAN唯一；JSON只存不含凭据的IP/规则快照，不把整个网络配置复制到资产表。网关保留asset_gateway_subnets作为当前已采纳真实网段的兼容投影，映射信息在绑定规则快照中表达。
- 网关新增唯一索引 `(owner_user_id,machine_id,network_instance_id)`（非空）；不增加直属实例排他索引。设备LAN仍同账号同节点唯一、空值允许；服务及自身设备已有约束保持。
- 不为原配置表增加RESTRICT/CASCADE外键；实例删除不级联资产，资产删除不写实例配置。新旧表的FK/事务一致性仍保证资产自身无孤儿数据。

## 2. 实例目录和可信快照

`list_instance_candidates(scope, role)`读取持久配置 `ListNetworkProps::All`；在线状态/运行IPv4只读补充。原旧列表依赖RPC在线、旧HTTP按登录账号取值，均不能直接当新候选API。

候选条目最小字段：`instance_id`、`display_name`、`source`、`online`（unknown允许）、`disabled`、`ipv4`、`ipv4_source`、`config_ref`（配置记录身份）、`config_fingerprint`、`rules[]`、`selectable`、`unavailable_reason`、`bound_gateway`（同权限范围的ID/名称或null）。不返回网络secret、完整配置或其他账号信息。

- 角色依据持久配置的IPv4规则。普通代理/映射混合仍属网关；解析失败或只有暂不支持的规则不得降级为空规则的直属候选。
- `ipv4_source = configured | allocated | runtime | missing`：先有效静态配置，再中央分配值，再对应实例已知运行值。配置已指定但非法时返回错误，不悄悄忽略。离线不抹除已有资产快照，无法重新确定IP时标明受限。
- 仅运行态、没有持久配置的实例不可新绑定（可展示不可选原因）；停用或离线本身不排除保存完整的配置。
- `config_ref`由持久记录的id/create_time识别世代；`config_fingerprint`只涵盖角色、相关IPv4配置/来源及规范化规则，不含密码、不因备注/无关配置改动而误报变更。动态IP作为登记采纳值单独比较，来源暂不可读不等于IP已变。
- 每个规则包含 `rule_key`、`real_cidr`、`mapped_cidr|null`、`prefix_len`；key由规范化内容稳定产生，不能用数组下标。规则重排不改变key，相同规范规则去重用于选择器，不修改源配置。

## 3. 地址输入与推导

`address_spec`为判别联合：

|mode|输入|后端生成|
|---|---|---|
|direct_instance|选定实例及其预览版本；可选手工IPv4 lan_ip|overlay=实例IPv4；LAN为纯IPv4，仍满足同节点唯一|
|gateway_rule|gateway_group_id、rule_key、整数host_offset、网关绑定版本|LAN=real网络基址+偏移；overlay=mapped基址+偏移，未映射时等于LAN|
|gateway_self|gateway_group_id、网关绑定版本；可选成对rule_key/host_offset|overlay=网关实例IPv4；LAN为空或按real规则推导，不取mapped作为自身overlay|

IPv4前缀0–32，偏移为0..2^(32-prefix)-1；/24界面可显示末段，非/24使用主机偏移及完整地址预览。两侧前缀相同，禁止溢出。/31的0/1、/32的0合法；其他前缀的网络/广播位提示用途，不自行增加旧资料中不存在的禁录规则。地址登记不证明网络可达。

后端地址模块提供纯解析/规范化/推导函数；预览与最终保存使用同一实现。客户端不能通过传入派生overlay/lan覆盖推导结果。新流程只推导IPv4，存量IPv6维持legacy处理。

新绑定模式的地址输入均只处理IPv4，不能通过复用旧canonical_ip让新直属LAN默默接受IPv6；旧legacy_manual仍保留原IPv4/IPv6校验。网关内普通设备与自身设备标识的调整如保留原编辑能力，必须通过address操作同步更新address_mode并校验每组自身唯一，不能仅切换布尔值留下不一致地址。

## 4. API与输入/输出

除context/accounts原有规则外，以下API统一使用已有query作用域 `owner_user_id + machine_id`，授权先于资源与实例查询。`{kind}`只允许gateway-groups/devices两个静态路由，不开放任意表名。

|方法与路径（前缀/api/v1/assets）|用途与输入|输出|
|---|---|---|
|GET /network-instances?role=gateway或ordinary|目录；核对既有资源时携带受授权的subject引用用于排除自身占用|候选摘要items和受限原因|
|POST /validation/instance-address|scope内subject、address_spec、config_ref/fingerprint或网关绑定版本|规范地址、来源、warnings、field_errors、preview_version|
|POST /validation/binding|subject（新增或现有网关/直属设备）、operation=attach或refresh、目标实例的config_ref/config_fingerprint；现有资源附已采纳绑定版本|旧/新快照差异、影响的子设备ID、可保存状态、错误和preview_version；首次预览不要求已有preview_version|
|POST /gateway-groups|request_id、name/remarks、binding实例选择及preview_version|网关记录+绑定状态；不接受新建手填subnets绕过|
|POST /devices|request_id、普通设备资料、固定归属、address_spec、preview_version|实体设备记录+地址/绑定来源；不新建网关行于devices|
|PUT /{kind}/{id}|一般名称/备注等资料；设备型号/类型等保持；legacy可保留原手工IP/网段编辑，新模式派生地址不得在此覆盖|更新记录；不要求配置在线，不改变归属/实例|
|PUT /{kind}/{id}/binding|request_id、operation、目标选择、preview_version；仅网关/直属设备，attach只用于旧未绑定，refresh只允许原scope同instance_id|原子保存采纳快照；同ID重建需明确确认新config_ref；直属同时保存已预览地址|
|PUT /devices/{id}/address|request_id、address_spec、preview_version；固定所属不变；旧下挂/自身设备转为继承网关也走此入口|显式修正当前地址，重新计算且检查LAN冲突；子设备不得另传独立实例绑定|
|GET现有组/设备查询及服务CRUD、DELETE|保持原路由；查询补充binding/address状态；服务归属不变|兼容原资料与原删除结果|

`preview_version`是服务端生成的绑定身份+相关配置+地址选择摘要，作为保存时的比较依据，不代表授权令牌。`request_id`要求用于新增及显式attach/refresh/address变更的超时重试。legacy_manual一般资料编辑可继续提交原地址，不能借此建立/改写新模式绑定；正式转换走上述独立接口。

新网关先调用binding预览，再用返回版本创建；新直属/下挂/自身设备先调用instance-address预览，再用返回版本创建。旧直属补绑的binding预览须包含保留/修改后的IPv4 LAN选择及overlay差异，不能自动丢弃旧IPv6地址。旧下挂/自身设备无需单独选择实例，先预览所属网关规则再调用address完成转换。

一般资料保存、绑定核对和地址修正分别提供明确操作及成功提示，不用一个保存按钮顺序调用多个独立提交后统一宣称全部成功。新建则由单次POST原子提交设备资料及其绑定/地址。

同实例核对的响应必须区分网关/设备资源；网关修改只更新自身采纳配置及网段投影，子设备IP不自动变化。字段级/结构性错误与资源错误均沿用 `{code,message,field_errors}`；预览非持久化，校验失败可返回field_errors供表单显示，提交失败必须返回HTTP错误状态。

## 5. 状态和动作

这是按需计算的资料状态，无后台状态机、轮询或写配置任务：

|状态|含义|可执行动作|
|---|---|---|
|legacy_unbound|升级前无关联资料|读/改一般资料、服务、按原条件删；显式补绑|
|current|采纳配置身份及地址依据仍适用|全部相应资料操作、新增子设备/地址预览|
|changed|角色/IP/规则与快照不同；可附rule_missing、role_mismatch原因|保留资料；同实例核对；角色不匹配时不能直接转换；子设备逐条选当前规则改地址|
|missing|持久配置已不存在|保留资料、服务和删除；引导恢复原实例或清理资产，不替换成别的实例|
|replaced|相同实例ID的持久记录世代已变|显式核对新旧差异后可采纳同ID新记录，禁止静默恢复|
|unavailable|配置解析/读取失败或IP暂不能确定|重试/手动刷新；保留原快照及非网络资料管理，禁依赖新地址的提交|

离线/停用是独立展示信息。组失效不等于设备/服务资源不存在；网络异常不能阻断元数据、服务或原有删除操作。权限撤销/节点真正不存在则清理前端失效上下文，与临时网络错误分开。

解析优先级统一为：合法升级旧记录无关联→legacy_unbound；持久来源查询失败→unavailable；查询成功但无记录→missing；记录世代不同→replaced；世代相同但必要配置无法解析或地址暂缺→unavailable；角色/相关IP/规则不符→changed；其余→current。部分绑定字段损坏不是legacy，返回unavailable并说明资料不完整。子设备先保留自身legacy模式，再判断父绑定是否可用、自己采纳的世代、规则及地址；父级不可用时显示对应状态/原因，不用子设备旧快照冒充当前有效。网关接纳新世代后，孩子仍按自己的世代产生replaced，直到逐条确认。

网关采纳新快照后：同一配置世代且未改变的规则key继续可用；规则已移除的子设备保留原地址并提示待核对；旧未绑定孩子继续legacy_unbound。若配置世代已变，即使rule_key相同，孩子仍需逐条通过address显式采纳新来源，父级确认不替代孩子确认。网关实例IP改变时，自身设备的旧overlay也须逐条核对，普通子设备则按规则是否变化判断。孩子逐条改地址，无批量覆盖。角色由普通变网关或反向变化不能通过核对偷偷搬迁，保留记录并提示按原删除条件清理后再创建。

## 6. 一致性、错误和兼容

- 写入顺序：当前授权 → 解析规范用户输入并查幂等重放 → 协调锁/事务内重读持久配置及采纳版本 → 角色/占用/引用校验 → 地址推导与既有唯一校验 → 资产与operation记录原子提交。锁顺序沿用 `lock_mutations → BEGIN IMMEDIATE`；运行RPC不得放在数据库写事务中长时间等待。
- 幂等hash基于用户提交的稳定选择、预览版本和scope，不将当次重新计算的地址混入hash。已完成同次请求在配置变化后仍可重放，资源删除返回原410语义。不同request_id的真新增遵守网关和LAN唯一。
- 复用原401/403/404、`lan_ip_in_use`、`gateway_self_in_use`、`request_payload_changed`、410等语义；新增409原因包括 `instance_already_bound`、`instance_config_changed`、`binding_role_mismatch`、`binding_rule_missing`、`instance_replaced`；422用于字段、IPv4/偏移/规则格式错误，503用于临时配置读取失败。最终码名T01统一，前端不能依赖英文message判断。
- 迁移只新增列/索引和legacy标记，保留旧ID、IPv4/IPv6、服务及已有索引；不修改config-server/OIDC/原实例配置。候选只读必要字段，不保存密钥。原普通/中央配置变更由下次按需解析发现，不侵入旧写路径。
- 暂不修改中央快捷CIDR输入以支持箭头；引导现有完整配置入口时必须基于真实可用路由/能力，没有入口的账号只说明原因，不展示死链接。

## 7. 前端组件与agent交接

- T08独占DTO与客户端，产出 `listAssetNetworkInstances`、`previewAssetAddress`、`previewAssetBinding`、`applyAssetBinding`、`updateAssetAddress`；复用原CRUD方法及useAssetMutation。同一次mutation保留request_id+payload。
- T09独占父表单和共用实例选择器/网关编辑器。实例选择器props：`scope, role, subject?, modelValue`；events：`update:modelValue, invalidated`，不自行保存资产。选择角色/归属变更只影响提交前草稿，清除依赖值并隔离旧响应。
- T10独占地址子组件与预览composable：props `scope, subject?, gateway?, addressSpec, disabled`；events `update:addressSpec, preview-change`。只预览、不改组/角色、不提交资产；/24及非/24都显示完整地址，父组件负责保存。
- T09普通保存事件 `{resource_kind:'device', record}`，网关事件 `{resource_kind:'gateway', record}`；T11依此调用设备定位展开或组目录刷新，网关新增后打开或提供明确入口定位该网关的管理结果，不让新对象只存在于后台目录。补绑/核对/地址修正事件带同类resource_kind和id；不混计数。
- T11独占页面/控制器/设备表/类型管理同名展示；保留查询按钮才生效、展开按需加载和保存后的既有定位策略。T12统一翻译、模块注册、旧节点入口和交叉接线；组件文件只在owner交接后顺序修正。
- 一般编辑最后保存覆盖；预览版本仅保护网络来源及显式修正，不扩大成所有资料的乐观锁。取消关闭放弃草稿，失败保留输入，不加新的离开确认。

## 8. 冻结与变更

T01已补齐以下DDL、DTO与helper签名并冻结，后续任务按该版执行。工程实现发现代码约束差异时由契约owner统一更新并通知依赖者；不得由多个agent各自产生同名不同义字段。状态frozen不表示已实施或运行验证。

## 9. T01精确实施协议（冻结）

### 9.1 DDL及记录字段

`asset_gateway_groups`和`asset_devices`均增加以下可空列：`network_instance_id TEXT`、`config_record_id INTEGER`、`config_create_time TEXT`、`config_fingerprint TEXT`、`binding_snapshot_json TEXT`。子设备也记录其采纳的父实例身份，表示继承来源，不成为独立绑定。

`asset_devices`另增 `address_mode TEXT NOT NULL DEFAULT 'legacy_manual' CHECK(address_mode IN ('legacy_manual','direct_instance','gateway_rule','gateway_self'))`、`rule_key TEXT NULL`、`host_offset INTEGER NULL CHECK(host_offset IS NULL OR host_offset BETWEEN 0 AND 4294967295)`。网关新增 `idx_asset_gateway_groups_instance` 唯一索引 `(owner_user_id,machine_id,network_instance_id) WHERE network_instance_id IS NOT NULL`；不增加配置表FK或直属实例唯一索引。使用新迁移000013，不重写000012。

### 9.2 JSON类型

所有nullable字段明确返回null。以下为字段全集，字符串ID为UUID；scope仍在query传递，不再重复在body设置owner。

```ts
type AssetRole = 'gateway' | 'ordinary';
type Subject = { resource_kind: 'gateway' | 'device'; id: string | null };
type ConfigRef = { id: number; create_time: string };
type ProxyRule = { rule_key: string; real_cidr: string; mapped_cidr: string | null; prefix_len: number };
type InstanceSnapshot = {
  instance_id: string; display_name: string; source: string;
  role: AssetRole | 'unknown'; config_ref: ConfigRef; config_fingerprint: string;
  ipv4: string | null; ipv4_source: 'configured' | 'allocated' | 'runtime' | 'missing';
  rules: ProxyRule[];
};
type InstanceCandidate = InstanceSnapshot & {
  online: boolean | null; disabled: boolean;
  selectable: boolean; unavailable_reason: string | null;
  bound_gateway: { id: string; name: string } | null;
};
type BindingState = 'legacy_unbound' | 'current' | 'changed' | 'missing' | 'replaced' | 'unavailable';
type BindingInfo = {
  state: BindingState; reason: string | null;
  instance_id: string | null; snapshot: InstanceSnapshot | null; current: InstanceCandidate | null;
  can_attach: boolean; can_refresh: boolean; can_edit_address: boolean;
};
type AddressSpec =
  | { mode: 'direct_instance'; instance_id: string; lan_ip: string | null }
  | { mode: 'gateway_rule'; gateway_group_id: string; rule_key: string; host_offset: number }
  | { mode: 'gateway_self'; gateway_group_id: string; rule_key: string | null; host_offset: number | null };
type AddressValues = { overlay_ip: string; lan_ip: string | null };
type BindingDiffSide = { snapshot: InstanceSnapshot | null; overlay_ip: string | null; lan_ip: string | null };
type InstancePreview = {
  can_save: boolean; preview_version: string | null;
  field_errors: Record<string,string>; warnings: AssetWarning[];
  addresses: AddressValues | null; snapshot: InstanceSnapshot | null;
  before: BindingDiffSide | null; after: BindingDiffSide | null; affected_device_ids: string[];
};
```

网关记录保留旧字段id/owner_user_id/machine_id/name/remarks/subnets/warnings/created_at/updated_at，并增加 `overlay_ip:string|null`、`binding:BindingInfo`。设备记录保留全部旧字段，增加 `address_mode`、`rule_key:string|null`、`host_offset:number|null`、`network_instance_id:string|null`、`binding:BindingInfo`、`address_spec:AddressSpec|null`；legacy_manual的address_spec=null。服务记录完全保持。

有效DHCP开启时配置中的残留virtual_ipv4不作静态来源（与Core实际应用一致），再尝试allocated/runtime；dhcp未显式指定时以dhcp_ipv4_cidr是否存在为默认。运行信息按当前owner/node范围以单次按需、限定超时的只读观测注入，不在事务内调用RPC，也不建立后台查询；缺失观测保持unknown/missing，不猜IP。

### 9.3 请求精确形状

```ts
type CandidateQuery = { role: AssetRole; subject_kind?: 'gateway'|'device'; subject_id?: string };
type BindingPreviewInput = { subject: Subject; operation: 'attach'|'refresh'; instance_id: string; lan_ip?: string|null };
type AddressPreviewInput = { subject: Subject; address_spec: AddressSpec };
type ApplyBindingInput = { request_id: string; operation: 'attach'|'refresh'; instance_id: string; preview_version: string; lan_ip?: string|null };
type ApplyAddressInput = { request_id: string; address_spec: AddressSpec; preview_version: string };
type GatewayCreateInput = { request_id: string; name: string; remarks: string|null; binding: { instance_id: string }; preview_version: string };
type DeviceCreateInput = {
  request_id: string; name: string; model: string|null; remarks: string|null; device_type_id: string|null;
  address_spec: AddressSpec; preview_version: string;
};
```

新device的gateway_group_id与is_gateway_self由address_spec计算，不接受body另传一套归属或派生IP。旧group/device新增body一律不得通过手工subnets/IP绕过实例必选。ordinary role由新device资源和mode表达，gateway通过groups创建，不额外传device_role。

网关一般PUT：`{name,remarks,subnets?}`；仅legacy网关允许subnets可选更新，新绑定网关提交subnets拒绝。设备一般PUT：`{name,model,remarks,device_type_id,overlay_ip?,lan_ip?,gateway_group_id?,is_gateway_self?}`；仅legacy_manual可更新手工IP和自身标记，gateway_group_id如提交必须仍等于原值；新模式不得提交IP覆盖或改变self。缺省可选字段保持当前值，不因省略清空；name/model/remarks/device_type_id为完整元数据字段，空值必须明确提交null。

预览不要求preview_version。POST validation/binding的新建subject为gateway/id=null，operation=attach；已有subject须在scope内，device仅允许直属设备。POST validation/instance-address的subject必须device（新建id=null）；已有子设备的mode须符合原归属及self标记。binding/地址预览返回InstancePreview，422格式字段问题转换为can_save=false+field_errors；授权/资源/暂不可读取错误保留HTTP状态。

PUT绑定和地址根据path建立subject，与先前预览算法一致。旧子设备（含self）转换使用PUT address；已有direct_instance改LAN或重新采纳当前地址使用PUT address，instance_id仍须相同。网关和直属通过PUT binding刷新配置身份；子设备不能调用PUT binding。

示例（scope始终在query）：

```json
{"subject":{"resource_kind":"gateway","id":null},"operation":"attach","instance_id":"11111111-1111-4111-8111-111111111111"}
```

```json
{"subject":{"resource_kind":"device","id":null},"address_spec":{"mode":"gateway_rule","gateway_group_id":"22222222-2222-4222-8222-222222222222","rule_key":"canonical-rule-key","host_offset":20}}
```

成功预览示意（snapshot字段须使用9.2完整结构，省略只为示例阅读）：`{can_save:true,preview_version:"sha256…",field_errors:{},warnings:[],addresses:{overlay_ip:"10.20.1.20",lan_ip:"192.168.1.20"},snapshot:<InstanceSnapshot>,before:null,after:<BindingDiffSide>,affected_device_ids:[]}`。保存通过相同输入选择与当前精简snapshot重新计算版本比对；普通资料不进入地址版本哈希。

### 9.4 Rust模块签名

以下helper为assets内部 `pub(super)`，JSON Value键必须遵守9.2。共同错误类型继续为 `common::AssetResult<T>`，不引入第二套HTTP错误。

```rust
// instances.rs
#[derive(Clone, Debug, Default)]
pub(crate) struct RuntimeObservation { pub ipv4: Option<String>, pub online: Option<bool> }
pub(crate) type RuntimeObservations = std::collections::BTreeMap<String, RuntimeObservation>;
async fn list_candidates(conn: &mut sqlx::SqliteConnection, owner: i32, node: &str,
    role: &str, exclude_group_id: Option<&str>, runtime: &RuntimeObservations) -> AssetResult<Vec<Value>>;
async fn get_candidate(conn: &mut sqlx::SqliteConnection, owner: i32, node: &str,
    instance_id: &str, exclude_group_id: Option<&str>, runtime: &RuntimeObservations) -> AssetResult<Option<Value>>;
fn snapshot(candidate: &Value) -> Value;
// address_derivation.rs
fn parse_rules(raw: &[String]) -> AssetResult<Vec<Value>>;
fn derive_address(mode: &str, instance_ipv4: &str, rules: &[Value], rule_key: Option<&str>,
    host_offset: Option<u64>, lan_ip: Option<&str>) -> AssetResult<Value>; // overlay_ip, lan_ip, warnings
// bindings.rs

```

instances返回None仅表示scope内无持久配置行；无效配置返回不可选candidate，字段齐全，role=unknown。snapshot只返回9.2精简InstanceSnapshot，剔除online/disabled/selectable/unavailable_reason/bound_gateway。bindings不写DB；child_state比较孩子采纳世代与accepted_parent/current，避免父核对掩盖孩子未确认。

AssetsStore由root增加 `runtime_observations: RuntimeObservations`（new默认空），提供 `with_runtime_observations`注入。领域层从store读取，helper不会跨事务RPC。REST缓存取值由root接线，当前作用域必须已经授权。
