# 前端流程与交互需求

本轮在现有节点详情页上接入角色、实例绑定和地址带出。用户已确认的主流程为“当前节点 → 选择网关/普通 → 选择匹配网络实例 → 填写资料并保存”。本文同时记录为完成该流程采用的工程方案；补绑、配置核对及状态处理属于工程设计，并非用户逐项回答的产品决定。接口及最终字段以[工程契约](../plan/contracts/v2.md)为准，生命周期与旧资料处理见[兼容需求](require-04-lifecycle-and-compatibility.md)。

## 新增、保存和回显闭环

|场景|填写与请求|成功后的处理|
|---|---|---|
|节点下新增网关|先选网关角色，再从当前账号/节点的候选中选普通代理或映射实例；展示实例组网IP、规则和名称/备注；同节点网关与实例一一绑定|返回网关结果，刷新目录并展示可定位的管理结果；管理窗口未打开时提供明确“查看网关”入口并定位新记录；不制造普通设备行，不增加设备数量|
|节点下新增普通直属设备|先选普通角色，归属默认直属节点；选择无子网转发规则的实例，读取地址来源，填写名称/型号/硬件类型/备注等资料|使用已有设备保存流程；清除不匹配的组/类型/关键词条件，定位并展开新设备，可继续新增服务|
|节点下新增普通设备并选择已有网关|普通角色保留所属网关选择；选组后使用网关绑定的实例及规则，不再选择另一直属实例|保存为组内设备，设备数量增加一条，按普通设备成功流程定位展开|
|从网关入口新增下挂设备|明确所属网关，继承其绑定实例，选择一条规则，填写主机部分，预览双IP后保存|刷新设备列表与相关目录；同样可展开服务|
|手动登记网关自身设备|保留已有自身设备标识，最多一条；组网IP读取所属网关实例，LAN选填；填写LAN时仅用规则及主机部分派生真实LAN，不映射网关本机组网IP|仍是一条实体设备记录，服务挂在该记录下，计数沿用原约定|

网关/普通是拓扑角色，手机、NAS、OpenWrt等仍为用户可维护的硬件类型。原有管理设备类型功能保留；删除使用中的类型仍由后端拒绝。

“管理网关组”的新增入口必须复用网关绑定编辑器。统一新增弹窗与管理弹窗不得形成两套校验或让其中一套绕过实例必选。保留现有居中弹窗及取消即放弃的操作方式，不增加强制创建服务步骤。

## 实例选择与IPv4地址预览

- 候选请求携带当前账号与节点；使用新增资产授权适配接口。旧`WebRemoteClient`的`/machines/{machine}/...`接口无目标账号参数，不能直接用它完成管理员跨账号候选查询。
- 后端提供候选可选性、不可选原因、名称/短ID、配置来源、IPv4来源及规则摘要；前端不读取或展示完整含凭据网络配置。网关候选包括不改址的普通子网代理以及改址映射；直属候选没有子网转发规则。
- 本轮工程方案以持久配置为登记依据：离线但有可用持久配置的实例仍可选择；仅运行而未保存的实例不能作为新绑定目标。没有确定IPv4时不能完成新绑定，已有资料仍能管理。离线、未保存、配置读取失败、地址未确定分别提示。
- 在提交前切角色、所属组或实例，清除依赖的规则、主机部分和预览结果；请求带上下文/序号隔离，旧响应不得覆盖新的选择。保存结果不确定时沿用既有幂等重试锁定原请求，不能一边重试一边改变绑定。
- 选规则后展示内网网段、组网侧访问网段和输入要求；普通代理两侧地址相同，映射按规则带出。`/24`可表现为填最后一段；前端不能将全部IPv4写死为`/24`，其他前缀按契约表达主机部分。
- 地址结果由后端预览返回，前端显示而不自行作最终计算。保存接口重新核对规则与配置指纹并生成地址，预览成功不等于保存必定成功；冲突、超范围、内网IP重复等按字段错误反馈。
- 直属模式的overlay为所选实例IPv4，只读显示，LAN仍可选手填纯IPv4；新绑定模式不接受IPv6，旧legacy资料继续按原IPv4/IPv6规则维护。`gateway_rule`模式使用规则与整数主机偏移；`gateway_self`模式overlay来自网关实例，LAN为空或由所选规则推导。保存模式使用`address_spec`判别联合，不让旧手填overlay绕过生成规则。
- 只在进入表单、选择变化、显式预览/刷新及操作完成后请求；查询表格仍统一点“查询”生效，不新增定时器、心跳或循环重试。

## 编辑、补绑、配置核对与删除

本轮工程方案采用`legacy_unbound/current/changed/missing/replaced/unavailable`绑定状态。列表摘要、编辑器及操作结果使用同一含义，具体状态定义与优先级见工程契约；未知配置不可显示为正常或无子网转发。

旧未绑定资料在补绑前保留原手工IP/网段编辑能力与原校验（含旧IPv6）；补绑完成后，相应字段按新模式显示实例来源或通过独立地址操作修改。不能直接删除旧输入控件，又只在后端保留维护能力。

|记录情况|页面应提供的操作|约束|
|---|---|---|
|旧资料尚未绑定（legacy_unbound）|展示“未绑定”及原双IP，普通资料、服务及删除仍可操作；提供一次性补绑入口|不按名称或相同IP自动猜实例；补绑预览并保存，取消保留旧资料|
|已有绑定正常（current）|展示实例/规则/地址来源，编辑一般资料|保持节点、组与角色固定，不开放跨实例迁移|
|同实例配置变化（changed）|展示已保存快照与当前差异，显式进入核对、预览并保存|仅同节点、同实例核对；读取列表不自动写资料或更新地址|
|实例缺失（missing）|保留历史绑定及地址，提示恢复原实例或清理资产；一般资料、服务和删除保持可用|不自动绑定同名新实例、不把错误清空成未绑定，也不提供跨实例修复绕过|
|同ID实例记录被重建（replaced）|展示旧/新记录身份差异，用户显式预览确认后可采纳同ID新记录|仍限原节点/实例ID；不得静默恢复或切换角色|
|配置暂时不可读取（unavailable）|保留已有结果，明确暂不可核对，提供手动重试|不把失败当空配置；不因暂时失败删除资料或禁掉服务资料管理|
|网关核对更新了绑定快照|刷新网关摘要；下挂设备原地址保留，受影响设备显示待核对|不批量覆盖孩子地址；规则消失逐条修正；实例同ID重建的新世代仍要求每个孩子显式采纳新来源，即使rule_key未变|

旧网关首次补绑保留既有孩子的legacy资料；旧下挂和自身设备先预览所属网关规则，再调用`PUT /devices/{id}/address`完成来源登记，不发独立binding请求或另选实例。既有IPv6资料继续可读和一般资料编辑，本轮新增IPv4推导不抹掉其地址。

网关与直属设备的首次补绑、同实例核对按“只读binding预览 → 明确binding提交”执行；旧下挂/自身设备及后续地址核对按“instance-address预览 → address提交”执行，每次apply携带request_id并复用幂等机制。首次预览从候选config_ref/config_fingerprint或网关绑定版本获得来源，不能反过来要求用户先提供尚未生成的preview_version；不能把预览当作已更新资料。

同一配置世代且规则未变化时，普通孩子可继续使用原规则；同ID实例重建导致世代变化时，即使规则内容相同，父网关确认也不替代孩子逐条确认。网关实例IP发生变化时，自身设备的旧overlay须单独预览核对；普通孩子是否需改地址依规则变化判定。普通/自身标识的调整如保留原编辑能力，须走address操作同步模式与地址并检查自身唯一，不只更新布尔值。

元数据保存、绑定apply与地址修正使用独立操作和成功提示，避免同一按钮串接多个写接口后把部分成功当作整体成功。地址修正调用`PUT /devices/{id}/address`，一般资料保存不改已派生IP；绑定/地址apply成功后按资源类型刷新结果。网关未完成首次补绑或需要核对且当前规则不可用时，先处理网关绑定再新增依赖该规则的孩子，已有孩子的一般资料和服务继续可用。

设备删除仍二次确认并删除提交时全部服务；有设备的网关禁止删除；有下属资料的节点禁止删除。删除资产不触发网络实例删除、停机或转发配置变更，删除网关后刷新候选释放占用。实例绑定失效不应阻止清理资产。

## 页面恢复与既有复审闭环

- 账号/节点切换时关闭相关弹窗、清理候选和预览、隔离旧响应；管理员目标账号始终可见。节点不存在或权限撤销已确认时重新加载允许的上下文并清除失效选择、旧行和操作入口；临时网络失败保留可辨识的旧快照。
- 同名网关、硬件类型及实例在列表、下拉选项和已选值中提供短ID/网段等辅助信息，不能只靠名称绑定。对应原复审R02。
- 常用编辑、删除、新增服务操作在桌面与窄屏可到达，表格仅局部横向滚动。对应R01；本轮不重做整套视觉风格。
- 返回网络节点列表恢复初始位置，作用于真实滚动容器；节点属性字符长度与后端统一按Unicode码点，不扩大为全站路由或表单改造。对应R04/R05；R03由上述失效恢复覆盖。
- 原节点卡片、实例数量、设置入口、设备计数口径、筛选“查询”按钮、多设备同时展开服务、HTTP/HTTPS链接和内置图标保持原有规则。

## 验收交接

验收应覆盖两个网关新增入口、普通直属与组内设备、自身设备、普通代理/映射、多规则及非`/24`、离线持久配置、未保存实例、旧资料补绑、配置变化/缺失、保存冲突、错误重试、权限上下文、列表定位与服务CRUD。具体拆分见T08–T12，集中执行由T13在用户授权后承担。本轮仅编写需求和任务，未执行测试、构建或CI。
