# 服务基本信息继承设备组网 IP 与内网 IP

## 需求与代码基线

用户需要新增服务时直接看到所属设备的组网 IP、内网 IP，设备地址变化后服务随之更新；服务基本信息只能查看这两个字段，不能单独修改。基线为 `CiBeDerORG/EasyTier` 的 `feat/node-attributes-main@c9ff7bbc04ae05cfce029629e7e30990d95dedfc`。

已有事实：服务通过 `asset_services.device_id` 固定关联设备；`db/assets/services.rs` 的新增、编辑和列表共用 `common.rs::service_json`。`AssetServiceDialog.vue` 接收 `device: AssetDevice`；设备保存和地址核对后，`useNodeAssetsPage.ts::afterDeviceSaved` 重新读取设备列表并更新该对象。服务写入通过 `validation.rs::service_payload` 白名单校验，不接受地址字段。

## 实现约定

1. 新增、编辑服务在名称下方展示两列只读字段“组网 IP”“内网 IP”，窄屏沿用现有单列布局；未填写内网 IP 显示“未设置”。字段可以选中复制，不能编辑。
2. 弹窗以所属设备为唯一地址来源；打开新增/编辑时通过既有设备详情接口按需读取最新双 IP，避免另一页面修改后仍展示旧设备缓存。本页设备对象更新时同步采用新值，隔离更早请求；关闭、切换作用域和卸载后忽略迟到结果。地址不加入服务可编辑草稿或写入请求，更新地址时保留未提交服务资料；读取失败明确反馈并支持重试。
3. 服务创建、编辑、列表响应增加 `overlay_ip: string`、`lan_ip: string | null`，从同账号、同节点、同设备关联取得当前已保存的地址。已有服务无需重建或回填。
4. 创建请求的幂等重试继续返回原创建结果，只将派生地址补充为当前设备地址；原有资源删除、归属、权限、端口占用及重试语义保持。
5. 不增加服务地址数据库副本、迁移、轮询或自动探测。实例配置变化仍走设备既有核对/保存流程；服务跟随设备已保存的地址，而不是擅自替设备接受新的实例配置。

## 分工和交付

- 后端：`db/assets/services.rs`、`common.rs`，负责同 scope 地址读取、统一响应和幂等回放。
- 前端与集成：`AssetServiceDialog.vue`、`types/node-assets.ts`、中英文 YAML；主线程统一维护文档、审阅和提交。
- 与原契约的关系：[v2 契约](../plan/contracts/v2.md)补充服务响应字段；服务写入和数据结构保持原有约定。
- 当前调试模式，运行验证未授权；本轮只实施和人工审阅，实际记录见[逐轮记录](../task/test-report.md)。

## 待验收场景

1. 为已有设备新增服务时，双 IP 与设备一致；鼠标、键盘不能修改，允许选中复制；内网 IP 缺失时显示“未设置”。
2. 保存后重新编辑服务，双 IP 保持一致；旧服务同样显示，不要求重建服务。
3. 保存设备地址或完成地址核对后，服务重新读取/弹窗收到设备更新即显示新值；服务名称、端口等草稿不被地址变化清空。
   另一页面修改设备 IP 后，即使当前设备列表仍缓存旧数据，重新打开新增/编辑服务也应取得新值；读取失败不得静默伪装为已同步。
4. 重试原创建请求，服务 ID 保持不变，双 IP 为设备当前已保存地址；旧版本生成的幂等记录同样补齐地址。
5. 服务写入请求携带 `overlay_ip` 或 `lan_ip` 仍被白名单拒绝；跨账号/节点访问和已删除设备继续按原规则拒绝。

以上场景均为待验证项，不代表本轮已执行。
