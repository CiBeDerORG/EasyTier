# 后端：实例绑定、IPv4地址与保存闭环

本文件承接[范围与改动矩阵](require-01-scope-and-change-matrix.md)。用户已确认资产关系、先选网关/普通再选实例、普通子网代理与映射均属网关、网关与实例一一绑定及IPv4优先。下文的存储方式、配置来源优先级、状态和错误处理为本轮工程方案，未逐条冒充用户答复；由[T01](../task/task-01-contract-and-baseline.md)统一冻结[接口契约](../plan/contracts/v2.md)后实施。

## 现有代码与变化

下列路径以仓库根目录为基准。

|代码入口|当前行为|本轮增量|
|---|---|---|
|`easytier-web/src/db/entity/asset_gateway_groups.rs`、`asset_devices.rs`|网关组与设备分表，均无网络实例引用|保留分表及旧ID，增加绑定和地址来源资料|
|`easytier-web/src/db/assets/groups.rs` 的 `create_group/update_group`|手填并替换网关组网段|新网关必须绑定实例，规则从该实例读取；旧资料保留|
|`easytier-web/src/db/assets/devices.rs` 的 `create_device/update_device`|手填组网IP和可选LAN IP，所属网关不可变|直属绑定实例；网关子设备选规则和主机部分，服务器生成地址|
|`easytier-web/src/db/assets/validation.rs`|严格字段白名单，校验手工IP/CIDR|扩展明确的绑定/推导输入，保留旧资料编辑路径，不接受前端伪造生成结果|
|`easytier-web/src/db/assets/common.rs` 的 `group_json/device_json`|返回手工地址、组、类型和网段提醒|一致返回绑定来源、登记快照、当前状态及可执行操作|
|`easytier-web/src/restful/assets/mod.rs`|账号/节点作用域、管理员权限、写锁和JSON错误已存在|在相同授权范围接入候选、预览、绑定确认及新版保存|

原实例读接口不能直接替代新候选接口：`easytier-core/src/management/full/remote_client.rs` 的 `handle_list_network_instance_ids` 先要求RPC在线；`handle_get_network_config_with_source` 优先运行配置再回退数据库。`easytier-web/src/restful/network.rs` 的原读取还使用当前登录账号。本轮应在资产作用域内读取持久配置，并明确来源，不能让管理员跨账号或离线操作绕回旧页面限制。

## 身份与持久数据

1. 网络实例绑定按 `owner_user_id + machine_id + instance_id` 定位。中央编译器 `central_network/compiler.rs` 使用中央网络ID作为各节点实例ID，因此不得建立跨节点的全局instance_id唯一约束；普通实例也不必有中央networks记录。
2. 保留 `asset_gateway_groups`、`asset_devices`、`asset_services` 及服务外键关系。网关仍承接组的管理职责，服务仍挂在实体设备；本轮不为统一名称重建全部实体。
3. 绑定持久资料至少表达：所属资源/节点范围、实例ID、选中持久配置行的ID与create_time、相关配置指纹、精简实例IPv4及来源、规范化IPv4规则快照。行身份用于识别相同实例ID被删除后重建，指纹用于识别同一行的相关配置变化。
4. 子设备记录所选规则稳定key、主机offset、派生的组网侧访问IP及LAN IP，并保留与网关的固定关系。规则key基于规范化规则内容，不能使用可随列表重排改变的数组下标。
5. 本轮采用现有组/设备表内联绑定身份标量字段、精简JSON快照，子设备内联模式、规则key与host offset；不再同时增加另一套多态绑定表。保留asset_gateway_subnets作为已采纳real网段的去重兼容投影，完整映射在快照中表达。实际DDL由T01冻结后由T02唯一落地。字段允许为空以保留旧资料，但新建路径必须按角色验证完整绑定。
6. 网关在同节点范围与实例一一绑定，数据库提供唯一约束；直属暂不增加实例排他唯一约束，这是本轮兼容性工程默认，不表示用户已要求多设备复用。
7. 快照和接口只保存/返回本功能必需的身份、IP与规则信息，不复制完整NetworkConfig；网络密钥、私钥和凭据不得进入资产快照、候选响应或错误详情。

现有同节点LAN非空唯一、每网关至多一条自身设备、同设备协议/端口唯一、设备删除级联服务的约束继续有效。网关组和实例不额外计入设备数量，设备数量仍按asset_devices记录统计。

## 实例候选与IP来源

- 从当前owner/node的 `user_running_network_configs` 读取，使用 `ListNetworkProps::All`，包含disabled配置。离线或实例停用不单独导致不可选择；运行态独有、没有持久配置行的实例不作为可绑定候选，界面解释需要先有可登记的持久配置。
- 读取节点和实例时复用资产权限：普通账号管理自己，管理员指定目标owner；external webhook模式保持不可用。先鉴权，后读取，不通过完整旧配置HTTP接口拼装跨账号结果。
- 相关IPv4来源顺序为：静态实例配置 → 可对应中央成员的allocated_ipv4 → 按需取得的已知运行IPv4辅助。来源、值与必要的观测信息分别返回；不能从机器来源公网IP、节点名称或旧手工IP猜测。
- 确定不了所需IPv4时禁止新绑定并提供原因，已有资料继续可管理。运行值仅为辅助观测，不因其变化在GET中重写资料；确认提交时重读并检验相应输入。
- 列出当前账号、当前节点全部已保存实例，按实例IPv4子网规则判定对所选角色是否可用：有普通代理或映射为网关，无子网转发为直属。role不再过滤列表；角色不匹配项返回selectable=false及原因。仅有IPv6规则、解析异常、配置不可读不能当作无规则；无效项保留展示并禁止选择，保留原配置。预览和保存仍重新执行原角色、IPv4与占用校验。
- 候选返回最少包括：实例身份与名称、配置来源、角色、IP及其来源、规则摘要、当前绑定占用信息和可选/不可选原因。配置行ID/create_time可封装为契约中的身份令牌，不要求界面显示数据库字段。

## IPv4规则与地址推导

`easytier-core/src/config/api_input.rs` 支持 `real_cidr` 与 `real_cidr->mapped_cidr`；`config/toml.rs` 要求映射两侧前缀相同；`gateway/proxy/cidr_table.rs` 保留主机位。新纯函数模块遵循这些语义，不修改底层网络逻辑。

|选择规则和主机offset|服务器生成LAN IP|服务器生成组网侧访问IP|
|---|---|---|
|`192.168.1.0/24`，20|`192.168.1.20`|`192.168.1.20`|
|`192.168.1.0/24->10.20.1.0/24`，20|`192.168.1.20`|`10.20.1.20`|
|`192.168.0.0/23->10.20.0.0/23`，276|`192.168.1.20`|`10.20.1.20`|

主机offset是相对于网段起点的整数，范围为0至该网段地址数减1；支持非/24、/31的0和1及/32的0，不能截取最后一个字节拼接。对前缀不大于30的网络/广播offset给warning但允许登记，沿用现有IP登记不证明可达的边界。界面可以把/24表现为“最后一位”，服务器输入与算法保持完整主机位含义。

地址预览只读，返回规则、规范地址、字段错误和已有唯一性冲突；保存仍重新解析/计算，并在事务中检验LAN唯一等约束。前端传入的最终地址不能替代服务器生成。直接绑定的设备和网关自身实例地址须与子设备访问地址分别表达，不宣称派生地址已经创建虚拟网卡或真实网络可达。

网关自身设备继续可选且每网关最多一条，其组网IP来源于网关实例；LAN选填，填写时选择本组规则和host offset，仅生成real LAN，不能用映射后的子设备访问地址替换网关本机overlay。普通子设备使用选中规则和host offset同时生成两侧地址，两类模式由v2分别表达。

## 保存、幂等与竞争处理

1. HTTP入口鉴权并确认owner/node上下文；写操作沿用 `CentralNetworkService::lock_mutations()`，存储事务沿用BEGIN IMMEDIATE。
2. 新建及显式attach/refresh/address变更请求先规范化用户请求及作用域，使用request_id语义；哈希基于用户请求与其preview_version，不包含读取时会变化的运行信息或自动重新生成的快照。
3. 同一合法请求先检查幂等重放，再重新验证实例和占用；否则首次保存已占用的实例会阻止自己的重试。已删除结果保持410，已用request_id改内容保持409；权限每次仍先检查。运行RPC不能放在数据库写事务中长时间等待，持久配置身份和版本须在最终保存时再查。
4. 新提交重读持久配置身份、相关指纹、角色和IP来源；与预览/选择不一致时返回可恢复的冲突并要求刷新确认，不静默换实例或改地址。
5. 网关绑定唯一、LAN唯一及自身设备唯一由数据库约束兜底；事务保存资产、绑定/规则快照及幂等结果，不留下半条绑定。
6. 现有普通资料最后一次保存生效的约定保留；相关网络配置指纹检查只保护绑定/地址确认，不擅自改成所有字段的乐观锁。新网关使用binding预览后单次POST创建，其他新设备使用instance-address预览后单次POST创建；已有资料的普通编辑、绑定核对、地址修正分为独立操作及结果，不能用连续多次提交伪装成一次原子保存。

此锁只能协调经过本Web服务的写操作，不代表远端运行配置不会变化。运行变化按按需状态和显式确认处理，不添加轮询或后台同步。

## 查询、旧资料与生命周期

绑定状态按需解析：`legacy_unbound`（未绑定）、`current`、`changed`、`missing`、`replaced`、`unavailable`，地址模式为 `legacy_manual/direct_instance/gateway_rule/gateway_self`；状态与模式分别表达。具体reason与动作矩阵见[生命周期需求](require-04-lifecycle-and-compatibility.md)及v2。GET不更新快照或地址。

- 同实例ID、相同作用域可执行“核对实例配置”：预览差异 → 用户确认 → 重读保存快照。同ID新配置行可在明确提示后接纳；不允许借此跨实例、改角色或搬动归属。
- 网关快照更新不自动重算孩子地址；同配置世代下未变化的规则key继续有效，原规则不存在或变化时逐条核对。若配置世代改变，即使rule_key相同，孩子仍须逐条通过address操作采纳新来源，父级确认不替代子级确认。网关实例IPv4变化时，自身设备overlay也标待核对。
- 旧网关首次补绑不自动重算旧孩子；旧直属设备通过binding明确确认原/新地址。旧网关子设备（含自身设备）通过instance-address预览后PUT address转换，沿用父网关实例，不走独立实例binding。未确认的旧资料继续保留legacy，不按名称、IP或型号猜测关系，旧IPv6地址不得静默丢弃。
- 原实例删改不被新资产引用拦截、不触发级联资产删除，原网络写路径继续保持；缺失绑定依然能编辑元数据、管理服务和按既有规则删除。
- 资产删除只删除绑定资料，不停实例、不删真实转发规则；节点/网关非空禁删、设备删除其服务继续按原约定。
