# 统一网关设备与普通设备（已撤回）

## 当前决定：恢复网关组设计

2026-10-23，用户确认“之前的网关组设计是正确的”，要求还原。本需求及以下界面、查询、计数和术语变更全部撤回；实现恢复到取消网关组前的版本。当前继续使用“网关组”筛选、“管理网关组”入口和原设备列表，不使用统一设备查询及计数规则。没有数据库迁移或记录删除。

本文保留为历史记录，不得再按下列内容继续实施。当前状态见上级 README 与 task/test-report.md 的最新还原轮次。

## 历史决定（已撤回）

当时要求节点详情截图中原“网关组”筛选改成“是否为网关设备”的单选项，去除“管理网关组”。产品只展示网关设备和普通设备，不再以“网关组”作为另一类用户概念。

这一历史决定曾替代网关独立目录、创建后打开网关管理、网关不计入设备数量的界面规则；现已撤回，恢复原规则。

## 界面与操作

1. 筛选使用“全部／是／否”三个互斥选项，默认全部，与设备类型和关键词一起点击“查询”生效。
2. 网关设备和普通设备显示在同一设备列表，提供角色标签。节点设备总数及列表总数包含网关记录；已有本机设备仍按设备记录计数，不做物理去重。
3. 移除独立网关管理入口。新增设备时也使用“是否为网关设备”的“是／否”单选，默认否。
4. 网关行直接提供编辑、删除、补绑及同实例核对；创建成功后刷新、定位该设备。存在下挂设备时继续禁止删除网关。
5. 普通设备的所属字段统一叫“所属网关设备”，保留直属节点选项。硬件类型（OpenWrt、NAS、手机等）仍独立于角色；网关没有硬件分类字段，筛选具体硬件类型时仅匹配已有该字段的普通设备。
6. 原普通设备服务入口继续保留，服务仍按设备 ID 管理。网关本机服务继续通过已有可选本机设备记录登记，不在本轮迁移服务。

## 数据与接口兼容

既有网关、普通设备及服务数据不迁移、不重建。内部表名、ID、外键和原 CRUD 接口保留，仅统一展示和查询。

`GET /assets/devices` 增加可选 `role=all|gateway|ordinary`。显式指定角色时返回统一分页记录，每条增加 `resource_kind=gateway|device`，保留各自字段。后端先按账号、节点、角色、硬件类型及关键词过滤，再统一排序、定位和分页。未传 role 时保留旧普通设备响应，旧调用方不误收网关记录。

网关关键词匹配名称和已登记组网 IP；普通设备继续匹配名称、型号、组网 IP 和内网 IP。绑定状态、权限隔离、旧资料补绑、地址派生和服务关系沿用原有规则。
