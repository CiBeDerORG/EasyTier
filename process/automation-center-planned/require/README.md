# 产品需求

## 目标与入口

侧栏新增「自动化中心」，与「服务导航」「服务管理」「应用与服务」并列，沿用已有页面标题、卡片、弹窗、暗色模式、移动端抽屉和语言切换。面向用户自己管理并已授权接入的设备。

完整产品分为四个区域：

| 区域 | 用户操作 | 结果与失败呈现 |
| --- | --- | --- |
| 设备画面 | 选择接入主机，点击发现手机；筛选分组，选择设备，点击打开画面 | 显示设备名称、画面时间、分辨率和授权状态；尚未查询、离线与连接失败分开呈现 |
| 单机控制 | 放大一台设备，点击/滑动/输入文字/返回/Home | 明确当前控制目标；旋转后同步坐标；断连时停用控制并保留原因 |
| 批量操作 | 锁定目标列表，执行一次动作或一个脚本 | 每台设备单独记录成功、失败、取消、结果待核实；由用户选择重试对象 |
| 脚本库 | 录制当前控制动作，编辑步骤、参数和适用设备，保存版本，点击运行 | 预检后展示目标与版本；执行期间可停止，结果可手动查询 |
| 接入主机 | 管理与验证承载手机连接的主机 | 复用部署 Agent 管理入口；区分主机绑定、组件安装、手机授权和实际控制能力 |

当前页面仅呈现准备入口和功能规划。没有模拟在线设备、虚构数量或可以点击但无法执行的手机控制按钮。

## 交互规则

1. 所有设备发现、打开画面、开始任务、重试和结果查询由用户点击触发；不注册定时任务、后台扫描、轮询或自动重连。
2. 打开画面后以连续媒体流显示，不用定时截图接口刷新。关闭会话或离开页面时显式关闭媒体/控制连接。网络异常导致关闭请求送不到时，不能承诺立即清理远端资源，需提供手动清理入口。
3. 「打开全部」只针对当前选中设备，并展示数量、画质档位和资源预算；超过预算时让用户减少数量或降低档位。首次请求不默认打开全部已登记设备。
4. 画面墙默认低分辨率，无音频；单机放大才请求较高画质。首期不默认保存截图、视频或剪贴板。
5. 批量动作发出前固定设备集合；新增设备不会被自动加入正在运行的任务。只能有一个写入控制者，手动操作与脚本不能同时抢占同一台手机。
6. 任务取消表示停止后续步骤，已经完成的手机动作不能撤销。断连后的未知结果不自动重新执行。
7. 首期录制的是控制事件序列，不保证能识别页面语义。不同机型、语言、分辨率和应用版本需做兼容性预检。

## 待确认的技术边界

- 手机平台：Android 优先；iPhone 需要另行配置 macOS/Xcode/WDA 链路，不能承诺与 Android 同等能力。
- 首期数量：先以 2 台验证，再以 10–20 台为试点目标；实际规模根据设备和链路压测确定。
- 接入方式：USB 最先实现；Android 无线调试需用户配对。跨地域通过 EasyTier 到达接入主机，不直接公开 ADB 端口。
- 「全部无定时器」：本方案按无业务定时器设计。系统 TCP、EasyTier 网络协议和手机编解码内部机制并非完全无时间行为；若用户连这些也禁止，无法保证跨网络实时控制。脚本等待、操作超时和 WebRTC 保活需要单独确认，当前不能默认为允许。

## 验收目标（尚未执行）

- 静置新页面 60 秒，无新增设备请求、管理轮询和自动重连；切换离开后不遗留管理任务。
- 每次发现只调用一次主机组件；部分手机未授权时不覆盖其他成功结果。
- 2 台不同分辨率/方向 Android 手机可同时查看，操作只到达选中目标；旋转过程中不产生错位点击。
- 10–20 台试点测量首帧时间、端到端延迟、丢帧、CPU/内存/带宽；局域网目标首帧 P95 ≤ 3 秒、单机交互延迟 P95 ≤ 300ms，仅为压测目标。
- 中途拔线、断网、关闭页面、主机重启不会重复执行动作，未知结果明确保留，可人工恢复。
- 未授权用户不能枚举设备、获取画面、发送控制或读取其他用户的执行记录。
