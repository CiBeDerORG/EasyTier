## 2. 身份、权限和持久化边界

### 发起者与目标

- 发起者由 `gateway_device_id` 定位；服务端校验 owner、node、`is_gateway_self=true`、所属组以及 OpenWrt 类型语义。
- 请求不得自行指定另一个目标组。owner_user_id 沿用本人/管理员代管权限；网关组从发起者记录派生。
- 普通发现可更新/覆盖的对象仅为当前组的非网关自身子设备，不能覆盖发起者及其凭据。
- 当前组 IPv4 唯一；跨组 IPv4 可重复。无组的既有直连资产保留其既有节点范围约束，不能被本次迁移静默放宽或误归组。
- IPv6 是附加观察信息；多 IPv4、IPv6-only 等超出首版匹配范围的记录明确待处理/跳过，不随机选择地址。
- UI 名称不是系统类型标识。T02 为 OpenWrt/手机和 ADB 服务提供稳定语义；已重命名或有歧义的历史类型必须显式识别，不能把任意相似名字当作已确认类型。

### 拟新增持久化能力（T01 冻结字段，T02 实施结构）

| 能力 | 最低字段/约束 |
| --- | --- |
| 网关发现配置 | gateway_device_id、owner/node/group 归属、endpoint_url、受保护的授权密码材料、配置版本、最近接入结果；返回只含 has_secret |
| 设备发现资料 | 可空 MAC、发现名称/hostname、人工显示名维护标记、IPv6、network/iface/sources、observation、last_seen/last_observed_at、来源与最近接受快照 |
| 同步预览/操作 | operation_id、request_id、来源快照、有效期、网关配置/绑定版本、逐行状态、所选 action/target/keep_service_ids、阶段错误 |
| 结构化 ADB 服务 | service_type=adb、唯一所属手机、唯一 TCP 端口、连接模式/来源信息、endpoint_revision；端口必须来自真实现有服务或本次成功发现 |
| 服务端点事件 | event_id、owner/device/service、旧/新 target_fingerprint、endpoint_revision、原因、阶段状态；提交后可恢复处理和幂等重试 |

- SQLite 原始内联唯一约束的调整须采用可验证的迁移，保留外键、索引、触发器、服务与公开关系。禁止只改查询而留下旧数据库约束。
- T02 结构迁移拟文件：`m20261024_000019_openwrt_discovery.rs`；T15 行为迁移拟文件：`m20261024_000020_adb_service_events.rs`。实施前 T01 核对最新 migrator 序号并登记；序号变动统一更新本契约。
- 密码不回传、不放 URL/日志；读取空密码不等于清除。凭据保护与密钥生命周期由 T01/T03 在已有配置能力上落地，并记录真实部署前提；不得虚构已存在加密设施。
- 2026-10-24 用户追加明确支持 HTTP：端点接受显式 HTTP/HTTPS `/ubus`，按保存的协议和端口连接。HTTP 不使用 CA；HTTPS 按现有接口约定验证证书。失败展示对应协议的错误；不携带密码静默遍历地址、跟随重定向或自动更换协议。

## 3. 拟新增 HTTP 接口

统一前缀：`/api/v1/assets/discovery/gateways/{gateway_device_id}`。所有请求使用 `owner_user_id` 查询参数，服务端再次核对归属。下列为拟新增接口，不是现有能力。

| 方法与相对路径 | 最低输入 | 输出 / 效果 |
| --- | --- | --- |
| GET /access | owner | endpoint_url、has_secret、config_revision、最近结果；无密码 |
| PUT /access | endpoint_url、secret_action=preserve/replace/clear、replace时secret、expected_revision | 保存后的脱敏配置；清除凭据不删除已有资产 |
| POST /access/check | request_id | 登录/能力检查结果；不触发普通或 ADB 扫描 |
| POST /devices/scan | request_id | operation_id、preview_id、preview_revision、扫描来源状态、逐行候选 |
| POST /devices/apply | request_id、preview_id/revision、rows | 逐行新增/更新/覆盖/跳过结果及关联阶段状态 |
| POST /adb/scan | request_id | operation_id、逐 IP 结果；必要时包含需处理的普通设备预览 |
| GET /operations/{operation_id} | owner | 读取已记录的阶段状态，不触发新扫描或重放已完成动作 |
| POST /operations/{operation_id}/resolve | request_id、expected_operation_revision、choices[{row_id,selected_endpoint_id}] | 处理该操作保存快照中的ADB端点歧义，只采用被选的一条，不重新扫描 |
| POST /operations/{operation_id}/retry | request_id、expected_operation_revision、stage=publication/connection/cleanup、event_id | 重试指定失败阶段；复核当前端点版本，不扫描、不重放成功阶段或旧脚本 |

凭据字段校验、公共前端 DTO/ApiClient 和错误码表由 T01 单处定义，T19 注册；各实现任务只扩展自己负责的模块。

### 普通设备预览行

最低信息：`row_id`、来源 IPv4/MAC/hostname/IPv6/observation、现有候选、差异、可选操作、目标绑定、警告/不可执行原因。

提交行：`row_id`、`action:create|update|replace|skip`、`target_device_id?`、`keep_service_ids[]`、预览认可版本。服务端从已保存快照取发现值，不能信任客户端替换 owner/group/IP 或服务归属。

- IP 一致不证明永久设备身份。MAC/名称差异用于确认；空值表示未知，不表示改成空。
- 未命中 IP 可手选同组旧设备；不能手选其他组或网关自身。
- create 遇同组 IP 占用拒绝；一个批次多行争用同 IP 也必须发现，不能按数组先后覆盖。
- replace 的 keep_service_ids 必须属于被替换设备；界面提交时再次复核，不依赖旧弹窗里的服务数量。
- 预览过期、网关绑定/凭据/设备/服务变化须返回明确冲突并要求更新预览；不能提交旧决定到已变化对象。
- request_id 重放返回原结果，不重复扫描、重建设备、公开规则或重连事件。只重试失败阶段，不重放已完成副作用。
- ADB补采产生的普通预览保存 originating_operation_id；原操作保留ADB快照、pending_ips、补采已使用标记及快照到期时间。devices/apply提交后T07仅返回逐行应用结果，T19交给T10继续原操作，不重新adb/scan或第二次补采；用户选择skip同样可结束相应待处理项。
- resolve只接受原快照的端点标识，不能让客户端临时提交任意新端口。原ADB快照过期或无法确认本次有效性时，结束为需要重新发现；用户显式新建扫描操作才能取得新快照。
- retry调用T11的公开应用或T17的清理/连接能力；由T19统一注册并鉴权。扫描本身失败需要用户显式再次scan，不暗中扩大重试为重新发现。

## 4. 普通设备应用与覆盖

T07 保留原 ID 更新发现资料和派生地址；非返回字段保留，人工名与来源名独立。T08 覆盖必须：

1. 在短事务内重新校验归属、IP、绑定、预览版本与服务勾选。
2. 创建替代设备；迁移勾选服务并保留服务 ID 与公开关系所有权，更新 device_id 和目标地址；未勾选服务走既有公开清理语义。
3. 删除旧资产记录，保留历史快照及旧目标清理记录；不把旧任务自动改到新设备。
4. 写入旧目标失效/新端点事件，提交后交 T17 清理与重连；外部 RPC 不放数据库事务中。
5. 失败不留下“旧设备删了，新设备/服务未建好”的半成品；外部映射应用可独立重试，不能撤销已保存的新地址而伪装成功。

T15 必须先修正地址变更/资产删除/ADB 变化相关整批取消触发器，故 T07 硬依赖 T15，T08 经 T07 继承。不能以“最终会联调”为由先交付会误取消整批的可执行更新路径。

## 5. LuCI 发现与 ADB 归一化

- 按 API 执行 session.login，再调用 easy-discovery.devices.scan 或 easy-discovery.adb.scan；scan 已返回结果，不为取得同批结果重复 list。
- 同时检查 HTTP、JSON-RPC、ubus result 和业务 status。error 即使带旧数组也不是本次成功；partial/truncated 必须保留提示。
- ADB类型/端口写入及端点事件只允许本次可确认有效的观测。error、busy、has_snapshot=false及失败来源携带的缓存端点仅展示状态，禁止改设备类型、覆盖端口、修改公开映射或触发重连；partial仅处理可明确归于本次成功来源的有效端点。普通发现允许选择历史记录导入的规则不因此改变。
- 普通发现可含租约与 24 小时历史记录；同步不据缺失删除资产，也不把 cached 当在线。
- ADB 来源仅 _adb-tls-connect._tcp；不把配对端口当连接端口，不把发现成功当作已授权。
- 同一次 ADB 操作，针对未匹配 IP **最多补一次普通发现**。只处理这些缺失 IP 需要的普通记录，不自动导入整份补采列表中的无关设备。
- 补采无歧义且能生成地址时复用 T07；需选择的身份冲突交预览流程；仍无普通设备则跳过并计数，不凭 ADB IP 虚构设备/MAC。
- 人工选择后的续接由T10唯一负责，沿用原ADB操作快照及“已补采”状态；T07/T19只传结果，不各自实现另一套续接或扫描。
- IPv4 在当前组匹配成功后设为手机，新增或更新唯一 ADB 服务。无变化不触发重连；端口改变后只写一份服务端口真值。
- 上游同一 IP 多个连接端口属于冲突结果，只允许最终选择一个；不得创建多条 ADB 或任取首项。非 ADB 服务端口占用也明确返回冲突，不删除其他服务。
- scan busy、失败、空结果及未返回某手机都不清空其既有服务。

## 6. 公开映射与自动化数据源

T11 保留公网服务器、网络、绑定 IP/端口，只更新目标 IP/端口及运行配置；保留服务迁移需同步公开记录的 device_id。服务移除则移除相应公开关系。结果区分 saved、apply_pending、applied、failed/unknown，失败提供针对原事件的重试。

T13/T14：
- 主机源为当前有效“手机 + 唯一 ADB 服务”；没有服务不显示可连接主机。
- 不从 automation_connections 的旧端口/默认5555回退，不利用旧端口补建服务。
- 历史服务缺少结构化类型或出现多个候选时提供明确修正状态，不按任意名称/排序悄悄决定端口。
- 仍复用现有 owner、实例绑定状态、实际 overlay IPv4 及路由歧义检查；跨网关组 LAN 地址可重复不表示执行器能区分相同实际组网地址。
- target 至少关联 device_id、adb_service_id、endpoint_revision、overlay_ip、port、connection_mode 和绑定版本；fingerprint 覆盖真实目标，不受显示名称变更干扰。
- 手工改服务端口和发现同步更新端口，进入同一事件链路。
- T10拥有现有db/assets/services.rs的类型、唯一性及手工端口事件适配；T14拥有现有AssetServiceDialog.vue的ADB类型/模式编辑和历史服务确认入口。公共validation、DTO、ApiClient和路由只由T19接线，避免历史未标注服务永远无法进入新数据源。

## 7. 单设备退出与重连事件

内部事件最少：event_id、operation_id、owner_user_id、device_id、adb_service_id、endpoint_revision、old_target、new_target、reason、阶段结果。名称字段是拟新增公共契约，T01 冻结后各模块不得各造一份。

### T15 / T16 按设备退出

- 退出目标是 run_id + device_id，而不是整批 run。终止该设备后续步骤，保留最后步骤实际结果/未知状态；其他设备继续。
- 服务端授权与执行器拒收屏障必须一致，旧 fingerprint 的迟到命令不能在新目标上执行。
- 清理完成是独立事实；收到取消请求不等于已经退出。旧历史不转移、不续跑、不重放。
- 拟新增内部动作 `POST /internal/v1/runs/{run_id}/devices/{device_id}/withdraw`，复用现有内部认证，携带 event_id、expected_executor_id 和 old_target_fingerprint；返回明确退出/清理状态。T16 实现业务，T19 统一注册 app.py/validation.py 与客户端。
- 用户原有“取消整批”仍可用；本需求的设备失效不得调用它。

### T17 / T18 重连

1. 服务和事件提交后立即推进旧目标失效及该设备退出当前脚本。
2. 有界清理旧 ADB、媒体、控制资源；清理未确认显示等待，不把新旧会话并存当完成。
3. 对最新已确认 endpoint_revision 执行新 ADB 连接；快速多次变更串行合并到最新目标，过时结果不能覆盖新状态。
4. 之前有投屏且页面仍在观看时创建新会话恢复原位置；之前没投屏只连接 ADB。用户已关闭/离开页面，不自动重新打开画面。
5. 首次 ADB 服务创建也尝试连接；未配对/未授权保留服务并显示待授权；失败有界结束并可重试，不无限连接循环。
6. 不续跑退出的旧脚本、不补发旧触控；重新连上后可参与新的任务。
7. 公开应用与连接各自反馈；映射失败不能伪装全部成功，也不能让无关手机退出。

拟新增重连协调路径：`easytier-web/src/discovery/reconnect.rs`、`src/db/discovery/reconnect_store.rs`、`src/restful/discovery/reconnect.rs`。现有执行器 runtime/worker/journal/adb 的写入只归 T16；T17 调用接口，不抢写执行器。

## 9. 本轮冻结补充

- 类型语义采用 `asset_device_types.semantic_kind = openwrt|phone|other|null`，旧类型保留 null，由用户显式确认；不按名称猜测。服务采用 `service_type=generic|adb`、`connection_mode=tcp|wireless`、单调递增 `endpoint_revision`。
- 发现预览有效期为 10 分钟，按请求时刻校验，无定时清扫。逐行版本覆盖设备、服务、公开记录及网关绑定/配置；操作请求 ID 与完整载荷绑定。
- 接入设置增加 `ca_pem` 公开证书信任材料，按显式配置校验 HTTPS。HTTP 保存时将 `ca_pem` 清空；HTTPS 的空白 CA 等同于留空，使用默认证书库。授权密码使用既有 `<数据库>.deploy-agent.key` 加密设施与独立上下文，数据库及该密钥一并备份；已有发现密文但丢失密钥时拒绝重新生成。
- 端点变更由数据库触发器记录持久事件并撤销旧目标；提交后只推进本次事件。重试只处理显式指定的未完成阶段；无后台扫描、轮询或无限重连。
- 当前开发和模拟验证已获授权；T21 真实设备验收另行安排，不影响前序实现与模拟联调。

## 本轮协议补充（2026-10-24）

- `GET .../operations` 只读最近 100 次操作；查看历史不触发 RPC。
- `POST /api/v1/automation/devices/{device}/endpoint-events/{event}/retry` 按 `request_id`、`stage` 显式重试最新端点事件。
- 执行器会话创建及关闭增加 `expected_executor_id`；响应返回 `executor_id`，不匹配或历史会话缺少身份则保持 `cleanup_pending`。
- 每次准备/建会话前保存完整目标及执行器身份；多个指纹独立记录与清理，迟到请求不能覆盖唯一“最后目标”。
- 覆盖后的新设备事件含 `predecessor_device_id`；其前驱清理未确认时禁止连接。
- 补发现结果为空或失败、显式跳过的 IP，本次 ADB 结果标为 `skipped`；部分确认只继续已处理 IP，其他可处理行保持 `pending_device`。
- 公网重试计划持久化原配置、选中的运行实例及当前期望配置校验值；重试不重新生成扫描或创建服务。
