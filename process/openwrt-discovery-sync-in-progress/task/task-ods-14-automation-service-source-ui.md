# ODS-T14 自动化主机列表与服务端口入口

## 目标、输入与输出

落实[ODS-R06](../require/require-ods-06-automation-service-source.md)及[PLAN-ODS-08](../plan/plan-ods-08-automation-source.md)。输入是 T01 的服务来源响应、异常语义和路由契约；输出是主机列表、连接入口及现存服务的结构化确认/编辑能力。可先按契约并行实施，T10 服务 CRUD 与 T13 目标解析只阻塞真实联调。

## 独占拟改范围与依据

- `easytier-web/frontend/src/components/AutomationCenter.vue`：`loadDevices`、设备过滤/选择及连接弹窗上下文。基线当前渲染接口返回的全部资产。
- `easytier-web/frontend/src/components/automation/ConnectionDialog.vue`：当前 `form.adb_port`、`perform` 和端口输入；改用服务目标及服务编辑入口。
- `easytier-web/frontend/src/components/node-assets/AssetServiceDialog.vue`：独占结构化 ADB 类型、连接模式编辑及从自动化入口定位现存服务的交互；基线表单只有通用协议/端口，没有结构化 ADB 类型。

不写 T18 的 `PhoneCard.vue`、`usePhoneSession.ts` 或 T10 的 `services.rs`。公共类型、API 客户端、校验及路由接线统一交 T01/T19；提交所需文案和调用签名，不自行增设第二套客户端。

## 实施步骤

1. 列表展示手机及唯一 ADB 服务的名称、目标端口和实际可用状态；不从旧连接配置补行，不给缺失/冲突数据分配默认端口，保留现有账号权限和筛选上下文。
2. 连接弹窗只读展示权威端口，编辑入口定位所属设备的 ADB 服务。移除重复端口保存；配对端口和临时配对码仍属于单次授权输入，不写作连接服务端口。
3. 在服务表单增加结构化 ADB 类型及连接模式；历史缺类型的现存服务保留原记录，提供用户明确确认/编辑入口，通过 T10 的服务 CRUD 保存和校验唯一性。不根据旧连接端口补造服务，不按名称/排序任取候选；手工端口变更进入同一服务事件链路。
4. 消费 T13 的不可用原因，区分资料缺失、绑定失效、服务冲突及待授权；服务存在不能显示为已连接。刷新后剔除不再存在的选择，不把迟到结果带入新账号。
5. 向 T18 提供当前服务目标版本、页面上下文和刷新结果；恢复画面由 T18 处理，列表刷新不能隐式开启投屏或重跑脚本。

## 完成条件与交接

实现 ODS-R06-A01、A02、A03、A05 的页面行为；用户能确认历史现存服务的 ADB 类型、编辑连接模式及唯一端口，多候选得到明确冲突，确认前不进入可执行主机。端口只有服务这一真值，禁止旧配置补建。交付 T19 的共享调用/文案清单及 T18 的目标上下文；与 T10/T13 联调后才能记录接口可用。

## 后续验证

检查历史无类型服务确认前后、手工类型/模式/端口编辑、唯一性冲突、旧配置不同端口、跨账号切换及配对输入分离；验证手工端口变更与发现同步走同一事件。后续获授权时验证实际接口；契约样例不充当后端通过证据。本轮未执行测试、构建或 CI。

主机列表显示服务目标及资料问题，连接弹窗改为只读服务端口。 统一证据见[验证记录](test-report.md)，使用/升级见[交付说明](delivery-record.md)。
