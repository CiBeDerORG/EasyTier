## 页面使用流程

2026-10-24 补充：用户明确要求直接 HTTP。新版本同时接受 HTTP/HTTPS 地址，下面的接入步骤取代早期仅 HTTPS 的限制；历史测试与发布记录仅代表其对应版本。

1. 在“节点详情”的设备类型中明确选择 OpenWrt 语义。发起设备必须是已绑定网关组的“网关自身”。
2. 打开该设备的“OpenWrt 发现接入设置”，配置路由器的 HTTP 或 HTTPS `/ubus` 地址及 easyadb 授权密码。直接 HTTP 示例为 `http://10.10.10.3:80/ubus`，端口以路由器实际监听为准；HTTP 隐藏证书栏并在保存时清空旧 CA。HTTPS 才需要根据实际证书配置 CA PEM；授权密钥填在“替换密码 → 新密码”，不能填入证书栏。密码不做 trim；“保留”不回显已有密码；“清除”删除保存的秘密。点击连接检查只检查认证/能力。
3. 点击“立即同步”生成普通发现预览，检查 IP、MAC、名称、缓存标记和地址规则，逐行选择新建/更新/覆盖/跳过。覆盖时勾选需要保留的服务，确认后才提交资产。
4. 点击“ADB 发现”。有效 IPv4 连接端点匹配本组设备；缺失时整批只补一次普通发现，无匹配则跳过，多端口要求选择保存快照中的端点。失败或 busy 的旧数组不更新服务。
5. 手机形成唯一 ADB 服务后，自动化中心直接读取该服务。未配对的手机仍需在手机端开启无线调试并由用户提供当次配对码；发现不绕过 Android 授权。点击准备脚本控制后才部署对应控件辅助组件。
6. 端口变化先撤销本机旧动作、清理旧资源，再尝试新连接。公开映射保存、运行态应用、清理和连接分别展示；画面仅在原观看意图仍有效时重建，旧脚本不会续跑。

若 HTTP 接口返回重定向，页面会报告 `discovery_redirect`。需使用能直接处理 `/ubus` 的端点，或检查 OpenWrt 的 HTTP→HTTPS 跳转配置；程序不会自行跟随跳转、改端口或更换协议。

## 行为与实机边界

页面空闲无扫描/维护轮询；操作历史只读，SSE 无保活和自动重订阅。断线后由用户点击刷新。有限 RPC 超时、实际运行步骤的超时以及已有活动媒体的授权租期仍用于中断操作和释放资源，不承担设备发现或服务心跳。

尚需 T21 验证 OpenWrt 真实 ACL/证书、fnOS/NAS 到手机的映射 IPv4、Android 配对和端口变化、scrcpy 首帧与 ICE/TURN、uiautomator2 控件兼容、公开实例真实应用/读回，以及两台手机实机并发退出隔离。模拟媒体层没有验证真实视频。

回退采用[备份恢复方案](rollback-record.md)，不要在新数据库上直接换回旧版程序。
