# 回退记录与执行步骤

本轮没有部署实机，所以没有执行生产回退。以下步骤用于后续验收时准备；对应版本、备份位置及摘要必须在实际操作时填写。

迁移 19 将同节点 LAN IPv4 唯一约束改为组内唯一。升级后不同组可能已合法使用同一 IP，自动降级会造成数据丢失，因此 `down` 明确拒绝；不能通过删除迁移记录或直接运行旧二进制绕过。

1. 停止新任务和新会话，记录仍待确认的执行器资源。关闭本轮会话、取消任务，确认受管进程退出；不以更换执行器数据卷冒充清理。
2. 停止后端和执行器写入，备份当前升级后的完整数据库、密钥、执行器 journal、artifacts 和 ADB 身份卷，保留本轮结果用于核对。
3. 成套恢复升级前的数据库一致备份、对应 `.deploy-agent.key`、运行配置、旧执行器状态及旧版本前后端/执行器。不得混用新 journal 与旧协议宣称任务可续跑。
4. 核对账号、节点、分组、资产、服务、公开关系及历史执行记录。若本轮曾实际应用公网映射，单纯恢复数据库不会立刻撤销远端运行配置；应在原节点/实例中人工核对并恢复旧映射，保留其他手工规则。
5. 仅用户明确点击后再连接测试手机，检查旧会话未复活、旧动作未重发。完成回退验收后再开放普通操作。

升级后新产生的资产或执行结果不能自动合并回旧数据库；保留升级后备份供人工比对。数据卷丢失、执行器身份变化、无法确认旧进程退出时，继续保留“待清理”，不得标记已释放。
